# TemperQ 发布复盘与上线缺项

日期：2026-10-23。交付范围为本地候选版、源码与部署准备；按用户要求，本轮不部署、不推送、不向 PyPI 发布。

## 本轮最小交付

用户主流程统一为 **训练 → 评价 → 纸面交易 → 模拟持仓**。训练设置保持现状，已训练模型和训练完成页进入模型详情，选择独立基准、创建新版本完整重训或可恢复删除。旧模型、实验和已绑定账户保留。

基准结果区分“可进入纸面验证”和“证据不足”；前者只表示历史信号达到研究门槛，不是实盘准入。独立评价完成后可用虚拟现金建立前向账户。证据不足仍可明确确认仅作观察；合成模型不能启用真实前向账户。首版真实每日策略仅支持冻结的 5 日开盘到开盘任务。

纸面账户显示净值、费用、持仓、成交、受阻和漏记记录；本地自动检查为每日 17:30 后一次，需工作台运行。已有 API 任务先更新再核验；普通 CSV 账户需要用户持续更新对应数据。失败后可手动重试，重复执行由账本去重。服务器常驻仍待目标机器验收。

模拟持仓从纸面账户进入，使用冻结模型、当前绑定行情及用户真实现金/CSV，只保存建议，不改纸面账本或连接券商。全市场首次载入可能需要数分钟，页面显示计算中。

## 发布检查中修复的问题

- 对外品牌、包名和命令统一为 TemperQ / `temperq`。保留内部 `qwb` 模块和旧命令兼容，不迁移旧账本、研究数据或主目录。
- 每日脚本改为读取账户绑定的数据源，避免默认指向开发者旧研究目录。
- 数据追加拒绝改写或删除已有历史交易日历，未来日历可更新。
- 数据库备份使用独立文件名与只读 SQLite URI，同一时刻多次备份不覆盖。
- 远程模型 README 采用限量流式读取；远程接口超时返回明确失败，不写入未完成分享。
- 新 `TEMPERQ_*` 环境变量优先，后端兼容旧 `QWB_*`；生产部署保持开发登录关闭，新增安全响应头与 CI 容器冒烟流程。
- 网页自动创建的个人评价协议留在本地并由 Git 忽略，避免将本机数据路径随候选包发布。
- 数据要求前置到上传与选择页面；新 CSV 保存覆盖初检，已知股票太少、没有共同截面或检验区间过短时先提示补数据。格式可导入、研究数据充足和统计上通过三者分开。

数据提示增量验收：导入、训练 UI、数据预检与四阶段入口 34 项通过；数据组合、账户、实验与导出回归另有 63 项通过。1440/390/360 宽、浅色/深色的 6 张页面截图及数据/持有期动态切换检查通过。未修改冻结模型、交易协议或账户执行实现。

## 验证记录

- 全量回归执行 630 项：629 项通过；1 项运行期间因源码变更触发实现哈希保护，停止修改后单独重跑通过。未把这次执行写成一次性全绿。
- 最终定向回归 127 项通过，覆盖四阶段流程、保留旧模型、父版本记录、删除恢复、评价先行、冻结模型推理、建议不改账、自动任务日内去重、暂停与失败可见，以及分享、数据、后台任务和发布导出；成本库另有 7 项通过。
- 网站生产构建通过；本地 UI 不依赖 Node、字体 CDN 或 GPU。
- 本地用户包在独立目录、独立 CPU 虚拟环境中执行 Windows 安装器通过：安装 TemperQ 与成本库、导入自检和合成训练报告成功。此检查仍在开发机，不替代另一台电脑或非开发者试用。
- wheel 已核对 `temperq` 命令、四阶段模块、随包字体、图标和许可证。源码与本地包均带 SHA-256 文件清单，私人行情、token、权重、账户和生成协议不分发。
- 浏览器 1440/390/360 宽、浅色/深色共 72 张整页截图通过，含官网 3D 非空像素、运动、历史曲线、字体与导出检查。
- 真实 40 股模型经网页完成独立基准，结论为证据不足，仅作工程验证。前向观察与历史演示分开；不据此声称策略盈利。
- 全市场账户真实持仓建议及 CSV 导出通过网页检查，使用账户冻结模型与独立日更源；输出仅是参考价模拟，没有新增成交或前向记录。

本机缺少 Docker，目标 Linux 容器、DNS、HTTPS、OAuth 回调与生产常驻未验证。新容器 CI 需推送后运行，不能把本地 Python 测试替代它。

## 你还需要准备的清单

| 缺项 | 完成标准 |
| --- | --- |
| GitHub 仓库 | 确定仓库地址和可见性，推送源码后检查 Windows/Linux、前端和容器 CI |
| 服务器与登录方式 | Linux 服务器、SSH 用户与密钥路径；安装 Docker 和 Compose，确认磁盘与内存 |
| 域名与网络 | DNS 指向服务器，80/443 可用；已有代理时按部署说明调整 |
| HF OAuth | 客户端 ID/secret、正式域名回调；填写服务器私有 `deploy/.env` |
| 会话与持久化 | 独立随机会话密钥、数据卷；完成一次备份恢复和容器重启验收 |
| 常驻纸面任务 | 配置每日先更新后记账，使用授权数据；确认时区、告警及断机后的漏记显示 |
| 外部用户验收 | 至少两位非开发者从安装、免费数据获取到四阶段流程独立操作，记录卡点 |
| 日历证据 | 连续两周真实每日运行；不得用补记或历史回放代替等待时间 |

## 明确保留的边界

账本仅扣佣金和印花税，尚未含 STRUCT 价差与冲击；不支持公司行动、北交所和特殊订单。默认模型仍需有效性和容量验证，不承诺追平或超过成熟平台收益。B2 保持实验冻结，当前不扩展算法。新部署的 `temperq` 卷不会自动迁移旧项目数据库，须先备份再显式恢复。
