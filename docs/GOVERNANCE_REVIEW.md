# 治理工作台

2026-10-26。实现状态：账户快照诊断、整数股数规划、方案比较、确认存档和导出；历史调仓节奏优化尚未接入此入口。

## 从自己的预测与账户开始

启动后首页为 `/review`。选择“新建治理诊断”，填写信号版本和可用时点，导入三张表：

| 表 | 列 | 含义 |
| --- | --- | --- |
| 预测信息 | `code,value` | 类型选目标权重、分数或排名；目标权重用小数，分数越大越优，排名越小越优 |
| 当前持仓 | `code,quantity,sellable_quantity` | 实际股数及本次计划可卖数量；空仓可留空 |
| 参考价格 | `code,price,status` | 未复权人民币价格，覆盖预测股票和所有已有持仓；`status` 可省略，默认为成交条件待复核 |

每张表可以粘贴或上传 UTF-8 CSV，不能同时输入两份。页面可下载空模板，也可载入明确标识的合成示例。当前支持沪深主板、创业板、科创板，最多 100 只预测与持仓股票，单文件 1MB。北交所尚未支持。

时间必须带时区，例如 `2026-10-26T15:30:00+08:00`。信号可用时点不能晚于账户与参考价格的时点。拟执行日需晚于参考日期，周末会拒绝；节假日与交易日历须核对。它是用户声明的拟执行日，当前不会查询在线行情或交易所日历。

价格状态：`conditional`（成交条件待复核）、`normal`（参考时点正常）、`buy_blocked`、`sell_blocked`、`suspended`。正常状态也不保证未来成交。已知禁买禁卖和停牌进入约束，锁仓股数不得出售。

当前入口只处理已核清的快照：现金已扣除冻结资金，挂单及公司行动已处理。未核清时先完成账户对账，不将冻结资金当可用现金。不会直接执行用户上传的策略代码。

## 如何比较方案

硬规则包括持仓只数、单票上限、最低现金、可卖股数、交易状态、买卖数量规则以及本次买卖合计金额 / 参考权益的上限。这里的换手预算不是市场个股换手率，也不是买卖金额除二的单边口径。

预测为目标权重时保留原目标，不默默将超限目标改写成已经合规；规划在硬约束内尽量接近它。预测为分数或排名时按明确方向选前 N 名，等权并受仓位上限和现金底线限制，不把分数当作预期收益。

候选包括：

1. 保持现有持仓：显式基线，有现存超限时照实显示。
2. 优先贴近原目标：整数数量与费用约束下，最小化相对扣费后目标的股票及现金金额绝对偏差，费用作极小次级惩罚。该金额目标不等同于严格最小化显示的权重比值。
3. 允许偏离内减少费用：在前一方案的权重偏离加用户容忍范围内，最小化预计费用，微小惩罚用于减少无意义换手。

“目标偏离”为股票与现金权重相对原目标的绝对差之和。例如，1% 权重从股票移至现金，合计偏离约 2 个百分点。默认额外容忍为 2 个百分点，是可修改的工程设置，未经历史收益验证。

用户选择优先贴近目标或在容忍范围内省费用。合理情况下会推荐保持持仓，避免为形成建议而增加交易；净收益没有被估计或假定提高。费用、目标偏离、换手、现金分别显示。

规划使用 SciPy/HiGHS。佣金按比例与最低佣金取大值，另加冻结日期规则下的卖出印花税和用户输入滑点。费用由既有 `Fees` 逐项独立复算，整数股数及数量规则复用冻结协议。不会复制另一套成交账本，不需要 PyTorch、外部模型调用或商用求解器。当前治理诊断尚未接入 STRUCT，不能把原纸面账户的 STRUCT 默认口径套在这张计划上。

求解限时后，只有独立规则检查通过的候选可以展示为可行方案，不称为全局最优。无可行候选时，列出保留仓位、预算下界等已知冲突和待处理动作；不自动修改硬约束。

## 确认与留档

结果首先显示推荐调整和改善/代价，再显示逐项诊断、候选对照和目标股数。点击“确认并保存方案”只增加一条计划确认记录，不创建订单、纸面账户或自动任务。

每次诊断存为独立记录；修改输入后另建诊断，不覆盖旧输入。确认后可以下载参考价格计划 CSV；完整输入与诊断证据可单独导出。它们可能包含个人持仓，仅保存在本地，分享前自行检查。

三层对象分开：输入与诊断、用户确认的计划、原有策略及运行账户。前两层存于 `runs/governance_reviews`，不会修改原策略版本、账本或自动任务。

## 当前边界

2026-10-27增量：有受阻时增加“只做朝向原目标的调整”对照，不把受阻权重配置给其他股票；原贴近目标方案仍受原股票池及全部硬约束限制。各方案列出数量限制造成的股票偏离下界、必须保留敞口与朝原目标完成额。下界按各方案费用后权益计算，不是收益损失或全部因果归因；其余股票与现金偏离不保证均可消除。详见[研究落地增量](research/TEMPERQ_EXTERNAL_AUDIT_20261027/11_研究落地增量_订单计费与受阻目标.md)。

当前快照可以产出仓位可行方案、费用与目标偏离权衡、锁仓和交易受阻诊断。缺少历史不会阻断这些计算。

信号年龄、调仓节奏、分批速度的历史优劣、实际订单与策略意图的长期偏离，需要历史信号、行情和交易记录，尚未接入此页。已有历史研究与纸面功能继续通过“我的策略”访问。普通公司行动的持续账本处理仍须按既有发布要求验收。

参考计划不包含未来价格、真实滑点、盘口容量、公司行动投影或成交概率。拟执行时应按新价格、可卖数量和交易状态重新诊断；它不是历史回测成绩或未来收益承诺。

## 开发接口

- `POST /api/governance-reviews`：请求头 `x-temperq-token` 为本机进程令牌，请求体为 `ReviewInput` JSON；沿用 localhost Host 校验，最多 1MB。
- `GET /review/{id}/evidence.json`：输入、结果、摘要和创建记录。
- `POST /review/{id}/select`：带表单令牌、候选编号与结果摘要，显式保存方案。
- `GET /review/{id}/plans/{selection_id}.csv`：下载已确认计划。

内核 `governance_review.py` 不依赖 UI 或存储；`review_store.py` 处理追加记录与摘要核对；`governance_review_ui.py` 负责网页、CSV 与 API。账户实际执行与未来的历史复验继续接既有账本，不复用参考计划作为真实成交。
