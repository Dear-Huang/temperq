# 模型组装与持续优化 SPEC（草案）

版本：0.2，2026-10-24。状态：**深化草案，供评审和分阶段实施；尚未冻结，规范不代表已实现**。本版收敛首版决策，补齐比较、诊断、算力和前向账户契约。页面骨架沿用 [策略流程 SPEC](STRATEGY_FLOW_SPEC.md)，参数分层沿用 [简单模式 SPEC](SIMPLE_MODE_SPEC.md)，研究路线沿用 [端到端实施记录](../E2E_IMPLEMENTATION.md)。不改变现有模型、交易协议或账本。

## 1. 产品目标与最小闭环

用户带着自己的数据或交易想法来，平台帮助他把想法变成可运行版本，看到改动带来的变化，再决定保留、修改、观察或暂停。训练与治理仍是主线，评价提供反馈。

首版必须解决两个流失时刻：整理数据后才发现不能用；训练结束只得到“证据不足”，没有可执行的下一步。成功不以训练次数、停留时长或挑出正收益曲线衡量。

> 用户可以先用默认配置训练，也可以加入自己的数据。每次改动都有可追溯的比较；结果不好时有依据、有出路，结果不明确时可以保存观察，不必反复调参。

首个纵向交付：**导入一组自己的数据 → 确认可用时点与覆盖 → 与基础训练配对比较 → 看结果和下一步 → 保留或移除该组数据 → 进入账户规则**。不以完整因子商城、全量消融或影子账户系统作为此闭环的前置条件。

## 2. 对象与用户用语

“底座、货架、购物车”可用于内部讨论；正式界面使用数据、特征、训练配置、版本等名称，不引入另一套需要学习的隐喻。冠军/挑战者仅作工程术语，界面称“正在运行 / 候选版本”，不暗示收益排名。

| 对象 | 内容与边界 |
| --- | --- |
| 任务 | 市场、决策/执行时点、标签及期限、股票池规则；改变后建立新的比较系列 |
| 数据快照 | 基础行情、历史成员/状态、可选来源、可用时点及内容身份；文件路径不是内容身份 |
| 训练配置（配方） | 任务、数据引用、输入组件、处理方法、引擎、参数和种子；有不可变版本和哈希 |
| 训练尝试 | 一次运行及父版本、改动、资源预算、状态、日志、产物身份；失败和取消也可追溯 |
| 比较系列 | 任务、评估样本、时间切分、统计协议和参考模型版本固定的一组开发比较 |
| 参考模型 | 该系列绑定的基础量价 + LightGBM，回答“比默认做法改变了什么” |
| 上一版 | 用户选定的父版本，回答“这次修改改变了什么”；与参考模型可为同一个产物 |
| 运行版本 / 候选版本 | 冻结的模型、处理链、规则、账户初值与执行版本；不只是一个模型权重文件 |

训练配置、比较系列、运行账户分别保存身份。数据追加或实现变化不能让旧报告引用新产物而不改变身份。

## 3. 首版体验：少选择，有抓手

### 3.1 入口与布局

阶段 ① 提供“使用现有模型 / 训练新模型 / 导入外部预测”；训练内复用同一个编辑器，不另建购物流程。可从基础训练开始，也可从“加入我的数据”或已有版本进入，自动填入对应设置。

默认首屏只有：行情数据、模型名称、训练配置摘要，以及“开始训练”一个主操作。特征与引擎提供可折叠的修改区；已有自己的数据时显示已加入的来源和检查状态。默认值来自注册表，不复制一套新默认。

专业用户展开后可选择输入组件、引擎、参数，查看/导出实际配置；不强迫新手先选择“简单 / 专业”模式。B1 上架后不要求选择人工特征，不能把因子研究作为所有人的入场步骤。

解释集中在右上角帮助与详情区，按当前阶段定位。按钮附近仅保留必要标签、单位、当前状态和真实错误；不为每个按钮加说明，不增加首次教学弹窗。颜色、折叠和显示模式不影响计算。

### 3.2 训练前检查

| 时机 | 立即反馈 | 处理 |
| --- | --- | --- |
| 选择/导入数据 | 字段映射、单位、代码匹配、覆盖范围、重复与缺失 | 硬错误先修复；保留已映射内容，返回时不重填 |
| 加入自己的数据 | 可用日规则、来源声明、匹配率、缺失率、预计损失样本 | 用户确认后保存来源版本；不因匹配失败悄悄忽略该来源 |
| 开始训练前 | 有效样本、任务兼容性、输入差异、计划运行的对照和资源预算 | 硬阻塞不启动；局限以紧凑状态列出，不重复确认 |
| 后台运行 | 准备/参考/候选/比较进度、耗时、取消与失败原因 | 可以离开页面，重启后区分可恢复与必须重跑 |

时间估计来自本机同类任务记录，显示范围和依据；冷启动显示“暂无估计”，不承诺几秒或几分钟。大数据可选轻量预览，必须标明样本范围，不能把预览当正式比较或经济结论。

### 3.3 结果首屏

默认展示：当前版本及本次改动、一句具体发现、与参考/上一版的紧凑比较、一个建议动作。信号结果展示排序差及区间、样本覆盖；完成规则检验后才展示相应净值与费用，不把 IC 换算成收益。

~~~text
我的模型 v2                         本次加入：自有资金流
与上一版的排序差 +0.003，当前区间跨零，尚不能确认改善

当前版本 / 基础参考 / 上一版       [查看比较详情]
样本、覆盖、耗时                  开发比较 · 已比较 4 个配置

[配置账户规则]  [修改这一版]       更多：保存 / 暂停研究
~~~

数值仅为页面示例，真实界面从产物读取。可运行且无严重退化时，默认主操作为“配置账户规则”；硬阻塞时为“修复数据”；有明确负向比较时为“查看改动对比”。不能把“暂不确定”做成不允许继续的门禁，也不能把比较完成显示为未来收益通过。

完整统计、各年结果、成本假设、输入来源与版本树放进详情。没有单项对照就显示“未分析”，不能用特征重要性猜出单项增量。

## 4. 可选输入与引擎

### 4.1 目录与上架条件

| 项目 | 输入与用途 | 当前状态 / 本轮取舍 |
| --- | --- | --- |
| 基础量价包 | 现有 10 个量价特征 | 已有，B0 默认；逐项定义和版本可查看 |
| 我的数据 | 自有指标、资金流、舆情分数等，作为特征 | 已有导入与 `x_` 入口；首批产品化对象 |
| 我的规则 | 经验公式作为输入特征 | 后续受限表达式；过滤和硬约束进入各自契约，不冒充特征 |
| Alpha158 风格包 | 成交量等必需字段、单位与窗口满足的量价模板 | 后续扩展；逐式核对、定义身份并注明 Qlib 来源与许可；不得用成交额冒充成交量或以不完整实现声称完整兼容 |
| 估值、盈利、质量 | 财务公告/修订与实际可用时点 | 数据未满足前不上架；仅有报告期或公告日期不自动构成完整 PIT 数据 |
| 等权组合 | 经预先指定方向的特征排名组合 | 后续简单基线；不根据检验结果自动翻转方向，缺失与归一化规则冻结 |

| 原始行情模型 B1 | 行情窗口到学习表示及分数 | 研究入口已有；共同任务、真实数据、推理与资源验收后接网页 |
| 直接学组合 B2 | 行情/特征及状态、约束到组合决策 | 研究阶段，不作为当前闭环交付依赖 |

未上架项目放在帮助或路线说明中，不以一排不可点击选项占据默认编辑器。已上架但当前数据不兼容的项目显示具体缺项；已保存配置不能因不兼容而静默移除组件。

每个来源/组件登记：`id`、版本、字段和单位、适用任务、时点规则、处理方法、依赖、来源与许可、内容哈希。组件历史结果仅在同一比较系列下引用，跨系列展示来源标签，不预示本次也有效。

### 4.2 三条路线

特征 + B0、原始行情 + B1、直接学组合 B2 可以并存；人工因子不是必经中间产物。工程上保留信号/治理/账本职责，不限制研究时的联合训练。

Kelly、Kuznetsov、Malamud、Xu 的 [AIPM，NBER w33351](https://www.nber.org/papers/w33351)，2026 年 6 月修订版，直接学习 SDF 组合权重并使用跨资产注意力；输入仍是 JKP 筛选后的 132 个股票特征（§4.1），不是原始行情无特征方案。该论文与 JKMP 的成本感知组合论文不同，不能据美股月频 SDF 实验宣称已解决本项目 A 股多头账户的交易摩擦。

B2 的排序指标若不适用，应标“不适用”，在独立账户比较决策结果，不把持仓权重冒充预测分数以强行复用模型成绩卡。

## 5. 参考、增量与验证纪律

### 5.1 两个比较对象，固定参考版本

默认比较当前配置与基础参考；已有父版本时同时展示上一版，避免只告诉用户相对平台默认的差距。父版本也可能没有优势，不将其称为统计最优模型。

新比较系列绑定创建时的基础量价 + LightGBM 版本，此后固定。平台升级只影响新系列；用户明确选择升级时创建新系列，在新参考下重跑需要比较的配置，不改写旧结论。无法运行参考时显示具体失败，不替换为更弱基线；候选可单独保存，比较保持未完成。

缓存按任务、实际基础输入内容、处理/特征与引擎实现、参数/种子、折与评估协议、依赖版本生成内容键；相同输入复用成功产物，防止并发重复计算。新增候选自有特征不能污染基础参考的输入身份。失败、中断或校验不完整的缓存不复用；经济回放另外绑定账户、规则、成本和执行版本，不能只凭模型缓存命中。

### 5.2 可比性契约

- 比较双方共享任务、行情身份、股票池规则、标签、开发折和评估日期；所有标签在拟合/选参时已到期，处理器只在允许的历史段拟合。
- 评估总体独立于候选配置定义。新增特征缺失不能悄悄删掉难预测股票；主要报告覆盖与未出分日期，最低覆盖沿用相应协议。完整交集可另作诊断，但不能替代主结果或掩盖覆盖失败。
- 新增数据若同时修改行情、期限、股票池或预处理，则标“多处改动”，不能将全部差异归给新增因子。任务/样本改变建立新系列，需要重算参考，旧成绩不直接相减。
- 同类随机模型配对种子；Ridge、等权等确定性方法不伪造多种子，也不要求不同引擎的种子具有同等含义。模型比较共用历史选参规则并报告各自预算，不能用候选的大量搜索对比参考的一次随手运行。
- 基础参考、父版本及单项对照均使用真正逐折样本外预测。最终重拟合模型不能回填其训练期成绩。

### 5.3 开发区与最终确认

| 区域 | 用途 | 允许的行为 |
| --- | --- | --- |
| 开发比较 | 用户反复添加、移除和修改 | 滚动历史验证，显示开发标签和可见配置数；支持下一步建议 |
| 最终留出 | 对已冻结候选做额外确认 | 候选、比较对象、协议先冻结，再揭示结果；登记整个揭示批次 |
| 前向记录 | 观察冻结配置上线后的表现 | 按时记录、迟到重建、历史演示分别保存；不承诺等待多少天必能裁决 |

开发区可以反复使用，不能每次改名就声称获得新的独立检验。最终留出揭示后，再按其结果修改的版本只能把该段当已知历史；新快照、复制项目或移动日期边界不能抹掉本地可追溯的揭示记录。未来新增未见日期才可能提供新证据；平台无法认证用户未在别处看过数据。

“已完成”“可运行”“历史改善”和“收益有效”是不同状态。无硬伤的候选可以进入规则检验和明确标记的纸面观察，不要求先证明 alpha。硬时点/执行错误不能被用户点击绕过。

### 5.4 自动比较与计算预算

默认自动运行当前配置、基础参考、可比的上一版；优先复用缓存，最多自动安排三组配置，不启动逐项全量消融。提交前展示计划、缓存命中和预计耗时；一台机器默认只训练一个作业，其余排队，可取消。

用户一次只加入或移除一组自己的数据，且父版本兼容时，当前与父版本就是该组数据的增量实验，无需再重训一遍。没有父版本时，以相同配置移除该组数据形成配对对象。若已占满自动预算，优先完成这组配对，其他对照标记待运行并由用户选择；不隐瞒少跑了什么。

“分析各项作用”由用户主动运行：先选组件、展示新增拟合数与预算、再运行。默认按数据源/特征包分组，不按每列逐一训练。取消或失败后已完成产物保留；算法不支持移除输入时明确不适用，不自动换引擎。

### 5.5 增量结论

“去掉一项”必须重新拟合，固定任务、样本、其他组件和预先登记的训练/历史选参规则。结论是**该组输入在当前配方中的条件增量**；有交互作用，多个增量不能相加，不能称因果贡献。多处改动的父子差只代表整体变更，不能拆给单项。

主指标为配对逐日 RankIC 差，配合日期相关性稳健的区间、有效天数、覆盖、逐折/分年度结果；时间块或 HAC 方法及窗口在比较前固定。种子波动为算法敏感性诊断，不能代替市场日期的不确定性；一年或少量种子不构成长期稳定证据。

首版沿用既有配对统计契约；批量组件分析必须登记比较族和多重比较处理。未具备有效区间、覆盖不足或比较族未校正时只显示探索差值，不出明确正负向结论。重复开发选择的偏差不会因单次区间或批内校正自动消失。

| 状态 | 必需依据 | 表述边界 |
| --- | --- | --- |
| 当前有改善证据 | 协议有效，配对区间下界大于零；批量比较按已登记校正；敏感性没有实质相反结果 | 只指指定开发样本的排序改善，不称未来收益更好 |
| 暂不能判断 | 区间跨零，或样本/精度不足 | 不能写“没有作用”“保留与否影响不大” |
| 当前有退化证据 | 同口径区间上界小于零 | 提供父版与组件对照，不断言永远无效 |
| 结果不稳定 | 有足够分段结果且出现实质反转，或结论依赖少数日期/种子 | 展示具体分段；轻微符号变化不自动判不稳定 |

未运行、失败、样本不足分别显示，不硬塞进四类。统计与稳定性可同时标记；明确写出冲突，不用单一颜色覆盖。

统计正差不自动等于值得保留。并排显示幅度、额外数据依赖、训练耗时与资源；差异很小但维护代价高时，用户可以继续用简单版本。经济价值仍需在相同账户规则下检验，不能用排序显著性代替。

### 5.6 相似度与尝试记录

相似度为共同合格样本上的逐日预测秩相关汇总，并显示样本范围；可另列目标/持仓重叠，名称分开。与基础参考不同不代表与其他用户不同，不提供“独特性分数”或排名。

常驻简短计数，例如“开发比较 · 4 个配置”；详情区分配置数、运行次数、种子、自动参考/消融、失败和重跑。缓存命中不新增配置，平台建议生成的新配置照常计数，最终留出揭示单独计数。可归档任务，删除大产物保留最小元数据并标记不可重算；本地计数不覆盖外部操作或人工删除，不能宣传为不可篡改审计。

## 6. 诊断与下一步

### 6.1 先证据、后建议

诊断是结果的解释，不是自动证明问题原因。按数据/运行硬阻塞 → 比较不可用 → 已观察的负向差异 → 不确定性排序；同页只突出一个主要发现、一个主动作，最多两个次要动作。优先依据确定性、修复成本和信息价值排序，不以未经验证的“预期收益”排序。

| 情况 | 必需依据 | 首屏发现与可执行动作 |
| --- | --- | --- |
| 数据或时点有硬伤 | 实际检查失败及涉及字段/日期/行 | 列具体缺项；主操作定位原导入映射/来源，不清空草稿。切换免费样本是新实验，不能冒充修好了用户数据 |
| 比较未完成 | 参考失败、覆盖不足、协议不兼容或任务中断 | 显示已完成结果与缺项；修复后仅补跑缺失工作，不给无依据的增量结论 |
| 排序能力暂不明确 | 有效 IC 区间跨零 | “现有样本尚不能确认排序能力”；查看基础参考或已有配对结果，不写“没有能力” |
| 有排序证据，交易表现弱 | 相应规则回放已完成；给出实际毛/净差、费用与换手 | 展示费用侵蚀的具体金额及假设；有依据时创建一版免交易带候选，仍用相同回放检验，不能仅因净收益不显著就宣称全由成本造成 |
| 改动暂不能判断 | 配对区间跨零或精度不足 | 保存候选、查看差值范围、可运行时继续纸面观察；不要求再训练才能离开 |
| 部分时期退化或整体较父版弱 | 实际分段或配对负向证据 | 定位版本差异与对应结果；恢复父版到新草稿，旧版不覆盖；未跑消融不能点名某列是原因 |

检查能力有限也要可见：没有历史退市/修订数据时显示“无法核查”，不能显示“退市偏差检查通过”；声明可用日不等于独立证实无前视。

### 6.2 建议必须可执行

每条建议带 `finding_code`、证据产物、适用条件、目标阶段、预填改动和比较对象。点击先生成草稿并显示差异，用户明确运行后才消耗训练预算；不自动改模型、股票池、账户或每日任务。

建议不改变经济语义：调仓频率只在引擎和信号契约支持时出现；改变预测期限/股票池要创建新任务系列，不能复用旧基准。增加年份/股票数只有在可用历史确实存在且时点合格时才建议，不能泛化为一定更有用。

连续几次未改善仍允许暂停，不弹“再试一次”、不自动搜索更多参数。保留整理好的数据、配置与负结果，使用户以后可以继续；不以不断试验制造留存。

## 7. 运行版本与候选版本

### 7.1 首版预算与边界

每个策略默认最多 **2 个同时启用的候选影子账户**，另有 1 个正在运行版本；归档候选不占名额。达到上限时提示暂停哪个候选，不自动替换。上限是单机维护预算，可在高级运行设置调整并显示资源影响，不是统计保证。日常同源数据更新共享，账户任务串行并各自事务去重。

第一轮 M1–M4 不依赖影子账户实现。候选可先保存历史结果、与父版比较、进入独立纸面观察；不能为等待 M5 留下无动作的空页面。

### 7.2 公平比较与保留原账户

已有运行账户不能直接与新建全现金候选的全路径收益相减。创建配对观察时，在已完成且可重建的决策边界，用运行账户当时的现金、持仓、可卖/待结算状态、调仓计数相位及共同规则建立两份独立分支：当前模型对照和候选。存在挂单、公司行动或其他未支持状态时不能省略；若引擎不能完整表达，禁止标记“公平配对”，可建立各自独立账户并明确不可直接比较。

候选的拟合与选择在前向起点之前完成，不能把后来训练的模型回灌为此前已运行。两分支从同一起点接收相同输入快照与执行协议，各自预测和记账；创建分支不写主账户，主账户仍可按原计划正常追加。只改模型以评估模型增量；若规则也改变，标签为整套策略版本比较。比较使用共同完整日期，缺失、受阻和迟到可见，不删掉一方失败的日期；同时报告实际仓位、换手、费用和风险差。展示这段配对观察与原账户全历史的区别。

### 7.3 明确替换与版本历史

替换由用户主动选择，不因几天收益领先自动推荐。页面展示改动、比较范围、前向天数、覆盖与执行阻塞；证据不足可以明确启用观察，硬错误仍阻止。

替换在明确的下一决策边界生效，生成新运行版本和新账户，核对初始现金、持仓及可卖状态；缺少状态承接能力时只能新建独立观察账户，不能称无缝切换。是否继续旧账户单独选择，默认保留其原运行设置，防止无提示停记。

旧模型、账户与记录均保留，新版前向天数单独计算；不把旧版最佳片段、影子历史或回测拼进新成绩。默认版本历史为“v2 比 v1 加入资金流”的列表，完整分支树按需展开，不强迫用户理解树结构。

## 8. 用户价值与边界

| 用户的目标 | 本版要交付的具体能力 | 不作的承诺 |
| --- | --- | --- |
| 看自己的数据有没有帮助 | 时点和覆盖预检，同配置加入/移除来源的配对实验 | 任何数据都能带来 alpha |
| 结果不好还能推进 | 有证据的发现、预填下一版、保存与暂停 | 总能调出好成绩，诊断能识别所有失败原因 |
| 不写完整研究系统也能比较 | 配置、缓存、任务、版本与比较在一个项目里 | 其他平台没有这些方法或不能本地运行 |
| 按自己账户长期使用 | 同一规则和账本，运行与候选分开保留 | 历史或短期前向能最终证明未来收益 |

开源、本机运行、图形界面和可扩展性继续成立；输入、统计和账户信息默认不离开本机。分享模板须排除私人数据、路径、账户初值及未授权产物；第三方数据遵循用户持有的授权，上传不执行任意代码。

财务、行业分类等来源按其真实发布时间、修订、历史有效期检查，不能都套用“公告日”一条规则。不改变既有交易规则，也不把平台未实现的检查列为已通过。

## 9. 工程职责与产物契约

以下为新增契约的职责要求，字段名可在实现 ADR 中细化，不能据此声称 API 已存在。

| 产物 / 职责 | 最小保存内容 | 复用基础 |
| --- | --- | --- |
| Recipe | 父版本、任务、来源及组件版本、引擎、参数、显式修改、输入/处理身份 | daily.selected_features、dataset、实验配置 |
| ComparisonSeries | 评估总体、标签、时间折、参考规格、统计方法、开发/留出范围与揭示记录 | 现有任务、folds、Bench 协议 |
| Attempt / JobPlan | 配置哈希、运行角色、依赖、预算、状态、错误、缓存与产物校验 | worker、任务队列、实验归档 |
| ComparisonResult | 比较对象、有效日期、覆盖、配对差和区间、分段、算法敏感性、局限 | pipeline 与 Bench 配对统计；须分别适配，不能混用协议 |
| Finding / SuggestedChange | 可核验原因码、证据引用、适用条件、预填变更和下一步路由 | 预检、审计、比较与账户诊断 |
| PairedObservation | 共同起点状态身份、两分支配置、数据/执行身份、记录质量与完整性 | 既有账本/看板；完整状态分支能力另行验收 |

缓存与配方不能仅以名称或目录路径寻址。实际特征选择必须贯通训练、最终模型及每日推理；移除来源后旧运行版本仍能读取其冻结依赖。语法错误、缺字段、依赖循环、不支持的引擎和非法无穷值在开始前拒绝；缺失值按引擎已声明的处理契约检查，不能统一当硬错误。错误返回到对应编辑位置。

## 10. 交付顺序与验收

| 里程碑 | 交付 | 验收硬线 |
| --- | --- | --- |
| M1 配方、参考与直接结果 | 数据预检、不可变配方、固定系列、参考缓存、结果并排 | 相同身份复用；改变数据/实现正确失效；参考失败不伪造比较；取消/重试可追溯 |
| M2 诊断与下一版 | 证据驱动发现、预填改动、保存/暂停、开发标签 | 阻塞/不确定/退化分别处理；每个动作落到可执行草稿；不清空用户输入，不绕过硬错误 |
| M3 我的数据完整闭环 | 一组自有数据与父版/去除版的配对，覆盖和时点提示 | 实际导入、训练、比较、保留/移除，再接规则与部署；使用真实产物而非 mock 数值 |
| M4 按需组件分析 | 分组消融、预算、相关度、种子敏感性、批量比较族 | 真正重拟合；不强制交集删样本；不相加组件增量；确定性模型无伪种子 |
| M5 候选并行观察 | 名额、状态分支、完整日期、明确替换 | 创建分支不写主账户、原有记录前缀不改；起点/可卖状态/节奏一致；缺失受阻可见；替换与重试不重复记账 |
| M6 扩展模型入口 | 共同任务下的 B1 网页接入、简单组合；再按证据增加特征包 | 各自输入和推理契约完整；有简单基线、真实数据验证和资源记录，不以新模型必须赢为通过条件 |

首批交付 M1–M3，先把用户自己的数据变成可比较的版本。M4–M6 按资源逐项验收，不以一次交齐作为 1.0 前提；B2 不在本轮验收范围。

交叉验收至少覆盖：未来输入/标签扰动不改变此前拟合；训练期处理不读取验证/留出；新增来源缺失不改变评估总体；输入相同缓存命中、实现改变失效；单次不确定不显示无效；无交易回放不推断成本原因；最终留出重复揭示有记录；导入/取消/失败后草稿与可用产物保留。

浏览器端到端使用实际任务和隔离账户，覆盖首次训练、自有数据增量、负结果后的下一版、默认/高级切换、关闭后续做、进入规则与部署、手机布局、帮助入口。合成样本验证软件行为；真实数据另记录协议、成本与覆盖，不把冒烟结果当经济增量。

产品验收邀请至少 3 位未参与开发的用户，包含不写代码者和有研究经验者；不用口头指导完成一次“导入 → 比较 → 决定保留/移除 → 规则检验”，记录中断点、完成时间与用户能否复述比较结论。此样本用于发现问题，不宣称证明市场留存。资源数据就绪后的配置目标沿用五分钟，不把训练耗时算成用户操作负担，也不承诺固定总时长。

## 11. 衡量是否值得继续

- 首个有效结果：有多少人从导入走到可解释的比较，在哪一步退出；准备、主动操作和后台计算时间分开记录。
- 有效下一步：结果不佳后，用户是否能找到并完成一次有依据的修改，或明确选择保存/暂停；不把盲目重训计成功。
- 可理解性：用户能否说出与谁比、改了什么、当前是否能下结论；不能只凭点击次数推断。
- 运行可靠性：选定版本是否按规则持续记账，数据/信号受阻是否可见；不以账户涨跌评价软件质量。

首次试用形成基线后再设转化/回访目标，不虚构行业阈值。默认只生成本地可导出的诊断记录；外发行为数据需要单独明确选择，不顺带收集数据或持仓。

## 12. 本版采用的五项首版决策

| 问题 | 本版选择 | 理由与后续条件 |
| --- | --- | --- |
| 参考系固定还是升级 | 比较系列内固定，升级显式建立新系列 | 保留旧结论；平台可以迭代，新参考不悄悄移动旧标尺 |
| 增量对照自动还是手动 | 参考/可比父版自动；单组数据改动自动配对；全量分组消融按需 | 先给用户直接反馈，避免每点一个选项都成倍训练；预算和未完成对照可见 |
| 影子账户上限 | 每策略默认 2 个候选，另有 1 个运行版本 | 控制单机计算与选择负担；可归档释放，不自动挑胜者或删账户 |
| 先 Alpha158 还是我的数据 | 先把“我的数据”做成完整增量闭环 | 直接兑现用户投入；B1 是后续主要扩展，不转向堆因子库；Alpha158 非 1.0 前置 |
| 差异在噪声内的颜色 | 中性灰蓝，标签“暂不能判断”；硬错误红、待处理琥珀、已观察改善青绿 | 文字和图标同时表达，不靠颜色裁决；作业完成用中性色，避免和收益改善混淆 |

以上为本轮草案的工程与产品选择，允许评审后调整，不声称风险阈值、算力上限或统计判定已经过真实用户验证。后续更改版本化，已冻结比较和账户继续按原身份读取。
