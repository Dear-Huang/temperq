# 策略审计：结论可追溯与口径分离 SPEC

版本：0.3，2026-10-28。状态：**P0、P1 已实施**（R0–R5，附 R6 的比较口径）；P2、P3 待实施。0.1 的评审意见见 §8，首批同区间复跑结果见 §10。

目标：每条审计结论都能追溯到仓库里写明的规则、数据和公式，而不是开发者的经验判断；事实、情景和经验阈值在页面上分开标注；依赖用户输入的结论，写明依赖哪一个输入。

运行时不依赖大模型：审计全部是确定性计算，同一输入得到同一结果。本 SPEC 不改变这一点，只修正规则本身和结论的表述。

## 1. 问题清单

| # | 问题 | 来源 | 影响 |

## 2. 原则

1. **三类依据分开**：规则事实（交易所和税务规则、账务恒等式）、有出处的方法（论文、平台文档）、经验阈值。每条结论标注它用到的规则编号。
2. **事实不随用户输入变**：账目对账、"回测是否按它自己声明的模型扣费"，只用导出数据和代码或配置里的声明。
3. **依赖用户输入的结论写明依赖**：与券商合同比较的结论，只在合同口径确认后给出单一结论；未确认时给情景区间。
4. **只说数据能证明的**：原因不能确定时，写出现象和"要确定原因还需要什么证据"，不写推测；"成交量为 0"和"数据缺失"分开。
5. **情景与收益分开**：固定成交下的成本节省是情景；收益影响只能来自重跑，且同区间重跑不等于样本外有效。
6. **审计不阻塞**：材料或确认缺失时继续审计，把受影响的结论降为条件情景并提示补什么。

## 3. 证据等级（所有卡片和检查项共用）

与 [审计覆盖](../STRATEGY_AUDIT_COVERAGE.md) 的四层证据对齐，替换 `audit_actions.EVIDENCE`：

| 等级 | 名称 | 含义 | 对应覆盖文档 |
| --- | --- | --- | --- |
| E1 | 记录事实 | 导出记录与账务恒等式上的复算 | 第 1 层 |
| E2 | 描述 | 事后分组，不证明改了会更好 | 第 1 层 |
| E3 | 情景 | 在声明假设下估计，固定原成交 | 第 2 层 |
| E3c | 条件情景 | 情景的某个前提未确认（如期初账户、券商费率），结论随它变 | 第 2 层 |
| E4 | 同区间复跑 | 改版在同一段历史、同一初始账户上重跑后的比较；仍是样本内 | 第 3 层 |
| E5 | 独立验证段通过 | 冻结候选后，在开发时未看过的验证段上比较通过 | 第 4 层 |
| E6 | 前向观察 | 模拟盘或实盘记录 | 第 4 层 |
| N | 待补材料 | 缺少计算所需材料 | — |

每个结论保存 `evidence`（等级）、`rules`（规则编号）、`conditions`（未确认的前提，空表示无），页面按这三项渲染。

## 4. 方案

### R0 最小规则注册表与证据字段（P0，R3、R5 的前置）

新增 `src/qwb/audit_rules.py`，P0 只建后端，界面放到 R2：

```python
Rule(id="T-HOLD-SHORT", kind="threshold", value=5, unit="自然日", applies_to=("stock", "fund"),
     range=(1, 60), text="持有 5 个自然日以内算短持有", source="经验阈值，未经样本检验")
Rule(id="F-TICK-STOCK", kind="fact", value=0.01, unit="元", applies_to=("stock",),
     text="股票最小报价单位 0.01 元", source="沪深交易所交易规则")
Rule(id="M-TICK-HALF", kind="method",
     text="价差下限 = 每边半个最小价位", source="作者 STRUCT 稿（SSRN，未经同行评审）")
```

- `kind` 取 `fact`、`method`、`threshold`；只有 `threshold` 可调。
- 报告保存本次使用的全部规则值和注册表版本，纳入结果摘要。
- 卡片的每个金额带公式和乘数，例如 `avoided_cost = avoided_switches × mean_round_trip_cost`，同时存两个乘数的值。

首批经验阈值：

| --- | --- | --- | --- | --- |
| T-HOLD-SHORT | 5 自然日 | 1–60 | 全部 | 持有期卡 |
| T-PRICE-LOW | 5 元 | 1–50 | 股票 | 低价股卡 |
| T-MIN-COMM-MATERIAL | ¥500 | 0–100,000 | 全部 | 最低佣金卡 |
| T-BUFFER-RANK | 前 2 名 | 2–10 | 全部 | 换仓卡 |
| T-WHIPSAW-DAYS | 5 个信号日 | 1–60 | 全部 | 换仓卡 |
| T-CHURN-WORTH | 占比 ≥ 20% 且 ≥ 3 次 | 0–100%、1–100 | 全部 | 换仓卡状态 |
| T-CASH-BUFFER | 1% | 0.1–10% | 全部 | 现金余量卡 |
| T-FEE-GAP | 差额 ≥ 1% 且 ≥ ¥1 | 0–10%、0–1,000 | 全部 | 费用卡出现条件 |

### R1 规则文档与依据展示（P1）

- 卡片"依据"一栏列出规则编号、类别和来源；`threshold` 显示"经验阈值"标签。
- 由注册表生成 `docs/AUDIT_RULES.md`；文档与代码不一致时测试失败。

### R2 判断口径设置（P1）

- 审计设置页增加"判断口径"折叠区，只列 `threshold` 类规则，显示单位、允许范围、适用资产和"恢复默认值"。
- 交易所规则、税率、账务恒等式不在此处出现。
- 改阈值生成新报告，旧报告不变；卡片显示口径句，如"按 5 天算短持有"，并链接到设置。

### R3 费用四组口径（P0，解决 P2、P3、P4）

每份报告保存四组字段：

| 组 | 字段 | 性质 |
| --- | --- | --- |
| 回测声明模型 | 来源（代码行或配置键）、引擎与版本、资产类型、买卖方向、佣金率、最低佣金、印花税、其他费用、计费单位（按委托/按成交） | 记录事实；无法完整解析时标"不完整"，列出缺哪一项 |
| 回测实际扣费 | 原始费用、费用组成（佣金/税/其他，导出给出时）、收费单位、证据来源（文件与行） | 记录事实 |
| 券商合同口径 | 已确认/未确认、佣金率、最低佣金、税费、其他费用、确认时间 | 用户输入 |
| 审计情景 | 1bp、2bp、3bp 等假设，每个给出复算费用 | 情景 |

规则：

- 不再从"费用 ÷ 成交金额"推出一个"实收费率"作为结论。这个比值受最低佣金、计费单位、部分成交、整单费用分摊、税费和其他费用影响，只作为描述性辅助数值显示，并列出它包含的成分。
- RQAlpha 的 multiplier 只有在同时固定引擎版本、基础费率表、资产类型和最低佣金规则时才解析为声明费率；缺任何一项时，声明模型标"不完整：仅定位到配置键"。
- 费用结论拆成两项：
  1. **回测是否按自己声明的模型扣费**：声明模型完整时，用声明模型逐笔复算并与实际扣费比较，结论为一致/不一致（E1）。38 号声明 2bp，结论"一致"，不随审计情景变化。
  2. **回测与券商合同口径是否一致**：合同未确认时只显示情景区间（E3c），不给"偏高/偏低"；确认后给单一结论，例如合同 1bp、回测 2bp →"回测成本高于合同口径约 ¥1,330，结果偏保守"。
- 效果验证页的重算按钮改名为"按费率情景重算"，标题写明所用费率及是否已确认。

### R4 未持有目标：汇总现象，区分零成交与缺数据（P0，解决 P5）

信号映射按"标的 × 信号时点 × 平台原因"汇总，例如：

> 26 天未持有选中的目标，全部是 513100.XSHG，全部在 9:31 下单，平台原因均为"当前无成交量"。

- 原因只用平台在委托详情里的原文；没有委托详情时写"原因未知"。
- 汇总集中在一个标的或时点时，附"要确定原因需要"：该标的当天的分钟数据，或原平台同区间的委托/成交导出。
- 不输出"迁移造成""数据缺失""流动性不足"等推断。

可选：用户上传分钟数据时，逐日记录并区分以下事实：

| 记录项 | 说明 |
| --- | --- |
| 时间戳语义与时区 | 分钟线标签是起点还是终点，时区 |
| 交易日历 | 该日是否交易日 |
| 数据版本 | 数据包路径、更新时间或版本号 |
| 该分钟是否存在 | 有行 / 缺行 |
| 成交量 | 有行时的数值；"0"与"缺行"分别报告 |
| 首个非零分钟 | 当天第一笔成交的分钟 |
| 平台原始拒单原因 | 委托详情原文 |

只有"有行且成交量为 0"才写"成交量为 0"；缺行写"该分钟无数据"。

### R5 换仓情景显式写出期初账户状态（P0，解决 P6、P7）

换仓卡标题改为"固定成交下少换 16 次，费用和价差情景约 ¥1,837；收益影响需重跑"，并显示：

| 字段 | 示例（38 号，已声明空仓起步） |
| --- | --- |
| 少换次数 | 16 |
| 配对口径 | FIFO |
| 已平仓笔数 | 39 |
| 期初状态 | 空仓，现金 ¥100,000 |
| 平均每笔成本 | ¥114.81（费用 + 价差情景） |
| 每笔成本是否随审计佣金变化 | 否：取导出的实际费用 |

期初状态的三种情况：

| 期初状态 | 处理 | 证据等级 |
| --- | --- | --- |
| 已声明空仓，给出现金 | 首日成交进入 FIFO | E3 |
| 已声明有期初持仓并给出成本 | 期初持仓按给定成本进入 FIFO | E3 |
| 未确认 | 首日收盘持仓按"成本未知"处理，不进配对；提示"首日持仓成本未确认，换仓节省仅为条件情景"，建议补填 | E3c |

### R6 改版复跑与证据升级（P2，解决 P8）

- 每张可改的卡片给出步骤：按卡片改代码 → 原平台重跑 → 在效果验证页上传，并选择"这次验证的是哪张卡"。
- 同口径比较两版（同一费率情景、同一期初账户、共同日期）。结果写回该卡：
  - 同区间重跑 → **E4 同区间复跑**，显示"更好 / 有得有失 / 更差（样本内）"。
  - 改法和候选值在开发段冻结后，验证段比较通过 → **E5 独立验证段通过**。
  - 模拟盘或实盘记录 → **E6 前向观察**。
- 不使用"已验证"这一笼统说法。
- 本地 RQAlpha 改版目录约定：与原版同样的六个文件，另加 `变更说明.md`（改了哪张卡、哪一行、候选值、开发段与验证段）。

### R7 经验阈值的检验（P3，长期解决 P1）

检验前先写并冻结登记文件 `threshold_trial.json`，冻结后不改：

| 登记项 | 要求 |
| --- | --- |
| 开发区间、验证区间 | 固定日期；验证段不参与选值 |
| 候选值 | 全部列出，例如保留带 {2, 3, 4} |
| 看验证段的次数 | 只看一次；看后不再调整候选 |
| 评价指标 | 预先指定主指标（如费用后净收益）和约束（如最大回撤不恶化超过 X） |
| 策略间汇总 | 预先指定，例如改善策略占比与中位数差 |
| 多重比较 | 报告候选总数；主结论按全部候选中最好与默认值的对比给出，不只报最好的那个 |
| 失败结果 | 全部保留，包括未改善和运行失败的策略 |

规则晋级条件：验证段按登记的主指标和约束通过。晋级后，规则来源从"经验阈值，未经样本检验"改为引用检验报告编号；未通过时保留"经验阈值"，同时附上失败的检验报告。

检验脚本和逐策略结果放本地；仓库放登记文件、汇总结论和方法。

### R8 格式覆盖与可复现回归（P3，解决 P9）

仓库内（`tests/fixtures/formats/`）：

| 内容 | 说明 |
| --- | --- |
| 脱敏表头 | 每个平台、每类文件的真实表头，无数据行 |
| 合成最小样例 | 每种格式一套能闭合账目的最小数据 |

## 5. 不做

- 不在审计运行时调用大模型。
