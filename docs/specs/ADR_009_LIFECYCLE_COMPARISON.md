# ADR 009：应收权利与事件日程的版本化比较

日期：2026-10-23。状态：本机定向验证通过，完整阶段未关闭。依赖：[ADR 004](ADR_004_ACCOUNT_LIFECYCLE.md)、[ADR 006](ADR_006_CONTINUOUS_ACCOUNT.md)、[N03 SPEC](N03_UTILITY_TRAINING_SPEC.md)。

## 问题与决策

应收总额一致不能说明支付时点、权利归属或未来现金流一致。登记但尚未除权的分红不进入当日净权益，仍影响后续现金流；金额为零但有正数有权股数的记录同样不能忽略。只比较收盘总额会漏掉这些差异。

在 `e2e_utility_v1.acceptance` 中增加可选的 `state_comparison_version`。省略或设为 `aggregate_v1` 时保持原门槛集合与原总额比较语义，不补隐式新阈值。显式选择 `lifecycle_schedule_v1` 时必须填写四项额外门槛：

```yaml
state_comparison_version: lifecycle_schedule_v1
max_daily_entitlement_quantity_gap: 0.00000001
max_daily_entitlement_amount_gap_cny: 0.00000001
max_daily_entitlement_mismatch_count: 0
max_daily_processed_event_mismatch_count: 0
```

数量单位为股，金额为人民币元；示例仅为合成诊断的工程精度。计数必须为非负整数，其他值有限且非负。版本未知、缺字段、错误类型或在旧模式下混入新门槛均拒绝。新生成的示例显式采用新模式；旧结果不回写或自动提升验证范围。

## 比较语义

对每个交易日的**决策前和收盘后**两个账户状态逐项比较：

- 按 `event_id` 对齐全部未支付权利，包括未确认和零金额权利；数量、金额取逐事件绝对差的最大值，不能跨事件相抵。
- 权利缺失、多出或 `asset_id/kind/recognized/payable_at` 任一不同，按受影响事件计一次元数据不一致。支付时间转为 UTC 后比较，等价时区表示不算差异。
- 对 `processed_events` 取对称差，计数并保存双方独有的事件阶段 ID；顺序不作为集合身份差异。
- 当日门槛使用两个时点差异的最大值，逐状态详情另存；全段再取逐日最大值。总应收、现金、股数、交收、成交和费用继续使用各自原门槛。

这不新增会计事件种类，不验证真实数据是否完整，也不覆盖尚未支持的挂单、复杂税制或衍生品状态。仍须通过独立原始股数账户评价和公司行为手算验证。

## 零持仓语义

连续账户原先会在数量为零时建立零数量权利，精确账户不会。现在只有实际有权数量大于零时才建立分红/终止权利；事件阶段仍照常处理和留痕。**数量大于零、金额为零**的权利保留，包括全额声明扣税或零清算金额。这个存在性分支在数量零边界不光滑，不使用 straight-through，也不据此声称边界梯度唯一。

## 验收

用实际事件账户核对两个状态时点；在总应收和净权益不变的情况下，分别改变支付日、事件/资产/类型、权利股数和已处理事件，必须被新门槛识别。补充零金额权利的丢失/确认阶段、不同事件金额相抵、等价时区及零持仓案例。

费用分母为零时，相对差为 null，绝对费用门槛继续生效，等于门槛可通过。辅助收益预测或 seed 预测被修改后，即使更新产物哈希及版本声明，扩展验证也须通过 checkpoint 重算发现不一致。软件通过与代理一致性、市场有效性继续分别报告。
