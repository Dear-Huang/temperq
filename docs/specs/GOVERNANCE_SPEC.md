# 治理层 SPEC（草案）

版本：0.2，2026-10-23。状态：**草案，待产品负责人修改后冻结**。本文不改变已冻结的 `daily_strategy_v1` 协议和已有纸面账户；新能力以新协议版本和新账户承载。文献与工程依据见 [治理层 ML 证据笔记](../research/GOVERNANCE_ML_EVIDENCE_20261023.md)。

v0.2 变更：按证据笔记修正测量与回撤表述；把控制、选参和 ML 估计器分开；第一个学习组件改为风险预测头；首个交付缩小为三项规则；回放改为显式运行；补充缓存身份与等敞口对照。

## 1. 为什么做

本项目内部实验（ML 同质化 v4）中，扣除种子噪声后不同模型的选股相关度约 0.95–0.97。这只说明在该样本和设置下预测层差异小，不是普遍结论；数据更多不保证更好，相关度高也不等于组合或净收益相同。

产品上的判断是：预测层之外，**拿到信号以后怎么做**同样因人而异：什么时候动、动多少、留多少现金、何时降风险。这一层叫治理层。

- **个性化真实存在。** 资金、风险承受力、交易纪律因人而异。
- **部分差异可精确复算。** 在固定历史路径上，费用、换手、持仓可以逐笔重算；未来成本仍有模型误差，最大回撤是路径极值，波动大，不能说"测得准"。
- **符合账户原生。** 治理规则就是用户在自己账户上的纪律。

文献把这一层分为风险预测、动态配置、组合优化和交易执行；方法有成熟依据（Gârleanu & Pedersen 2013；Boyd et al. 2017；Brandt et al. 2009 等），但这不等于已证明能提高本项目 A 股账户的净收益，需要本项目自己的对照与前向记录。Qlib 等平台也有组合、风险和执行能力，我们的差异化落在用户授权、决策解释和账户闭环，不建立在"大平台没有治理"的假设上。

| 层 | 内容 | 谁决定 |
| --- | --- | --- |
| 信号层 | 每只股票每天的预测分数 | 官方基准模型、用户自训模型或外部模型（三选一） |
| 治理层 | 选股数量、权重、免交易带、节奏、风险控制 | 用户的授权书 + 规则 + 可选的估计组件 |
| 账本层 | 按可成交口径记账 | 平台，规则固定，用户不可改 |

用户的角色是**投委会**：定授权书和规则，审阅系统在授权内做了什么，决定是否继续。

## 2. 信号来源

| 来源 | 说明 | 边界 |
| --- | --- | --- |
| 官方基准模型 | 平台用公开日线训练、随包发布的 LightGBM 模型 | 只用公开日线训练，如实标注数据来源与期间；用户本地推理。平台不在服务器上公布每日选股 |
| 用户自训模型 | 现有训练入口产出的 B0/B1 模型 | 沿用现有冻结模型与数据源绑定 |
| 外部模型 | 体检入口导入的预测表（code, date, score） | 前向跟踪需用户每天导入新预测 |

首轮验收只选一类（默认：用户自训的 B0 模型），其余作为适配器后续接入。

信号与治理解耦：预测分数算一次并缓存，换治理规则不重新训练、不重新推理。缓存身份至少包含：信号来源与模型版本、数据快照、决策时刻与执行延迟、分数类型（排名或数值）及任何校准参数。只用 `(来源, 日期)` 不够。

基础模型分数通常是截面排名，不能未经训练期校准就当成预期收益与 bp 成本直接相减。

L2 数据只用于成本模型（STRUCT）的标定与验证，不进入基准模型训练；若将来要用，须先确认数据合同允许分发衍生权重，并如实披露。

## 3. 授权书（mandate）

规则和估计组件都在授权范围内运行。越界即拒绝或截断，在决策记录中写明原因。

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `exposure` | 股票总仓位下限/上限 | 0–100% |
| `max_weight` | 单票目标上限 | 等权时自动为 1/N |
| `cash_floor` | 最低现金比例 | 0 |
| `turnover_budget` | 年化单边换手上限 | 不设 |
| `drawdown_trigger` | 账户从高点回撤超过此值时进入降风险状态 | 不设 |
| `max_industry` | 单行业上限（需要行业数据） | 不设，后续版本 |

`drawdown_trigger` **只是降风险的触发阈值，不保证实际亏损不超过它**：跳空、跌停、T+1 和停牌都可能阻止执行。界面与记录须分开呈现"目标超限"和"实际持仓超限且无法卖出"。

授权书进入策略身份哈希；修改授权书等于新建策略版本。

## 4. 治理规则

当前代码固定为每 5 个交易日调仓、选前 10%（或 `n_hold` 只）、等权（`src/qwb/strategy.py:142–147`）。

### 4.1 v1（首个交付，只开放三项）

| # | 规则 | 参数 | 说明 |
| --- | --- | --- | --- |
| G1 | 持仓数 | `n_hold` 或 `top_share` | 现有能力，提到界面 |
| G2 | 单票上限 | `max_weight` | 草案：超出部分留作现金，不再分配给其他持仓（待决定，见 §11） |
| G3 | 免交易带 | `hold_until_rank` | 持仓排名未掉出前 K 名就继续持有；新买入仍需进入前 N 名；K ≥ N |

调仓节奏固定为每 5 个交易日，与现有协议一致。

### 4.2 后续，各自单独交付

| # | 规则 | 说明 |
| --- | --- | --- |
| G4 | 调仓频率 | `rebalance_sessions` ∈ {1, 5, 10, 20}；改变标签与持有期的匹配，需单独说明 |
| G5 | 止损 | 单票自买入成本回撤超过阈值，次日开盘卖出；冷却期内不再买入 |
| G6 | 大盘开关 | 基准指数低于 N 日均线时总仓位降至设定值；属于择时，需单独对照 |

执行顺序固定并写入协议：授权书检查 → （G5 止损）→ （G6 大盘开关）→ 选股（G1 + G3）→ 权重（等权 + G2）→ 授权书再检查 → 生成目标 → 现有成交规则。

所有规则只使用决策时刻（15:30）及以前的数据。

## 5. 估计与选参组件（可选，v2）

三类性质不同，分开列：

| 类别 | 组件 | 说明 |
| --- | --- | --- |
| 控制 | 波动目标 | 按风险估计缩放总仓位，使组合风险接近目标值；一个参数，确定性规则 |
| 选参 | 免交易带宽度选择 | 在训练期网格选 K，全部尝试入账，测试期只看一次 |
| ML 估计器 | **风险预测头（第一个学习组件）** | 小型线性/树模型，预测未来 5 日风险；与 EWMA、滚动波动基线比较 |
| ML 估计器（实验假设） | 元标签 / 执行价值头 | 判断一次触发的交易是否执行、执行几成；先作为待检验假设，不写默认有效 |

风险预测头的最低要求：

- 固定 5 日标签；日线平方收益单独命名，不称作 realized variance。
- 标签使用当时可定义的资产或持仓集合，不用未来选出的股票回填历史篮子。
- 除预测损失（如 QLIKE）外，同时检查实际敞口、费用、风险跟踪误差、换手和净收益；预测好不直接推出治理有用。
- 首轮对照只有两组：EWMA 风险估计 + 相同控制规则，对 ML 风险估计 + 相同控制规则。没有增益也算完成交付，默认值保留纯规则。

元标签的额外要求：用滚动样本外信号训练，不用基础模型在自身训练集上的分数；按日期分组并清除标签跨边界样本；标签区分"股票是否上涨"和"执行这次交易相对继续持有/现金是否有增量价值"。

可参考的工程：cvxportfolio（GPL-3.0，可与本项目 AGPL-3.0 组合）作目标持仓生成的参考与交叉核验；skfolio（BSD-3-Clause）；CVXPYlayers（Apache-2.0）。这些库只生成目标权重，A 股整手、T+1、涨跌停、最低佣金仍由现有成交与账本层处理，不引入第二套撮合。

不在本 SPEC 范围：B2 可微组合层、强化学习、大模型多智能体投委会。B2 有扎实研究路线，保留为长期候选；当前不默认上线是因为本项目验证不足，不是缺乏理论支持。

## 6. 快速回放引擎

- 输入：缓存的预测分数、行情面板、治理配置、授权书、初始资金。
- 复用现有成交规则与费用计算。
- 输出：每日权益、持仓、成交、受阻订单、费用、换手，以及每笔决策的原因码（§7.3）。
- 同一输入重复运行逐位一致；回放与纸面账户对同一天给出相同目标。
- 回放只用于历史调参，结论标注"历史回放"；不写入纸面账本，不冒充前向记录。
- 性能：耗时与内存实测后记录；不预设"必定几秒完成"。

## 7. 可视化与参与

### 7.1 治理面板

卡片调整规则和授权书，**点击"运行"才回放**，避免每次拖动都隐式增加一次尝试。结果更新净值、费用、换手、回撤。

### 7.2 新旧对照

固定同一信号和初始账户。新旧净值叠在一张图上，差异分解为费用、换手、回撤、收益。仓位水平不同时，补充相同平均敞口的对照，避免把长期多拿现金误认成治理能力。结论用一句人话 + 红黄绿灯。

### 7.3 决策回放

点选任意交易日，显示信号前 N 名，以及每只股票的决定和原因码。

首批原因码：`BUY_TOP_N`、`HOLD_IN_BAND`、`SELL_OUT_OF_BAND`、`CAPPED_MAX_WEIGHT`、`REDUCED_MANDATE`、`NOT_REBALANCE_DAY`、`SKIP_LIMIT_UP`、`BLOCKED_LIMIT_DOWN`、`BLOCKED_SUSPENDED`。G5/G6 上线时再加 `SELL_STOP_LOSS`、`SKIP_COOLDOWN`、`REDUCED_MARKET_FILTER`。

页面同时展示未约束目标、约束后目标、实际成交三层。

### 7.4 授权书检查

规则组合可能越界时标红并说明原因；回放中实际触发的越界和截断逐条列出。

### 7.5 投委会周报

纸面账户每周生成：本周决策汇总、触发了哪些规则、有无越界、与纯规则版本的差异、累计前向天数。

### 7.6 尝试计数

面板显示"本策略已试过 N 套规则"，所有回放尝试本地入账。本地台账只能校验一致性，不能证明未删除历史或未在别处试验，不宣称不可篡改。

## 8. 比较与社区（待决定，不进入首轮）

只比前向成绩，同一信号来源分组。历史样本外比较、成本压力和前向观察各司其职；几个月的前向观察也不是充分的盈利证据。

任何排序或百分位都是绩效比较，不因换名称而消除选择偏差。公开方式三选一，待产品负责人决定：

| 选项 | 做法 | 风险 |
| --- | --- | --- |
| A 不排名 | 只给本人看在群体中的位置 | 吸引力弱，仍有选择偏差 |
| B 多维成绩卡 | 公开成绩卡，注明前向天数，不以单一收益排序 | 中等 |
| C 收益排行榜 | 按收益公开排名 | 最接近收益竞赛，合规与宣传风险最大 |

首轮成功标准不是社区或排行，而是演示"同一信号、两份授权、不同决策的原因与后果"。

## 9. 边界

- 平台不托管资金、不连接券商、不自动下单、不在服务器上公布每日选股。
- 治理层输出是"用户自己的规则在自己账户上的建议"，不是投资建议。
- 账本仍只扣佣金和印花税，未计价差与冲击；STRUCT 接入前，所有对照必须标注此限制，不称全成本。

## 10. 里程碑与停止条件

| 里程碑 | 最小交付 | 停止条件 |
| --- | --- | --- |
| G0 共用契约 | 固定一个现有 B0 模型、初始账户、5 日节奏、成本声明；缓存身份按 §2 | 能解释一份信号如何变成当前目标 |
| G1 三项规则对照 | §4.1 三项 + 授权书前四字段；新协议 `daily_strategy_v2`；回放引擎与原因码；两组配置并排 | 默认配置下 v2 与 v1 同日目标一致；现金、整股、T+1 一致；前视截断检查通过；一位用户能说出一次规则改变为何改变成交或费用 |
| G2 成本口径与风险基线 | 接入一致的价差成本或明确做费用压力；EWMA 风险基线 | 不把佣金/印花税账本称为全成本；能复算费用、持仓和风险跟踪误差 |
| G3 风险预测头 | 一个风险头，对相同授权的 EWMA 控制 | 无标签跨界和基础模型泄漏；报告预测质量与经济影响；无增益也完成 |
| G4 前向双账户 | 冻结纯规则与 ML 治理两套策略，真实日更并排记录 | 自动运行、失败和漏记可见，修改即新版本 |
| 后续 | G4–G6 规则、元标签、周报、社区 | 各自单独立项 |
