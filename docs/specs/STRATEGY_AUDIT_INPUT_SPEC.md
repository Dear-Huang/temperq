# 策略审计：输入、周期与参数 SPEC（草案）

版本：0.5，2026-10-27。状态：**A1、A2 实施；A3已接入有限的治理代码候选，以及按订单计费和受阻目标对照；A4–A5及其他代码适配后续实施**。§9 的五项选择已按本轮授权定案。本文规定审计平台的页面结构、用户要交什么文件、回测要多长、哪些参数用户填、哪些由平台默认。计算方法沿用 [策略审计](../STRATEGY_AUDIT.md) 与 [审计覆盖](../STRATEGY_AUDIT_COVERAGE.md)；不使用规则卡或策略模板，用户带自己在其他平台做好的策略来。文件字段模板仅帮助录入，不生成策略或示例交易。

验收采用本地 BigQuant 的代码、交易、持仓、日志四件材料和聚宽持仓原表，私人文件不随仓库分发。当前定位到的聚宽材料只有持仓文件：可以核对并推算净变动，缺代码时阻止启动审计；不以合成代码冒充用户策略。

## 1. 页面结构

```
[TemperQ]  策略治理  盈亏归因  回测对比  模拟运行   我的策略  策略导入   ⚙

策略治理
当前策略：BigQuant · 策略名 · v1 ▾
```

| 页 | 做什么 | 是否需要上传 |
| --- | --- | --- |
| 策略治理 | 正文选择策略 → 具体审计发现 → 生成治理代码候选 → 逐环节结论 | 否；补件统一回策略导入页 |
| 盈亏归因 | 谁赚谁亏、回撤亏在哪、成本占多少；可选两个版本对比 | 否，读取当前策略 |
| 回测对比 | 原版本与优化版本并排比较，给结论灯 | 否；若优化改了选股，需用户回原平台回测后导入新结果 |
| 模拟运行 | 选策略版本开纸面账户，每日清单与成交回填 | 否；每日需导入当天目标持仓或信号 |

右上角常驻“我的策略”和“策略导入”，策略治理页把“当前策略”放在正文标题下方选择；其余页保留同一策略上下文。下拉最后一项是“+ 导入新策略”。所有上传、一致性核对、参数确认与缺项补充均在独立策略导入页完成；确认后才进入四页工作区。同一个策略无需重复上传已有文件。

“我的策略”逐条展示四个按钮：**一键审计、一键归因、一键回测、一键模拟**。一键审计复用已确认参数并生成新报告；未确认时先进入导入核对。归因读取当前报告；回测进入版本比较、模拟进入执行准备，不将尚未实现的政策重放或未启用的账户标作已运行。

导入缺项提供“上传对应材料”和“下载对应模板”。补件整份替换所选类别，沿用其余原文件，生成待确认的新材料版本；旧版原文件和报告不覆盖。模板按已识别平台生成，含空字段表和填写说明；不包含虚构的收益或成交。只上传模板表头时提示填写数据。

## 2. 用户要交的文件

### 2.1 文件清单

| 文件 | 必填 / 选填 | 平台用它做什么 | 缺少时 |
| --- | --- | --- | --- |
| 策略代码（粘贴或上传 .py/.txt） | **必填** | 静态读取设置候选及行号，用户核对后用于审计；优化代码属于 A3 | 缺代码可保存材料核对草稿，不允许开始审计；只有代码时允许独立的静态检查 |
| 回测交易记录 | **财务审计需要** | 每笔成交的成本、价差情景、持有期、来回交易 | 聚宽可由持仓推算净变动，注明“由持仓推算”；成交价、真实费用、日内往返及公司行动仍未知，不冒充逐笔成交 |
| 回测持仓记录 | **强烈推荐** | 每日总资产与现金、回撤、逐股盈亏归因闭合、分红送转后的股数 | A1 可审原成交费用与价位情景；仅在补齐行情等必要材料后才能近似重建，当前不虚构权益和回撤 |
| 运行日志 | **推荐** | 未成交订单、数量被调整、跌停卖不出、分红送转事件 | 成交可行性与执行偏离两项显示"未审：缺日志" |
| 每日打分 / 预测表 | 选填 | 信号能管几天、换一种构建方式会怎样、规则暴露 | 这三项显示"需要每日打分数据"，并给出导出方法 |

规则：

- 文件原样上传，不要求改列名、改编码。平台自动识别平台来源与文件类型（例如 BigQuant 的汇总行、聚宽 GBK 编码与多出的"总资产"列）。
- 识别结果先给用户确认："识别为 BigQuant 回测交易记录，642 笔，2024-05-07 至 2024-12-31。"
- 代码只读不运行。
- 文件只存本机，不上传到任何服务器。

### 2.2 各平台导出方法

页面按所选平台显示导出步骤（截图加文字）。首版支持：

| 平台 | 已用样例验证 | 待确认 |
| --- | --- | --- |
| BigQuant | 代码、交易、持仓、日志四个文件 | 每日打分（m2 输出）能否导出 |
| 聚宽 | 实际持仓原表；代码静态读取使用合成测试 | 用户实际策略代码尚未提供；交易记录与日志的导出入口和格式 |
| 其他（Qlib、Excel 等） | — | 按最小格式上传：`trades.csv`（code, date, side, quantity, price, fee）、`holdings.csv`（code, date, quantity） |

### 2.3 上传后先做一致性核对

在审计之前检查并显示，不通过时说明原因与处理办法：

| 核对 | 例子 |
| --- | --- |
| 代码里的回测区间与文件实际区间是否一致 | BigQuant 样例：代码写 2024-01-01 至 2025-12-31，数据只到 2024-05-01 至 2024-12-31，实际只跑了 8 个月 |
| 交易记录能否和持仓对上 | 前后两天股数变化是否等于当天成交 |
| 日志委托数与成交数 | 647 条委托、642 笔成交，差额来自未成交或数量调整 |
| 期初资金 | 代码中的 `capital_base` 与持仓首日总资产是否一致 |
| 价格口径 | 成交价与真实（不复权）价格的比例；聚宽样例为前复权，股数与金额会偏 |

## 3. 回测周期

不同审计项需要的长度不同。页面按实际长度显示能审什么、不能审什么。

| 回测长度 | 能出结论的审计项 | 不出结论的 |
| --- | --- | --- |
| 少于 3 个月 | 费用设置核对、价差估计、成交可行性 | 其余均标"样本太短" |
| 3 个月至 1 年 | 加上盈亏归因、回撤归因、规则触发统计 | 规则效果、回测对比只给数字，结论灯一律黄灯，注明"样本少" |
| 1 至 2 年 | 规则效果、回测对比可给结论灯 | 若未覆盖一次明显下跌，提示补充 |
| **2 年以上（推荐 3 年）** | 各环节满足长度门槛，可继续逐项检验 | 仍受材料、算法接入、独立日期、市场覆盖和区间限制，不能自动变绿灯 |

推荐：**至少 2 年，最好 3 年以上，并覆盖至少一段明显下跌。** 页面上传前就显示这句话。

另外两条硬规则：

- **规则效果检验至少20次触发且覆盖20个不同日期。** 同日多只股票、拆单不能冒充独立证据；达到门槛只允许检验，仍需区间、多重比较和验证比较支持结论。高级设置可提高，不能降至20以下。
- **默认末尾25%的日历时间作为内部验证段，至少3个月。** 建议只使用前段，默认边界前隔离20个观测交易日期，隔离后建议段也至少3个月；窗口更长时先提高隔离长度。无法满足则不登记可用的比较分段。
- **历史内部验证段不等于全新未见留出。** A2 只登记分段、摘要和资格，不运行优化或效果检验。原始账目事实可以展示全期；后续优化器只能接收建议段数据，已看过的回测尾段不能重新声称未见。

## 4. 参数：用户填什么，平台默认什么

### 4.1 用户需要确认的（多数从代码自动读出）

上传后显示一张"策略参数"卡，能从代码读出的已填好，用户只核对：

| 参数 | 来源 | 用户需要做的 |
| --- | --- | --- |
| 来源平台 | 用户选 | 选一个 |
| 策略名称 | 默认取代码注释或文件名 | 可改 |
| 初始资金 | 代码 `capital_base` 或持仓首日总资产 | 确认 |
| 佣金率、最低佣金 | 代码 `set_commission` / `set_order_cost` | 确认；改成自己券商的实际费率更准 |
| 持仓数、权重方式、持有期、调仓周期 | 代码 | 只读显示，读不出时请用户补填 |
| 成交价设置（开盘/收盘） | 代码 | 只读显示 |
| 回测区间 | 代码与文件 | 只读显示，不一致时提示 |

读不出的项目才要求填写；能读出的不再让用户输入第二遍。

### 4.2 平台默认，不需要用户填

卡片下方一行说明："以下由平台按研究默认值设置，一般不用改；懂的可在『高级设置』中修改。"

| 参数 | 默认 | 依据 | 能否改 |
| --- | --- | --- | --- |
| 卖出印花税 | 2023-08-28 前 10bp，之后 5bp，按成交日期自动选 | 财政部公告 | 锁定 |
| 最小价位 | 0.01 元 | 交易所规则 | 锁定 |
| 价差主口径 | 价位地板半价差（0.005 元 / 成交价） | 交易所规则，不依赖模型拟合 | 锁定为主口径 |
| 价差参考口径 | STRUCT 完整估计（滞后版 `struct_lagged_2021_2023_v1`），与主口径并排显示 | 作者 SSRN 稿，未经同行评审 | 可关闭 |
| 开盘、收盘集合竞价的摩擦 | 半档只作单列压力情景，不认作必付成本 | 竞价机制不同，需要对应数据另核 | 高级可改情景，不能认证实盘成本 |
| 涨跌停判定 | 按板块与日期的涨跌幅规则 | 平台规则包 | 锁定 |
| 卖出后观察窗口 | 5 个、20 个交易日 | 常用短期与月度窗口 | 高级可改 |
| 规则效果最少触发次数 | 20 次、20个不同日期 | 工程门槛，不是显著性证明 | 高级可提高 |
| 区间估计 | 日期分块抽样，20 日一块，2000 次 | 与平台其他检验一致 | 高级可改 |
| 验证段比例 | 末尾25%，至少3个月；建议段也至少3个月 | 历史内部对比，不保证数据未见 | 高级可改10%–50%，最低月数不降 |
| 边界隔离 | 20个观测交易日期 | 防止观察/标签跨界，须覆盖实际最长窗口 | 高级可改1–252；超过20日窗口须提高 |
| 免交易带候选宽度 | 持仓数的 1.5 倍、2 倍（待实测） | 093453 调整速度研究与本仓库换手诊断 | 高级可改 |
| 额外成本压力 | 每边 0、5、10、20bp | 成本压力检验 | 高级可改 |

高级设置里修改过的项，在审计报告首页列出"与默认值不同的设置"。

## 5. 审计输出

### 5.1 策略治理页

```
总结三行：1 处需修 · 3 处可改 · 4 处一致；最大一笔影响 ……
逐环节卡片
[ 生成优化后的代码 ]
```

每张卡片固定四行：

1. **发现**：具体到哪一笔、哪一条规则、哪一行代码。
2. **影响**：多少钱或多少 bp；能精确复算的写数字，估计的写"约"并注明口径。
3. **怎么改**：对应用户平台的代码改法。
4. **依据**：研究出处或交易规则，以及适用条件。

结论按用户本轮要求统一三种：🟢 **基本通过**、🟡 **缺乏证据**、🔴 **需要调整**。每项标题下用一句话说明“审什么”，不再用“构建/治理”等分类词或“基础测量”作结论。通过只限已检查的范围；未实现或缺少材料的检验不能变绿。不给总分。

### 5.2 优化后的代码

- 只改审计指出的地方，每处改动旁加注释，写明对应哪条发现。
- 不改用户的选股核心逻辑（因子、打分、过滤条件）。涉及选股的建议只写成文字，不直接改代码。
- 页面左右对照显示原代码与新代码，改动处高亮。
- 用户点"保存为新版本"后生成 v2；v1 与其审计结果保留不变。
- 必须提示："优化代码需要回到原平台重新回测；本平台不运行你的代码。"

本轮有限实现：

- BigQuant：对能精确定位的`if cash > 0: context.order_value(instrument, cash)`分支，真实小额买入和确认费率支持时，可选择增加最低买入金额判断；不拦卖出。金额按最低佣金/佣金率预填，不按历史收益调优，可由用户修改。
- 代码中唯一的`context.max_cash_per_instrument`常量高于用户确认上限时，可收紧到确认值；不自动放宽，不声称已修复存量超限。
- 逐处标明发现编号，保留因子、SQL、排序和卖出逻辑；改后做静态语法和下载字节编码检查。下载完整`.py`和`.patch`，候选独立存档，原输入与报告不改。
- 未识别的订单语义、动态表达式、其他平台和缺少相应发现的代码不强行改写。候选始终标为“待原平台回测”，不宣称最优方案或收益已改善。

### 5.3 盈亏归因页

总盈亏 = 逐股贡献 + 费用 + 现金，必须闭合；不闭合时显示差额与原因。另给最大回撤期间的逐股贡献、价差估计占收益的比例。

### 5.4 回测对比页

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| 平台重放 | 只改治理，且有原目标/打分、候选池行情、可交易状态及公司行动 | 同一信号与期间重放；仅原成交与行情不能恢复另一种构建。A1/A2 不运行该项 |
| 原平台回测导入 | 改了选股或平台无法重放的部分 | 用户把 v2 代码回原平台回测，导出四个文件后导入 |

结论按验证段给出，并注明本策略已比较过几次。

## 6. 策略命名与标签

**名称**：`来源平台 · 策略名 · 版本`，例如 `BigQuant · 反转二选一 · v1`。平台与版本自动生成，策略名用户可改。

**自动标签**（从代码与文件读出，用于筛选和后续使用）：

| 标签类 | 例子 |
| --- | --- |
| 来源 | BigQuant / 聚宽 / 其他 |
| 频率与周期 | 日频 · 每 5 日调仓 · 持有 2 日 |
| 规模 | 持 2 只 · 资金 100 万 |
| 风格（用户确认；自动推断只可提出候选） | 短期反转 / 趋势 / 量价；未确认则不标 |
| 数据完整度 | 四件齐全 / 缺日志 / 缺持仓 / 有打分 |
| 回测长度 | 8 个月 / 2 年以上 |
| 状态 | 已审计 · 有优化版 · 模拟运行中 |

版本号规则：v1 为原始上传；每次"保存优化代码"或"导入原平台新回测"生成新版本；版本只增不改。

## 7. 边界

- 平台不运行用户代码，只读解析。
- 审计结论说明"在给定数据和假设下"；回测对比不保证未来收益。
- 价差结论以价位地板为主口径；STRUCT 完整估计并排参考，标明作者模型、未经同行评审。
- 每日打分、交易记录中的时点由用户和原平台负责；平台只能做部分核对。

## 9. 本轮定案与待外部核实

1. **采用25%默认比例**，至少3个月；边界隔离后建议段也至少3个月。记录为历史内部验证，不认证未见。
2. **保留20门槛**，同时计不同日期；只作允许效果检验的最低条件，不能直接判有效。
3. **允许代码静态检查**，与财务审计分开，不显示虚构的收益或效果。
4. **聚宽交易及日志导出入口仍待真实账号核实**。本轮不索要账号或登录信息，不写未经验证的截图教程。已验证的持仓适配和受限净变动推算可用。
5. **风格由用户确认**。自动分类只能给候选，不能从收益或少数持仓推断为已确认风格；未确认留空。

## 10. A1/A2 实施边界

- 四页及右上角策略选择器共用不可变的导入记录；旧路径保留，旧工具集中到设置。没有自动迁移账户。
