# 经验策略与标准模板 SPEC

版本：0.1，2026-10-25。原始状态为离线内核；本日已按发布 SPEC 接入实际检验与纸面链路，范围和证据见 [实施验收记录](RULE_IMPLEMENTATION_ACCEPTANCE_20261025.md)，不表示全部发布验收通过。

发布范围与后续次序补充见 [1.0 发布与用户适配 SPEC](RELEASE_AND_ADAPTATION_SPEC.md)。本文件的 LightGBM 自动经验特征训练、逐条经济贡献分析与影子账户对比不自动成为 1.0 前提；先完成真实模板出分、检验与部署。已有内核仍须通过缺失传播、量纲、中文语义和资源边界验收，不能以文件已存在视作发布通过。

## 1. 要解决的门槛

多年炒股用户带着选股、买卖和持仓经验进入平台，却只能选择平台模型或上传完整外部预测。系统没有入口记录“放量突破”“跌破 20 日线卖出”等想法，也没有一套原策略供对照。

因此用户第一步不是训练模型，而是先得到一份**自己的经验策略 v1**：可解释、能运行、可被逐条修改。小白直接选择标准模板；专业用户把模板改成自己的规则卡；两者都保留同一个参考版本。

## 2. 产品链路

```text
选择标准模板 / 从空白开始
        ↓
规则向导：选股范围 → 看好的特征 → 必须满足的条件 → 买卖纪律
        ↓
规则卡 + 打分卡（原策略 v1）
        ↓
模型检验：规则本身的历史结果、成本、缺失和尝试次数
        ↓
可选：用规则卡特征训练 LightGBM，和原策略并排比较
        ↓
选择更适合自己的版本 → 纸面账户 → 前向记录
```

用户的“盘感”不允许事后回填历史。平台提供从今天开始的每日看好名单记录；这些记录只能进入前向观察，不能伪造成历史训练标签。

## 3. 规则卡

每张规则卡包含：编号、用户可读名称、受限表达式、权重、是否为必须满足。`required` 规则生成候选股票资格；其他规则生成分数。所有规则只读取决策时刻及之前的本地日线面板。

首版表达式白名单：`open`、`high`、`low`、`close`、`amount`、`volume`、`adj_factor`；`mean(x,n)`、`std(x,n)`、`ret(x,n)`、`rank(x)`、`above(x,y)`、`below(x,y)`、`cross_up(x,y)`、`cross_down(x,y)`；加减乘除和括号。禁止 Python 调用、属性访问、导入、条件表达式和任意函数。

规则运行在日期 × 股票宽表上，不跨股票滚动。窗口不足返回缺失，不填零；缺字段直接阻止检验并告诉用户需要哪种数据。除权因子和交易日历仍按现有数据契约处理。

打分卡：

```text
score(date, stock) = Σ rule.weight × rule_value(date, stock)
eligible = ∧ required_rule(rule_value > 0)
```

打分卡只定义排序输入，不自动宣称收益预测。等权是默认，手动权重在高级设置中显示；权重变更生成新版本。

## 4. 首批标准模板

模板只使用日线 OHLC、成交额和可选成交量；不依赖财务数据或公告日对齐。每个模板先作为“原策略”跑检验，结果不与平台 LightGBM 混为一谈。

| 模板 | 规则卡 | 需要的数据 | 适合的问题 |
| --- | --- | --- | --- |
| 趋势跟随 | 收盘在 20 日线之上；20 日线在 60 日线之上；60 日收益 | 日线 OHLC | 强势是否值得继续持有 |
| 短期反转 | 5 日回撤越大分越高；仍在 20 日线之上 | 日线收盘 | 下跌后的反弹是否可执行 |
| 低波稳健 | 20 日波动越低分越高；成交额高于均值 | 日线收盘、成交额 | 低波和流动性是否更适合账户 |
| 量价配合 | 5 日上涨；成交额高于 20 日均值 | 日线收盘、成交额 | 放量上涨是否值得跟随 |

模板来源写成“工程基线”，不写成经典方法有效证明。每个模板页显示使用字段、窗口、规则卡和局限；不显示“推荐收益”。

平台默认 LightGBM 仍是第五个候选，承担“复杂模型能否超过简单经验卡”的挑战者角色。若简单卡更稳，产品仍然成功：用户知道复杂模型没有带来可验证增量。

## 5. 有经验用户如何打造自己的模型

第一版只要求回答四个问题：

1. 我做哪些股票：全市场、自己的股票池，或明确排除 ST/停牌等。
2. 我看重什么：从模板规则卡选择、删除或添加；每条标为“必须满足”或“加分项”。
3. 我如何排序：等权或手动权重；不把分数单位伪装成收益率。
4. 我怎么交易：持仓数、保留带、总仓位、最低现金、调仓周期，以及周期外是否授权。

自然语言备注只作为版本说明，不能直接执行。用户确认后的规则卡才进入回放。遇到“题材要启动”这类无法历史量化的经验，选择“从今天开始记录名单”；平台保存生成时刻、数据截止和首次接收时间，未来只用前向记录评价。

模型升级采用冠军/挑战者：经验卡 v1 固定不变；LightGBM 可以把规则卡值作为输入特征，与基础量价特征一起训练；两者用同一账户、同一费用、同一检验期比较。不能只因为模型曲线更好就覆盖原策略，用户主动选择后才建立新版本。

## 6. 防止经验被调成回测曲线

- 每次规则卡改动生成新尝试并计数；最终留出期冻结，不允许反复查看后调整。
- 规则表达式、数据字段、窗口、权重、模型版本和数据快照都进入哈希。
- 结果分为排序表现、账户经济结果和前向记录；“规则可运行”不等于“收益有优势”。
- 所有缺失、受阻、成本和实际仓位保留；不把不能成交的理想交易当作结果。
- 首版不提供自动搜索规则组合，避免把向导变成曲线拟合器。

## 7. 当前工程范围

已实现：`src/qwb/experience_rules.py` 的安全表达式引擎、规则卡和打分卡；`src/qwb/experience_rule_templates.py` 的四个模板；安全性、缺字段、滚动因果和规则解释测试。

原接入次序如下；实际进度以实施验收记录为准，其中自动经验特征训练、经济贡献分析和影子账户仍按发布 SPEC 留待后续：

1. 在模型阶段加入“经验策略”入口，先选择模板或空白规则卡。
2. 将打分卡输出接入现有 `signal_matrix` 契约，生成历史预测并走同一模型检验。
3. 在规则阶段显示经验卡与 LightGBM 的并排对照。
4. 加入止损等交易纪律前，先为规则定义时点、受阻行为和公平对照；没有这些契约不开放。

当前不能说平台已经支持任意自然语言转策略，也不能说四个模板具有收益优势。它们解决的是“有一个可运行、可修改、可对照的原策略”这一入口问题。
