# v0.2 规则闭环实施验收

日期：2026-10-25。依据 [发布与用户适配 SPEC](RELEASE_AND_ADAPTATION_SPEC.md) v0.2；本记录跟踪实施，不增加发布范围。

## 已接入

| 交付 | 实现 |
| --- | --- |
| 同一策略流程 | 首页模板、训练、已有模型共用模型 → 规则 → 部署 → 运行；草稿恢复，数据准备后返回原策略 |
| 四个日线模板 | 趋势、反转、低波、量价；`rule_signals` 实际计算历史与持续分数，无 LightGBM 替代执行 |
| 无代码编辑 | 有界字段、条件、窗口、权重、必须满足；修改和切换保留草稿，切换模板先确认差异 |
| 规则与账户 | 规则输出接原账户账本、三组历史对照、费用和成交约束；没有符合条件的股票可保留现金，未知输入受阻 |
| 缺失与版本 | 有效性掩码、窗口要求、覆盖、旧版配对与候选变化；冻结规则、配置、实现哈希，修改保留旧版旧账户 |
| 尝试记录 | 规则计算的成功与失败均记录；同一策略修订沿用系列次数；历史开发比较不冒充独立留出 |
| 本地 AI 协作 | `rule_card_v1`、只读 `temperq rule validate`、中文预览与显式确认、来源字段、JSON / Markdown 成绩卡、根目录 `AGENTS.md` |
| 结果与隐私 | 证据不足仍可纸面观察；逐条经济贡献未分析；成绩卡按白名单导出，不包含持仓、账户初值、token 或本机路径 |

代码入口：`src/qwb/rule_cards.py`、`rule_signals.py`、`rule_ui.py`、`rule_cli.py`、`scorecard_export.py`；安全表达式复用 `experience_rules.py`，账户运行复用 `strategy_workspace.py` 和原统一账本。

规则卡只表达已支持的选股条件和打分；止损、自然语言执行、经验特征自动训练、MCP 和内置 agent 均未开放。不提供专有因子库，未启动 Kronos 微调或修正量学习。

## 软件验收

软件验收只使用隔离的合成数据，不接触用户账户，不产生真实投资证据。

- `tests/test_rule_cards.py`：往返、来源、非法格式与资源限制、因果计算、只读 CLI。
- `tests/test_rule_strategy.py`：四模板真实产物；历史与持续计算一致；追加行情、重复记账幂等；导入未确认不生效；新旧版本与次数；空候选和缺输入分开。
- `scripts/qa_rules.mjs`：真实浏览器从首页经过编辑、导入确认、模型检验、账户检验、历史演示、看板和修订；检查桌面/手机溢出及页面错误，截图在忽略的 `artifacts/rule-browser-qa/`。
- 原训练、外部信号、政策、行情、CSV、看板和仓库边界采用对应现有测试回归。

## 发布前仍需完成

1. 至少两名未参与开发的用户独立走完起步、修改、检验、部署和恢复，记录卡点与用时；30 秒和五分钟目标尚未做真人验证。
2. 无开发环境的另一台 Windows 机器实际启动便携包，并验证下载失败后的恢复；同机隔离/迁移测试不能替代该项。
3. 如开展连续两周观察，必须按真实日历积累并记录真实开始日；历史演示和合成追加测试不能补齐。

既有账户的记录和身份保留。执行实现变化时旧账户会受阻，需显式建立新版本；本轮没有改写历史哈希或让旧账户静默换实现。软件验证通过不代表上述人工验收完成，也不代表已具备收益优势。
