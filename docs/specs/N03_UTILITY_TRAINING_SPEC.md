## 目标与依据

实现“原始时点数值观测 + 已执行账户状态 → 编码器/收益头 → 受约束持仓 → 连续净效用训练”，并以独立 Bench 评价。因子不是必经输入；专业用户可替换 encoder、loss、allocator 或外部训练循环，只要声明能力并满足数据/输出契约。

复用 [调研](../research/E2E_RESEARCH_REVIEW_20261022.md) 的 P01/P03 决策训练思路、P04 的 CVXPYlayers 和 Qlib 的模型组织模式。首版不增加 RL、预训练大模型、公告多模态或自写优化器；这些工作按主 SPEC 另行验收。论文指标与上游榜单不作为本项目收益证据。

N02 已接通共同组合层，但未证明训练代理足够准确。最终合成样例实际费用 250.08 元、按成交计算代理费用 68.37 元，意图代理几乎为零；两模型成交路径相同。N03 必须先解释这条路径，不能直接训练一个利用代理误差的模型。

接续证据：同成交差额已分解为最低佣金溢价减代理额外冲击，整数完整模式可复现原账户；分数份额的最低佣金仍有明显偏差。已有账户反馈和 CVXPYlayers 参数到多日效用的受控梯度检查；生产映射、GRU 训练循环、状态截断/恢复、配置/worker 和闭环模型比较尚未验收。下列门槛继续作为完整 N03 的要求，不因基础模块落地而关闭。

## 交付边界与接口

| 模块 | 交付 | 边界 |
| --- | --- | --- |
| `portfolio/` | 版本化连续账户推进、动作映射、风险/成本配方复用、差异分解 | 精确原始股数账本继续独立；不共享两边的状态推进实现来伪造一致 |

冻结风险/成本配方起步；风险模型和成本模型不与编码器同时学习。当前风险只覆盖日内区间，若训练风险惩罚改为完整净权益区间，须另版本化配方并包含旧持仓隔夜，不能改名沿用日内矩阵。

## G0：训练前的会计与动作门槛

先用固定动作、相同初始状态与价格路径比较连续环境和独立精确账户，逐项打开约束；这一步不训练或选择模型。

| 场景 | 必须核对的量 |
| --- | --- |
| 无费用、可分割份额、完全成交 | 隔夜旧持仓、开盘买卖、日内估值、现金与净权益手算；共同动作下会计恒等 |
| 权重保持与隔夜漂移 | 目标等于决策权重仍可能在开盘交易；不可把 `w=h` 等同于持有股数不变 |
| 比例费用与最低佣金 | 意图代理、成交代理、实际费用分别报告；费用只扣一次，资金不足限制买入 |
| 整数手、交收、停牌和限价 | 数量、可售批次、未成交原因、动作到成交映射与净权益差异 |
| 分红、应收、拆股和终止 | N01 的时序和单位不变，应收不能花费，支付不重复计收益 |
| 失败或缺失历史 | 结构化失败续持；仍计漂移风险、费用和覆盖，不能删掉失败日期 |

增加真正“保持股数”的固定账户对照用于解释再平衡费用；这是实验控制，不把它自动映射成现有目标权重语义。若未来需要不下单/数量型策略输出，另立版本契约，不能改变旧 `target_weights` 的开盘意向含义。

成本差分至少保存 `actual-intended = (filled-intended)+(actual-filled)`，同时报告人民币、占权益 bp、成交代理相对误差（分母为零时为空）和费用分项。未做逐项测试前不得把全部差异归因于最低佣金。分开报告价格漂移、成交时间和分母差异，收盘权重误差不能单独作为交易误差。

精确会计夹具沿用 ADR 001 门槛及手算金额。连续松弛与真实约束的容差单独在实验开始前冻结，包括每日/累计权益差、费用绝对与相对差、换手、未成交、状态反馈差及分母规则。只按权益判定费用差不够；阈值变更形成新探索计划，旧失败样例保留。超限路径可用于诊断，不得进入主要经济比较。

G0 通过要求：精确语义无未解释差异；所有近似都有单独开关、来源和差异报告；N02 的零意图换手但非零成交案例可重算。通过不要求人为降低每种真实约束的差异，而要求其边界与适用资格明确。

## G1：可微动作和梯度语义

组合层输入为小数预期收益、因果风险平方根、当前环境已执行后的漂移持仓、可用现金/应收及已知限制。风险和流动性配方只读决策可见修订，使用 N02 的身份与失败语义；未来执行数据只在环境推进时揭示。

训练必须显式声明：CVXPYlayers 的原始动作、训练环境动作、生产目标映射以及梯度停止位置。现有 HiGHS L1 投影不支持反传；首版可保留训练原始动作与生产映射两条路径，但必须分别归档并验证差异。不得静默使用 straight-through、裁剪再归一化或以 detach 后的账户声称完成路径梯度；需要这些近似时另立 ADR 并做消融。

首个训练候选按 ADR 007 使用显式、有界的 Tensor 生产映射；梯度经过实际映射，训练和精确账户共用映射版本。它仍包含箱体/预算修正，必须满足 ADR 的单项修正上限、失败和审计要求；不得以“端到端”省略这部分。工作区中的候选实现还不是通过验收的训练路径。

先在光滑小问题检查动作、现金、费用、净权益、最终效用对模型参数的有限差分/方向导数；沿用主 SPEC 数值门槛和步长扫描。投影边界、零交易点、活跃集变化单独报告，不伪称梯度唯一。求解失败、非有限梯度、权益非正必须中止并保留失败，不回退为零仓或等权。

交收、整数和限价的梯度处理须逐项声明；不能只在前向实现约束而省略对效用优化的影响说明。只有覆盖实际训练计算图的检查通过后才开放效用训练。

## G2：episode、效用和模型选择

1. 时间线固定为收盘后观察与决策、次日开盘执行、次日收盘净权益；旧持仓隔夜、事件、费用按参考账户顺序处理。未来价格作为环境反馈，不能进入观察、预测、风险估计或提前可交易筛选。
2. 初始账户、burn-in、片段边界、强制清仓与费用、再平衡频率、BPTT 长度和 detach 时点全部配置化并入账。不同 episode 可并行，同一 episode 不打乱日期；不得拼接独立片段制造换手路径。
3. 首个效用为 `-mean(log(E[t+1]/E[t])) + lambda_var * Var(net_returns)`。净收益已经扣费后不再重复扣费；明确方差定义、风险系数和单位。Sharpe/CVaR 等后续目标需冻结消融，不事后选最好指标。
4. B1 预测 checkpoint 在历史训练/验证段确定；B2 从同一编码器、初始化、容量和组合参数开始微调。验证无梯度、账户独立，内层选择后冻结外层预测，禁止测试收益选择 epoch、成本或初始账户。
5. checkpoint 至少保存模型、优化器、RNG、配方和数据身份；若不同时保存账户/episode 游标与 BPTT 状态，则恢复能力标为整折重跑。取消、失败、未运行 trial 均持久化，不覆盖上一成功版本。

训练代理账户与精确账户分别读取各自过去状态，额外比较闭环反馈路径；不能只在固定动作下吻合就声称策略实际行为吻合。若专业用户选择另一训练环境，须保留相同的能力与差异声明。

## G3：验收与后续研究

| 检查 | 通过条件 |
| --- | --- |
| 因果性 | 扰动未来价格/流动性/事件不改变此前观察、动作、配方和约束；更改未来成交可改变后续账户反馈 |
| 账户及梯度 | G0/G1 全部有配置、手算/差分证据及失败边界；无未声明修复 |
| 运行闭环 | 新配置检查、CLI/worker、取消/失败、归档与 checkpoint 重放通过；原生预测/分数/目标路径无回归 |
| 独立评价 | 生产目标可交独立 Bench 重算，代理和精确状态/费用/权益及反馈差异完整，超限资格明确 |
| 环境 | 至少本机 CPU lock 可复现；Linux/GPU 只有实测后才列为已支持 |

N03 软件验收不要求 B2 胜出。完成后才执行 N04：预声明至少三种子、训练/搜索预算、B0/B1/B2 与 2×2 消融、成本与约束压力、日期块配对推断。保留全现金不交易、冻结初始持仓等控制；不得只报告盈利子集。

真实市场经济确认还需要数据授权、历史资产池/时点证据、退市与公司行为覆盖、容量敏感性和方案冻结后的未见时段。重复查看的历史数据仍是开发数据。外部复现、服务器部署和对外发布门槛继续按主 SPEC 的 N05，不以源码 ZIP 或 CI 文件代替完成。

## C1：首个可执行版本的配置契约

新运行类型定名 `e2e_utility_v1`，已由现有 `runconfig.resolve`、`pipeline` 和 train worker 统一处理。下表为字段契约；可执行配置由 `scripts/run_utility_pipeline_demo.py --config-only` 连同协议生成，命令见训练说明。未知键、错误任务和不支持能力必须在运行前拒绝，不能降级为 `e2e_prediction_v1`。

| 配置段 | 必须解析并归档的内容 |
| --- | --- |
| 运行 | `spec_version/name/task/output`；任务固定 `cn_alloc_daily_v1`，原有预测任务保持语义 |
| 数据与观察 | `data.source=pit_bundle/dir`、内容身份；`observations.lookback/min_history`、配方与修订规则；相对路径相对配置文件解析 |
| 初始化 | `initialization.run/fold`，通过归档验证器核验源 GRU 运行，再从该折各 seed 的清单定位 checkpoint；记录配置/权重哈希，不接受仅凭任意权重路径建立来源 |
| 模型 | `model.name=decision_gru_v1/freeze_encoder`；通道和隐藏维度由源 checkpoint 决定；首版 CPU float64，记录从预测模型 float32 转换的事实 |
| 时间折 | `folds` 为显式列表；每折含唯一 ID、train/validation/test 协议、`fit_cutoff/selection_cutoff`；首个 smoke 可只一折，正式研究仍按 N04 多滚动折 |
| 组合层 | 字段嵌套在 `portfolio.risk/cost/optimizer/production`；风险/成本/优化器展开默认并拒绝未知键。生产段显式包含 `policy/buffer/dust_threshold`，修正容差在 `portfolio.optimizer.tolerance`；旧策略要求阈值为 null，新策略按 ADR 008；额外约束未支持则拒绝 |
| 执行近似 | `continuous.integer_lots/settlement/market_restrictions/minimum_commission/fee_model` 全展开；首个可微主配置不取整，最低费等开关如实保留；非法组合拒绝 |
| 效用 | `utility.variance_penalty`，固定总体方差 ddof=0；已经扣费的净权益不再扣同笔费用 |
| 训练 | `train.seeds/epochs/patience/learning_rate/cpu_threads/max_seconds/max_episode_steps/detach_every`；正整数/有限数校验；`detach_every=null` 表示不截断；每 epoch 一条顺序 episode、一次优化器更新 |
| 差异门槛 | `acceptance` 必填：权益绝对元与相对初始权益 bp、费用元与相对差、换手和状态容差；记录分母为零的规则、适用模式及超限资格，禁止隐藏默认放行 |
| 可选验证审查 | 仅显式 `validation_audit.schema_version=utility_validation_audit_v1` 启用；省略保留旧配置身份语义；每个完整 epoch 的独立候选和内层精确排序按 ADR 010 保存，不增加选模模式 |

协议含完整初始现金/持仓、交收/应收、决策及成交日历、费用和市场规则。train/validation/test 使用独立且预先声明的初始状态；不能把片段收益拼成一条账户净值。首版不支持隐式承接状态、隐式 burn-in 或末日强平；需要这些语义时须先增加明确配置及测试。观察窗口可合法读取片段开始日前的因果历史。

首个优化器固定 Adam；其完整配置、版本和实际参数组写入 resolved config，调度器暂不支持。seed 集合不可为空或重复，checkpoint 缺 seed 时拒绝；单 seed smoke 明确标为初步。超时针对每个 trial 的完整训练/验证预算；取消和超时在每个决策及 epoch 边界检查，不能只在开始检查。

当前 `acceptance` 必须逐项显式声明，所有数值有限且非负，无隐式放行默认值：

  state_comparison_version: lifecycle_schedule_v1
  max_daily_entitlement_quantity_gap: 0.00000001
  max_daily_entitlement_amount_gap_cny: 0.00000001
  max_daily_entitlement_mismatch_count: 0
  max_daily_processed_event_mismatch_count: 0
  max_daily_equity_gap_cny: 10.0
  max_daily_equity_gap_bp: 0.1
  max_total_cost_gap_cny: 20.0
  max_total_cost_relative_gap: 0.1
  max_daily_cash_gap_cny: 10.0
  max_daily_receivable_gap_cny: 0.00000001
  max_quantity_gap: 0.00000001
  max_locked_quantity_gap: 0.00000001
  max_daily_turnover_gap: 0.001
  max_action_weight_gap: 0.000001
  max_unfilled_quantity_gap: 0.00000001

以上仅是合成诊断的工程门槛，不是金融有效性建议。权益 bp 分母固定为精确账户初始权益；费用相对差分母为精确费用。锁定数量按资产及 UTC 到期时刻匹配，未成交数量按资产及买卖方向匹配，不能先汇总相抵。新 `lifecycle_schedule_v1` 模式在决策前及收盘后比较逐事件权利数量、金额、归属/阶段/支付时间和已处理事件集合，见 ADR 009。旧配置不声明版本或声明 `aggregate_v1` 时保留总额模式及原门槛集合，不补新字段，不重解释旧结果。报告必须显示实际比较版本，不能以总额相等宣布完整生命周期状态等价。

## C2：时点、初始化与选择隔离

每个折满足以下不变量，比较使用带时区的实际时刻，而非日期字符串：

1. 源预测 checkpoint 的标签成熟与拟合/选择身份可验证；首个版本保守要求其选择截止不晚于效用 train 的第一次决策，避免把晚于该时点训练的初始化用于历史动作路径。
2. train 的全部执行反馈可用时刻不晚于 `fit_cutoff`，且 `fit_cutoff` 不晚于 validation 首次决策；validation 的全部选择反馈不晚于 `selection_cutoff`，且后者不晚于 test 首次决策。决策、次日成交和反馈日期跨界时按反馈时刻检查。
3. 数据内容、观察配方、资产身份及源预测任务与 `cn_alloc_daily_v1` 的收益区间明确兼容。当前原生预测任务为下一开盘至收盘；旧五日标签不能静默接入。
4. test 收益、成交和评分不得进入早停、阈值选择、成本拟合或初始账户选择。独立 Bench 读取未来价格做执行可以，策略上下文不能读取。
5. 首个 GRU 每次在有限窗口内重新编码，不跨决策保存隐藏状态；跨日可微反馈来自账户。后续 stateful encoder 必须版本化其 reset、保存和截断规则。

每 epoch 从同一 train 初始账户重建，顺序推进、计算净效用、反传及更新；之后以 `eval/no_grad` 从独立 validation 初始账户评价更新后的权重。选择最小 validation loss；严格改善才更新最佳 epoch，平分保留较早者。epoch 0 的源初始化作为独立控制记录，不参与首版 epoch 选择。若全部 epoch 失败，不产生可发布模型。

启用 ADR 010 时，每个完整 epoch 另存同轮候选、优化器/RNG，并在内层 validation 重算精确/连续三路径及风险成本指标。所有审查耗时计入原训练预算，候选副本不改原训练参数/RNG。完整/部分审查与训练成功、代理资格分别记录；诊断排序不修改上述选择规则。外层 test 不传入审查器，未来若切换精确验证选模须另版本化。

冻结 encoder 必须体现为相应参数 `requires_grad=False` 和从优化器组移除；记录参数名、数量及更新范数。无可训练参数、非有限梯度和参数更新失败为错误；全现金导致的有限零梯度则是合法负结果，记录原因，不改成本或强迫交易。

## C3：截断、内存和 checkpoint

`detach_every=K` 表示在第 K、2K… 个决策之前截断账户状态路径；截断不重置现金、持仓、交收或应收数值。跨截断的当日收益必须由该日实际使用的截断后期初权益与期末权益计算：`r_t=E_after_t/E_before_t-1`。不能把 detach 后的分子与保存的未 detach 前日权益配对，否则会留下错误的跨段分母梯度。

无截断时逐日收益应与连续净值相邻比值一致；有截断时前向数值保持一致，梯度按每段固定期初状态定义。测试必须隔离仅由前段动作带来的路径，证明截断后不再从后段损失反传至该动作，同时保留后段策略参数本身的梯度。净值序列用于审计；用于训练的收益图必须遵守上述边界。

状态 detach 不自动释放已经保存的整段 loss/audits 图，也不保证内存随 K 有界。首版允许每 epoch 汇总后一次反传，但必须有 `max_episode_steps` 硬上限和实测峰值内存，超过预算拒绝。分段反传、在线方差聚合或梯度检查点另行实现和验收，不能仅凭参数名宣称内存优化。

最佳模型的权重、优化器状态、CPU RNG、epoch 及选择记录必须来自同一时刻；不能混用最佳权重与最后一轮优化器。保存 `weights.pt/training_state.pt/model.json`，逐项哈希、安全加载、有限性/维度校验，并核对重载预测、动作和账户路径。训练期间失败、取消或超时保留最近完整记录，不用半写入文件替换已选模型。

首版能力声明为 `whole_fold_only_no_mid_episode_resume`：保存训练状态用于审计，失败后按同配置从源初始化重跑整折；不承诺断点续训。若要恢复中途 epoch/episode，必须同时保存账户、游标、RNG、优化器、最佳选择状态和 BPTT 语义并有一致性测试。

### C3-R：独立进程资源证据

资源工具与主训练配置分开版本化，操作入口见 [资源实测](../UTILITY_RESOURCE_AUDIT.md)。矩阵在预训练前冻结为资产数 24/64/128 × train 步数 3/12 × 不截断/每 2 步截断 × 两次重复，共 24 个效用 fit；一轮、seed 0、CPU 单线程、fit 120 秒及子进程墙钟 180 秒。三个资产池各通过真实共享预测 pipeline 预训练一轮，核验源归档、数据与选择截止，不能手写预训练身份或改收益头制造交易。

每个预训练及效用 fit 使用新的顺序子进程。保存父进程墙钟、子任务时间、fit 时间、fit 前高水位和最终进程峰值 RSS；这些量不混用，也不将两个高水位之差称为训练内存。超时回收整棵自有进程树；Windows 虚拟环境启动器的下层解释器必须有实际终止用例。

覆盖率分母固定为全部声明格。预训练失败则其依赖格全部 not_run；fit 失败、超时、缺最终 RSS 均保留，不填零或删除。资源范围只在成功条件下汇总 min/median/max，没有成功时为 null。重复参数按实际重载 Tensor 比较；计时/RSS 不要求重复相同。失败历史与原生上下文保留，不自动增加预算后覆盖旧结果。

验收包括冻结 intent/plan、源 checkpoint 与协议输入溯源、全部场景台账、保存重载、汇总重算及重哈希后删场景/改汇总拒绝。正式资源测量期间不并行训练、测试、安装或其他基准。小规模 Windows 测量不授予未测规模、并发、Linux/GPU、通用容量或随 K 有界内存的支持声明；工具校验也不等于独立重跑或硬件计时认证。

## C4：独立评价与必备产物

同一已选 checkpoint 至少保留三条明确标识的评价：

| 路径 | 用途 |
| --- | --- |
| 连续账户闭环 | 每日用自身实际状态生成动作，评价训练近似；不是投资绩效基准 |
| 精确账户闭环 | 同一生产 policy 每日读取精确账户自身状态，保存目标，再交独立回放器重算并逐日核对 |
| 连续动作固定回放 | 冻结连续账户产生的数值动作，在精确环境执行以分解执行近似；重新绑定精确状态身份并明确为诊断，不能伪造原提交或冒充精确闭环 |

比较逐日现金、股数、可售/交收、应收、实际成交、费用、权益、换手、违约和下一动作。状态分叉后动作不同是反馈效应，应保留原因；禁止强制复用昨日目标来制造相同路径。费用差同时报元、bp 和相对差；费用分母为零时相对差为 null，并使用预声明绝对门槛。

成本明细使用显式 `same_fill_cost_decomposition_v2` 时，逐笔保存同实际成交代理与实际成本的桥接，以及最低佣金溢价、卖出税率差、滑点差和代理冲击差；意图代理到成交代理的桥接在逐日层记录。逐笔、逐日及总计均保留 CNY 与固定期初权益 bp；逐笔另报本笔成交额 bp。权益分母固定为第一条账户审计的 `equity_before`，不得每日更换。相对成本差以同成交代理成本为分母；零成交额或零代理成本分别输出 null，保留绝对差。逐笔和汇总分项须满足恒等式；不得把相对比例再次换算为金额 bp。旧 API 默认 v1 不变，诊断计划必须声明实际使用的版本。

归档复用现有生命周期与身份验证器，至少含 `task.yaml/config.resolved.yaml/folds.json/trials.json/metrics.json/report.md`、输入/代码/环境清单及 checksum。`predictions.parquet` 保存真实的收益头预测与既有运行身份字段，不能将权重当分数；目标、求解/映射记录、连续账户和精确账户逐日表另存。验证器须覆盖这些新产物并能发现篡改、缺决策、错误 seed/fold 或过期状态。

trial 状态至少区分 queued/running/succeeded/failed/cancelled；超时记录独立 reason。某个 seed/fold 失败时可保留其他成功产物，但全体状态不得标为成功，主要比较资格默认失败，不能仅平均成功子集。未实现的恢复和不支持的平台在报告中明确列出。

进入基线验证及训练循环后的失败，在 trial 追加 `failure_context.schema_version: utility_training_failure_v1`，至少记录 epoch（基线为 0）、phase、completed_epochs、原异常类型及原因。phase 区分基线验证、训练 episode、反传、梯度检查、参数更新、内层验证、候选审查与最终化；此前的配置/数据/初始化预检仍按原错误台账处理，不保证有该上下文。已完成轮次和候选保留；未开始的折/seed 标记 not_run；训练失败不生成已选成功模型。该字段为增量诊断，不改变旧成功归档或异常类型。

策略动作生成失败附 `decision_policy_error_v1`，记录决策身份、时刻、资产顺序、数据快照与失败阶段；已成功计算的历史长度、预测表示、实际漂移权重、锁定上下界、预算/应收、换手、生产版本、配方身份及求解审计按阶段保留。生产映射拒绝时保存原始分配与原始求解审计；非有限预测以可序列化文本保留。目标构造/验证失败使用同一诊断版本，另标 target_validation，并保留决策身份、时刻和成功动作审计。只有进入相应阶段的字段才要求存在。

故障注入必须经过实际 GRU/求解/生产映射/worker，至少覆盖缺历史、求解后端失败、超量生产修正及非有限梯度，分别在首轮和已完成一轮后触发。原生训练默认中止；上述训练诊断不是目标提交的 `decision_failure_v1`。外层精确诊断的可选失败续持按 C4-F 和 ADR 011 单独声明版本、覆盖率、资格与回放语义。

B1/B2 共用初始化、dtype、组合层、生产映射、协议与执行条件。源 B1 为 float32 时，先增加同权重转 float64 的未微调 B1 控制，量化转换影响；不能把精度和生产映射改变造成的差异全部记成效用训练增益。预测微调与效用微调的 2×2 消融再统一参数容量及预算。

### C4-F：原生精确评价失败续持

按 [ADR 011](ADR_011_OUTER_EVALUATION_FAILURES.md) 实施独立评价版本 `utility_outer_evaluation_v1` 和 `explicit_failure_hold_v1`，仅显式配置时生效；操作见 [外层评价](../OUTER_EVALUATION.md)。现行训练、连续 validation 和 ADR 010 候选审查仍按原错误中止。实现存在不等于通过验收，实际证据以阶段矩阵 G0-06 为准。

`max_seconds` 为每个模型外层诊断的合作式预算，在决策和阶段边界检查，不能中断底层求解，不宣称进程墙钟硬限额。原始行情修订及事件使用显式 `evaluation_asof/feedback_cutoff`，不能把收盘时间等同于行情可用时间。计划冻结实际模型参数及标签缩放身份，即使所有精确日期均失败也要核验。

| 事项 | 实施与验收要求 |
| --- | --- |
| 可续持的失败 | 仅显式启用的原生精确诊断评价中，有效决策上下文内可分类的缺历史、收益预测、求解或生产拒绝；记录原异常及阶段，不能宽泛捕获所有异常 |
| 必须中止 | 配置/协议/数据身份无效、过期状态、会计错误、非有限账户、取消及资源预算耗尽；保留失败，不转成逐日成功 |
| 失败日账户 | 输出绑定当日决策/状态的显式失败记录，不产生新再平衡订单；原股数按公司行为调整，照常推进交收、应收支付和估值；不能将漂移权重作为目标重平衡，不能复用过期目标 |
| 下一决策 | 从推进后的真实精确账户重新生成上下文，成功时恢复正常决策；保留连续多日失败和首次成功身份 |
| 覆盖与资格 | 保存全部声明日期，区分成功动作、合法不下单、失败续持与未运行；全部日期进入收益/风险，发生失败的 trial 默认无主要比较资格，不能只平均成功日期 |
| 三路径诊断 | 精确路径可保留续持结果；连续路径失败仍中止相应诊断。缺动作时动作差异为 null 并注明缺失，不填零；覆盖不完整的三路径比较不得标为 PASS |
| 独立回放 | 显式失败提交由现有独立目标 Bench 推进；逐日核对现金/股数/交收/应收/事件/费用/权益。回放使用归档失败记录，不依赖再次触发同一次后端故障 |

关闭用例至少覆盖首日失败、成功后失败、连续失败再恢复、非全现金与受限持仓、失败日公司行为/应收支付、合法不下单，以及取消/超时/无效身份不被吞掉。删除失败日期、重哈希篡改失败绑定或汇总、将失败改写为成功都必须被拒绝。需有共享 CLI/worker 的正式小型诊断及独立回放结果；用例和结论写回阶段矩阵 G0-06，再进行最终阶段签结。

归档完成状态与评价状态分开：worker succeeded 表示产物已生成，trial 另记 `training_state` 和 `evaluation_status`。失败评价为 `DIAGNOSTIC_WITH_FAILURES`；连续路径保存完整前缀、失败处及后续 not_run，完整连续收益和缺失差异为 null，比较为 INCOMPLETE。全体精确失败时辅助预测允许为空，不填零。依赖完整连续账户的固定模型归因/消融脚本须明确拒绝不完整诊断。

验证器重算成功动作与连续前缀，失败日期回放归档错误事实并重算上下文和独立账户。它不认证某次临时故障确曾发生，也无法识别实现者一致改写整套错误事实；该类证明需要外部运行证据。单文件篡改后重哈希须拒绝，不能因此宣称具备外部事实认证。
