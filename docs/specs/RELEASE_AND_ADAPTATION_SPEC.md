## 4. 共用流程：从一份具体策略开始

沿用“模型 → 规则 → 部署 → 运行”四阶段，不再增加主导航或另建一套训练产品。模型阶段的来源选择中提供经验策略，不让用户先到多个资源页准备齐全部材料。

| 用户 | 起点 | 默认操作 |
| --- | --- | --- |
| 没有经验的小白 | 一份完整日线模板，或现有入门模型 | 查看实际配置和结果，修改一项，进入规则检验 |
| 有经验、不会编程 | 最接近自己思路的模板 | 通过点选修改条件、窗口或权重，确认中文含义 |
| 专业玩家 | 已有信号、模型或训练数据 | 使用原有导入和训练入口，展开配置、查看与导出实际参数 |

默认不先发一份 15–20 题问卷；先展示模板，按用户修改逐步出现相关问题。自定义规则用受限的字段、操作符和数值控件，不要求写表达式；空白编辑属于次级入口。

页面只保留当前状态、必要输入和一个主动作；原理和术语集中帮助。高级区收起不丢修改，换模板前明确列出替换内容，重启后回到策略断点。未经确认的自然语言备注不参与计算。

## 5. 经验如何变成策略和后续训练素材

| 经验性质 | 例子 | 1.0 行为 | 后续训练用途 |
| --- | --- | --- | --- |
| 必须遵守的约束 | 单票上限、不买 ST | 约束组合和候选资格；缺字段不得猜测或静默跳过 | 不允许模型学着违反 |
| 可检验的投资假设 | 趋势向上、成交额扩大 | 生成有定义、有版本的特征值和打分卡 | 使用实际到期收益标签，学习假设的条件性价值 |
| 行为偏好 | 少换仓、不急着建满仓 | 用现有明确参数表达 | 用户纠正用于学习偏好，不能冒充收益标签 |
| 无法历史还原的判断 | 今天看好某个题材 | 现有外部信号入口可记录；缺少历史时点只做前向观察 | 仅使用当时真实记录，不接受事后补记当历史证据 |

四个模板是趋势、短期反转、低波、量价工程基线，不声明已验证收益优势。成交额和成交量分别命名；不以成交额规则冒充“成交量放大”。模板依赖哪些字段就检查哪些，不满足时说明缺项，不再加财务数据依赖。

发布前必须校准离线内核与规范：

- 比较、上穿和打分过程保留有效性掩码；窗口不足、缺值、无穷值不能变成零分或“不满足”。报告缺失与覆盖，禁止静默改变主要比较样本。
- 布尔条件可用 0/1 加分；连续收益与波动先采用固定、因果的无量纲转换再组合。转换、权重、并列排名处理和缺失政策进入版本，不直接把不同单位的数值相加。
- 窗口须为有界正整数；表达式长度、AST 深度、运算与面板资源有界。白名单之外拒绝执行，不接受任意代码或无界幂运算。
- 中文描述与语义一致：是必须满足还是加分项、均值是否包含当日、收盘后何时可执行都明确；例行计算不能读取未来。
- 每份模板冻结完整组成：候选池、排序规则、组合规则引用、节奏与成本；持续运行使用同一实现。仅保存 `rule_template` 名称或备注不算规则已执行。

止损、跌破均线卖出等不能因出现在问答里就视为已支持。只有定义触发时点、下一交易日执行、T+1/停牌/跌停受阻和持仓状态，并经历史及运行一致性验收后才开放；否则不上架该选项。止损意图不保证成交价或最大亏损。

### 5.1 AI 协作接口（1.0 只做格式与文档）

许多用户会让自己的 AI 工具（如 Claude Code、Codex 或桌面智能体）部署和操作开源项目。1.0 不内置 agent、不接任何模型 API，只把 AI 能安全参与的边界做成稳定接口：AI 产出规则卡文件，平台校验，用户确认后才生效。

| 交付 | 内容 | 约束 |
| --- | --- | --- |
| 规则卡格式 `rule_card_v1` | 规则卡可导出、导入为 JSON：字段、操作符、窗口与数值、用途（必须满足 / 加分项）、中文复述、格式版本 | 与页面点选编辑使用同一结构和同一受限表达式白名单；不存在只能由文件表达、页面无法显示的规则 |
| 校验命令 | `temperq rule validate <文件> --json`：非交互，返回是否合法、逐项错误原因、中文复述、所需字段 | 只读，不写策略、不触发检验、不计入尝试次数 |
| 导入与确认 | 工作台导入规则卡文件，显示中文复述与差异，用户点确认后生成新版本 | 未确认的导入不参与计算；导入不能修改锁定交易规则、费用口径或已有版本 |
| 来源字段 `origin` | `template` / `user` / `imported`；文件导入（包括 AI 写的）一律记为 `imported` | 检验报告列出每条规则的来源；所有来源的检验同样计入尝试次数 |
| 成绩卡导出 | 成绩卡可导出为 Markdown 与 JSON，用户可交给自己的 AI 解读 | 导出不含持仓明细、token 和数据文件路径；平台不内置结果解读 |
| `AGENTS.md` | 仓库根目录，简短说明：安装、启动、确认已装好、规则卡格式与校验命令位置 | 写明 AI 不得：改锁定交易规则、编造数据来源、回显或提交 token、替用户开启纸面账户或每日自动运行、删除记录 |

AI 协作边界：AI 只能产出规则卡文件和解释文字；不得直接写数据文件、修改交易规则或费用、删除记录、开启纸面账户或自动运行。每条 AI 产出的规则生效前，必须经过校验命令和用户在工作台的确认。由 AI 发起的检验与人工发起的检验同样入账，不另设豁免。

这一节不改变 §3 "不在 1.0"中关于自然语言生成可执行规则和 MCP 的排除：用户自己的 AI 写出规则卡文件，与平台内置自然语言生成是两回事；前者经同一校验与确认，后者仍不在 1.0。

### 6.1 公司行动：事件覆盖和运行链路必须贯通

2026-10-26 的训练对照中，63 次精确账户回放全部因持仓复权因子变化且缺少事件覆盖而停止；现有 `paper.py` 对同类情况也会停止记账。研究失败记录不是所有运行路径都已测试的证明，但已确认这项不能只作为研究局限留到发布后。

- 复用已有生命周期事件与统一账本能力，接通数据、历史检验、纸面日更、恢复与看板；不另写一套分红收益算法，不迁移或改写用户旧账户来通过验收。
- 首版明确支持普通现金分红、送转与拆并股。登记日权益、除权除息日、现金实际到账和新增股份可用时间分别记录；应收、现金、原始股数、可卖数量和费用按冻结协议对账。不得仅凭复权因子推算分红金额或股份事件。
- 事件具备来源、唯一标识、可用时间、修订与数据版本。未到可用时点的事件不能参与历史决策；修订不能静默改写旧账或旧成绩。
- 缺少持仓事件覆盖、事件冲突或遇到未支持的复杂事项时，保留安全暂停，显示缺项及补齐后的恢复入口。不得忽略因子变化、事后删除股票或按零事件继续。
- 隔离账户验收至少覆盖：登记日前持仓有权益、除权日新买无旧权益、现金分红应收转到账、送转数量与可卖状态、同日重试及重启幂等、缺事件暂停并补齐恢复、事件修订的显式处理。历史检验与日更走同一事件实现并能核对现金和权益。
- 合成契约测试通过后，还须在独立复制的数据与隔离纸面账户上完成一段含真实普通公司行动的连续运行验收；记录事件来源及覆盖，不用用户真实账户做开发测试。

## 8. 修正量学习：研究契约

基础策略可来自模板、用户规则、平台模型或外部信号。先固定基础策略与账户规则，再研究一个小模型是否能改善其中一类决策。减少模型自由度可能有益，但不预先声称样本需求必然更少或收益更容易显著。

### 8.1 首个任务

仅研究固定调仓时点的目标权重微调；不同时学习周期外触发、止损与选股池。学习器输出 `delta`，正则项使其倾向于零，单票及组合偏离预算在看结果前确定并版本化，不硬编码宣传“±5%适合所有账户”。

```text
基础目标 w_base + 候选修正 delta
          ↓ 同一授权与可行性处理（包括 delta=0 的基线）
最终目标 → 同一数量、成本和成交账本
```

`delta=0` 时必须逐期复现基础策略结果；约束投影、整手与最低佣金可能改变实际偏离，报告目标偏离和成交后偏离。用户纠正学习偏好；经济目标使用决策时不可知、之后真实到期的结果，不把接受建议当获利证据。

### 8.2 评价与启用

- 固定基础策略，与修正版做滚动样本外配对；训练、缩放、收缩与选参只用当时已到期数据。
- 同初值、费用、股票池、交易日历与成交约束；列净结果、换手、风险和实际仓位。明显改变仓位/换手时增加相应解释性对照，不把少承担风险自动称为 alpha。
- 偏好匹配和经济增量分别报告。否决率记录展示次数、明确反馈、修改与未反馈；未反馈不当接受，自选反馈不宣称因果改善。
- 启用是版本级选择：独立验证不足则不启用修正版；原策略继续。不能用交易后才知道的收益决定当天修正是否为零。
- “不确定时回到基线”只控制采用范围，不保证基线安全、不保证修正版永不亏损；部署先做纸面候选，用户主动确认后切换版本。

## 9. Kronos 微调：一次有限实验

这是实验计划，不是已完成测试或 1.0 功能。已有零样本产物用于复现参照，不再把相同配置包装成新发现。官方工程见 [Kronos](https://github.com/shiyu-coder/Kronos)。

### 9.1 开跑前锁定

登记权重/tokenizer/代码与许可、对应预训练截止证据、数据快照、证券成员口径、标签、输入处理、精确日期、种子、训练步数、混合权重规则、统计方法与预算。权重截止无法对应核实则保留污染风险，不发布“干净样本外优势”。

所有正式检验日期晚于已核实截止日；微调训练段、开发段、最终段按时间分开，五日标签跨界样本清除，并保证训练时标签已到期。2024–2025 和 2025H2 已见结果只作开发/历史参照；未来未揭示段必须先登记。没有可用未见数据时只交开发研究，不重新命名旧样本。

先做单批前向、反向及可保存恢复的资源试验。历史“约 1.1GB、57 秒/决策日”的记录只说明旧推理配置，不说明本机 RTX 5060 8GB 能完成微调；确认驱动、精度、实际峰值显存和耗时后再启动。8GB 内无法按预登记配置完成即停止，不因此采购硬件或扩大工程。

### 9.2 固定比较和实验预算

- 比较 LightGBM、原零样本 Kronos、微调 Kronos、LightGBM 加微调信号四组；每组同日同股票，覆盖与未出分单列。
- 仅一个微调配方，三个固定种子 `0/1/2`，种子覆盖训练及随机推理。回看仍为 120、sample_count=1；不同时搜索窗口、采样次数、模型大小和 tokenizer。固定排名混合公式，权重只从 `0.1/0.2/0.3` 中按三个种子的开发段平均配对增量选一次，并列取较小权重，冻结后用于最终段。
- 最多一个资源试验、一个三种子正式批次；正式批次合计 GPU 占用上限 12 小时。这是工程预算，不是已测耗时。运行前估计无法完成就停止；中断恢复仍计入预算，技术失败的重启也登记，不重置试验次数。
- 单独报告微调模型 IC、条件残差 IC、混合相对 LightGBM 的配对 IC 增量、种子变化及覆盖。残差为正只作诊断，主要判断依据是冻结混合是否实际带来增量。

### 9.3 Go / Stop

种子变化衡量训练稳定性，日期序列衡量市场样本不确定性；不将“超过种子波动”作为唯一统计门槛。LightGBM 使用冻结的同一集成产物，不为不同 Kronos 种子挑选不同参照。先计算每个种子每日配对 IC 差，再按日对三个种子取平均，得到主要检验序列；不能把三倍股票数或种子数当独立市场样本。

预登记该序列的连续块 bootstrap：块长 5 个决策日、2,000 次、bootstrap seed=0，报告 95% 百分位区间。样本不足以支持预登记统计协议时不作 Go 判定；若修改统计协议须在揭示最终段之前记录。

主要项为冻结混合相对 LightGBM 的日度配对 Rank IC 差；同时检查三个种子的方向与幅度。仅当未揭示段上均值为正、95% 区间下界高于零、至少两个种子增量为正且无时点/覆盖硬伤，才进入账户回放候选。多候选揭示须调整统计结论，不能只报最好的种子。

未通过、区间跨零、预算耗尽或没有独立数据，则记录停止/证据不足，不继续扫配置。通过仅表示可研究账户结果；再用相同初值、成本和执行检验净经济结果、资源代价及前向运行，之后才讨论可选上架。没有证据不能替换默认 LightGBM。
