# ADR 010：逐轮内层验证候选审查

日期：2026-10-23。状态：**本机 Windows CPU 合成软件范围已验收；完整 N03 与经济有效性未验收**。对应 [接续 SPEC R02](NEXT_ITERATION_SPEC.md) 与 [N03 G2](N03_UTILITY_TRAINING_SPEC.md)。

## 问题与决策

连续账户和精确成交的状态/成本存在偏差。仅保存连续验证最优 checkpoint 无法检查其余 epoch 的精确验证排序。新增可选配置段：

```yaml
validation_audit:
  schema_version: utility_validation_audit_v1
```

仅允许该字段与版本。省略时保持原配置和运行行为，不向旧 resolved config 补字段。该能力是诊断，不增加精确验证选模、代理门槛选模或 epoch 0 参选。此类选模变化须另立 ADR/配置版本。

## 行为与产物

每个完成训练更新及连续验证的 epoch，复制模型权重、同轮优化器、CPU RNG 与训练记录。审查器持有独立模型副本，在 `eval/no_grad` 下从已保存候选重载，使用唯一的内层 validation 协议与独立初始状态运行既有三路径评价。连续重算损失必须与原该轮验证损失一致。

审查器不接收 test 协议；验证成交/事件反馈不晚于 `selection_cutoff`。审查前后保留原训练权重、梯度、优化器和 RNG，不用诊断排序修改早停或选择。调用与持久化均计入 `train.max_seconds`，逐决策检查取消/超时。

`validation-candidates/fold-####-seed-N/` 保存运行前计划、所有预声明 epoch 尝试、每轮 checkpoint/训练状态、完整三路径账户、候选结果及排序摘要。候选模型的 fit schema 单独标识为候选，不代表已选模型；恢复能力仍为整折重跑。

连续和精确损失均按相同净对数增长及总体净收益方差定义，已扣费用不重复扣。分别报告费用、净收益、方差、换手和违约；代理资格只作诊断，不用于挑选候选。排序最小化损失，平分以较早 epoch 展示；两两反转和 Kendall tau-b 单独报告，单候选或某一路全平分时 tau 为 null 并记录原因。

诊断异常与失败保留；未运行的后续 epoch 标明早停或训练中断。部分候选失败时排名显式为不完整，不能仅将成功子集称为完整审查。训练本身可保留原选中模型；完整审查状态与训练成功、代理合格分别报告。取消/超时及身份变化继续中止原 trial。

## 验证与兼容

扩展归档验证须从全部已保存候选重算三路径、目标/账户、候选指标及排序，检查候选轮次与训练历史覆盖；修改结果并重哈希仍被拒绝。部分失败审查不能获得完整审查的 PASS 结论。

必测：已知反转、平分/单候选、候选缺失与失败、原选模与 RNG/同轮状态不受影响、外层 test 扰动不改变候选和已选参数、验证反馈越界拒绝、取消与预算、重哈希篡改。共享训练行为改动需要相关广泛回归；旧身份结果保持原解释，新增源码身份生成新运行。
