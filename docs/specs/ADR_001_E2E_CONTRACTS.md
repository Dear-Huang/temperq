# ADR 001：端到端研究接口与参考环境

日期：2026-10-22；更新：2026-10-23。状态：接口与本机 CPU 数值参考已验收，干净跨平台验收进行中。

## 决策

1. `qwb.portfolio.contracts` 提供不可变 `AccountState/Position/SettlementLot/PendingOrder/TargetWeights`。序列化严格检查字段；状态内容指纹绑定目标，旧分数入口拒绝目标持仓字段。
2. 目标权重必须有限且非负，原值保留，不做裁剪与归一化。SPEC 的 `1e-8` 负值容差不用于接受负持仓：浮点求解器边界误差需在生产方显式报告/重新生成，而不能在验证端隐藏修复。权重加总判断保留 `1e-6` 容差。
3. `qwb.portfolio.reference` 先提供独立原始股数、开盘 IOC 参考账户。目标按开盘实际净权益定量，先卖后买，按资产顺序确定资金分配；整数买入单位由每只资产显式提供。它不是当前 `weight_research_v1` 的替代品，也还不构成完整目标持仓 Bench。
4. IOC 未成交数量当次到期，原因保存在审计中；输入中若已有待执行订单则明确拒绝，不能暗中丢弃。此协议尚不支持跨日挂单或公司行为，全部结果固定为诊断。T+1 用显式未来交易日开盘结算时间，不能用自然日加一。
5. `qwb.observations.WindowBuilder` 要求原始数据带可用时间，按决策时可见的修订构建窗口；默认 60 个交易日 OHLCV/amount。价格取窗口最后已知 close 为参照，成交活动采用窗口内 log1p 中心化；这些变换无全样本拟合。掩码保留缺失资产/通道。
6. `folds.TimeFold/rolling_time_folds/time_fold_masks` 增加月/周显式时间折与标签可用时间。保持旧年度训练 API，尚未宣称旧训练器已自动使用通用折。
7. 首个数值后端仍是 CVXPYlayers 1.2.0 + SCS；PyTorch 先锁 2.11.0，与本机已有版本一致。通过 `requirements-e2e.lock` 单独固定 CPU 研究依赖；安装时显式使用 PyTorch CPU index。主训练环境不自动加装这些依赖。

## 验收口径

`qwb e2e check --output <新目录>` 实际运行状态、账户与数值梯度检查，任何缺失依赖/失败都返回非零。报告保存代码与环境身份、手算账户、参考求解残差和有限差分步长扫描；不以测试跳过冒充通过。检查只是本地 M0 参考检查，不是 M0–M5 全链路认证。

边界点梯度需单列分析；光滑内点参考门槛维持 SPEC：约束残差 `1e-6`、方向导数相对误差 `1e-3` 或近零绝对误差 `1e-5`。手算账户夹具现金与净权益误差门槛 `1e-8 × max(1, equity)`，测例同时检查精确预期金额。

## 环境发现

本机为 Windows/Python 3.11.15，现有 torch 2.11.0+cu128。`diffcp 1.1.9` 的 PyPI 文件列表没有 Windows wheel，需 C++ 构建工具；不能把“lock 能解析”当作“干净机器安装成功”。独立环境位于忽略目录 `artifacts/environments/e2e/`，现有 `.venv` 未因求解器安装被改写。

CVXPYlayers 1.2.0 发行包实测不能直接接受构造参数 `solver=cp.SCS`，尽管其 torch 类文档字符串仍列出该示例；实际接口分派使用 `solver="DIFFCP"`，再以 `solver_args={"solve_method": "SCS"}` 显式指定 SCS。实现按安装版本的分派代码与运行结果固定，不仅依据主分支 README。

2026-10-23 已完成干净虚拟环境 CPU lock 安装、本机参考检查和 62 项相关测试；路径、代码身份与编译缓存边界见 [实施记录](../E2E_IMPLEMENTATION.md)。本机 WSL 组件未启用，没有以 dry-run 代替 Linux 实测。
