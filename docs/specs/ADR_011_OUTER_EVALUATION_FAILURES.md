# ADR 011：外层精确诊断的显式失败续持

日期：2026-10-23。状态：**本机 Windows CPU 合成软件范围已验收；完整 N03 与经济有效性未验收**。对应 N03 C4-F / R03-F。

## 决定

保留 `e2e_utility_v1` 旧配置和训练/连续 validation/ADR 010 候选审查的中止行为。只有显式声明以下配置才在外层 test 启用新评价：

```yaml
outer_evaluation:
  schema_version: utility_outer_evaluation_v1
  failure_policy: explicit_failure_hold_v1
  max_seconds: 120
```

未知键、模式、版本、非有限或非正预算拒绝。预算为每个模型外层诊断的合作式时间上限，在决策及阶段边界检查，不能中断正在进行的底层求解；不是进程墙钟硬限额。取消、预算耗尽及系统/内存异常中止整个任务。

源价格修订和事件以运行的 `evaluation_asof` 验证，归档为计划中的 `feedback_cutoff`。直接调用诊断 evaluator 也必须明确传入该截止，不能将执行收盘误当作晚几分钟发布的原始行情已经可用的时点。

可续持的错误只包括原生 policy 明确分类的观察历史不足、非有限收益预测、因果风险/流动性历史不足，以及可识别的求解失败、无可行持仓或生产数值拒绝。形状/dtype/device、配置/数据身份、过期状态、无效配方、目标验证、账户会计和未知程序错误不得靠阶段名自动转成失败续持。

精确策略错误转为既有 `decision_failure_v1`，绑定当日决策/数据/协议/账户/资产池身份。复用独立目标 Bench；不下新单，原持仓照常经过估值、交收、公司行为和应收支付，下一日从推进后的账户重新决策。合法零成交目标仍是成功动作。

新评价保存完整声明日期的决策尝试台账，明确成功、失败及上下文；不复用过期目标。精确路径全部日期进入收益/风险。任一失败使主要比较资格为 false，并标为 `DIAGNOSTIC_WITH_FAILURES`；任务完成状态与评价状态分别记录。

连续路径不续持。可分类策略失败时保存此前完整步骤、首失败上下文和后续 not_run；三路径差异标为 INCOMPLETE，缺失差异为 null，不填 0，不只平均成功前缀。系统/身份/会计/取消/预算错误仍向上传播。精确失败而连续完成时，仍比较全部日期的账户差异，失败日动作差异为 null，并因显式失败撤销比较资格。

## 验证与真实性边界

先冻结评价计划（配置、核心、数据、协议、模型版本、实际参数和标签缩放身份），再归档策略尝试、目标/失败提交及账户。验证器先核验完整计划，全部失败也不能跳过模型身份；在成功日期重算实际模型动作，失败日期使用归档错误事实、重新绑定当前重算上下文并回放失败提交，不要求复现同一次临时求解故障。连续失败同样重算此前完整步骤，检查归档失败处上下文，再中止其诊断。

验证器核对全部日期、尝试/失败/目标/摘要的一致性及独立账户。删失败日期、改单个失败身份、将提交中的失败改成成功或将未完成比较标为 PASS，即使重哈希也须被拒绝。它不能证明临时故障确曾发生，也不认证实现者一致改写整套错误事实；需要外部运行/日志签名才能获得那种证据。
