## 策略审计：输入、周期与参数（当前主线，v0.5）

平台审计用户在其他平台做好的策略。当前实施A1导入与一致性、A2周期资格与历史内部验证分段，及有限的A3治理代码候选。上传、核对、模板下载和补件集中在独立“策略导入”页；“我的策略”逐条提供一键审计、归因、回测和模拟入口。治理页正文选策略，逐项给出基本通过、缺乏证据或需要调整，可生成已识别BigQuant小额买入过滤和收紧上限的代码候选；需回原平台回测。代码必填，允许仅代码静态检查；持仓推算净变动不能冒充真实成交。默认末尾25%、至少3个月，20次及20个不同日期只作效果检验最低门槛。A4重放和A5完整标签后续实施。见 [策略审计输入 SPEC](STRATEGY_AUDIT_INPUT_SPEC.md)。

第二轮外部研究已接入按委托计费核验与受阻目标对照，见[研究落地增量](../research/TEMPERQ_EXTERNAL_AUDIT_20261027/11_研究落地增量_订单计费与受阻目标.md)。同单部分成交不列为合单节省；缺计费依据只作情景。受阻方案沿用原硬约束，逐只列出偏离下界、可调整额、费用与现金，不推算未来收益。

## 1.0 发布与后续训练

基础策略可来自入门模型、自己训练、外部信号或经验模板，共用“模型 → 规则 → 部署 → 运行”。1.0 补齐规则卡、点选向导、四个日线模板与实际检验/持续出分的连接，完成 Windows 和新用户验收；修正量学习留作 1.1 候选研究，Kronos 微调独立限额验证，B1/B2 等不作为发布前提。已有 Kronos 零样本结果、权重截止核实、已见留出期和实验停止条件统一记录在 [发布与适配 SPEC](RELEASE_AND_ADAPTATION_SPEC.md)。

规则卡的使用与文件接口见 [规则卡与本地 AI 协作](../RULE_CARDS.md)。真实出分、编辑、导入确认、检验、纸面演示和版本保留的实现状态及尚待人工完成的发布验收，见 [实施验收记录](RULE_IMPLEMENTATION_ACCEPTANCE_20261025.md)。

## 为谁做，最终交付什么

让普通投资者在自己的电脑或服务器上，用获授权的数据训练、修改和比较模型，并把通过检查的模型运行成每天可查看、可追踪的策略。专业方法作为默认设置，进阶用户可以替换数据、特征、模型和组合规则。

最终产物是**可运行的策略包**：模型、数据处理、预测时点、股票池、组合与风险规则、成本假设、版本记录和运行配置。绑定模拟或实际账户状态后，每日生成买卖建议，记录成交反馈，展示持仓、净值、费用和回撤。首版交付交易建议与模拟账户，不以券商自动下单为发布前提。

这里的“端到端”首先指用户流程贯通。一个网络直接输出持仓并按收益训练，是可选研究方法，不是完成上述产品的必要条件。

## 三条模型路线

| 路线 | 用户得到什么 | 当前优先级 |
| --- | --- | --- |
| B0：LightGBM / Ridge | 自动生成默认特征，训练打分模型，通过组合规则生成目标持仓 | 产品主线，先打通每日运行 |
| B1：原始行情窗口 → GRU 预测 | 不要求用户自己设计因子；学习行情表示，接同一组合与评价流程 | 后续候选，不在 1.0 范围；先对齐任务并验证真实数据 |
| B2：按净效用训练持仓 | 研究训练目标是否改善决策 | 实验功能，暂停扩展；不阻塞 1.0 发布 |

B2 暂停是资源与产品次序选择，不代表理论无效或永远无法验证。已有合成软件测试不构成真实市场收益证据。

## 策略流程与页面链路（草案）

策略为主对象，统一为模型、规则、部署、运行四阶段；模型检验和规则检验分别留在前两阶段。持久草稿支持恢复进度，解释集中帮助；CSV 上传后逐列映射、确认单位，再检查保存。见 [策略流程 SPEC](STRATEGY_FLOW_SPEC.md) v0.3 实施版，外部用户试用仍待验收。

## 模型组装与持续优化（草案）

先交付“我的数据有没有帮助”的完整闭环：固定系列参考与可比上一版、单组数据自动配对、全量分组分析按需；开发比较与最终留出分开，结果不佳时生成有依据的下一版草稿。默认界面只露核心输入，B1 不要求人工因子，B2 留在研究阶段；候选前向比较另行验收。五项首版决策与 M1–M3 优先级见 [模型组装 SPEC](MODEL_BUILDER_SPEC.md) v0.2 草案。

有经验用户的规则卡、受限表达式和四个日线标准打分模板见 [经验策略 SPEC](EXPERIENCE_STRATEGY_SPEC.md)。

## 接下来照什么做

按 [发布与适配 SPEC](RELEASE_AND_ADAPTATION_SPEC.md) 的范围实施；[原最小交付 SPEC](PRODUCT_WORKFLOW_SPEC.md) 保留交易契约和历史实施记录。当前顺序是：

1. 核对经验规则的缺失、量纲、语义与资源限制，完成规则卡和点选编辑。
2. 将四个模板的真实出分接入同一模型检验、规则检验与纸面运行，不用入门 LightGBM 代替执行。
3. 验收版本保留、恢复、数据失败、成本和运行一致性，完成 Windows 冷启动与普通用户试用。
4. 达到发布条件后停止扩展；修正量学习、Kronos 微调及其他平台目标分别按后续计划处理，Linux/服务器不作为本次 Windows 发布新增前提。

竞品、文献、已核查的能力缺口和不能宣传的结论见 [方向核验](../research/PRODUCT_DIRECTION_REVIEW_20261023.md)。用户操作见 [使用手册](../使用手册.md)，现有运行与版本比较见 [研究闭环](../RESEARCH_WORKFLOW.md)。
