产品定位以 [产品理念与长期规划](../PRODUCT_VISION.md) 为准。每步按最小交付停止，当前硬线见 [最小交付 SPEC](PRODUCT_WORKFLOW_SPEC.md)，不将长期愿景逐条追加为当前验收。

## 为谁做，最终交付什么

让普通投资者在自己的电脑或服务器上，用获授权的数据训练、修改和比较模型，并把通过检查的模型运行成每天可查看、可追踪的策略。专业方法作为默认设置，进阶用户可以替换数据、特征、模型和组合规则。

最终产物是**可运行的策略包**：模型、数据处理、预测时点、股票池、组合与风险规则、成本假设、版本记录和运行配置。绑定模拟或实际账户状态后，每日生成买卖建议，记录成交反馈，展示持仓、净值、费用和回撤。首版交付交易建议与模拟账户，不以券商自动下单为发布前提。

这里的“端到端”首先指用户流程贯通。一个网络直接输出持仓并按收益训练，是可选研究方法，不是完成上述产品的必要条件。

## 三条模型路线

| 路线 | 用户得到什么 | 当前优先级 |
| --- | --- | --- |
| B0：LightGBM / Ridge | 自动生成默认特征，训练打分模型，通过组合规则生成目标持仓 | 产品主线，先打通每日运行 |
| B1：原始行情窗口 → GRU 预测 | 不要求用户自己设计因子；学习行情表示，接同一组合与评价流程 | 第二条产品路线，先对齐任务并验证真实数据 |
| B2：按净效用训练持仓 | 研究训练目标是否改善决策 | 实验功能，暂停扩展；不阻塞 B0/B1 发布 |

B2 暂停是资源与产品次序选择，不代表理论无效或永远无法验证。已有合成软件测试不构成真实市场收益证据。

## 接下来照什么做

以 [产品闭环实施 SPEC](PRODUCT_WORKFLOW_SPEC.md) 为当前实施依据，顺序是：

1. 明确策略包、预测/交易时点和账户状态，修正参考选股清单与账户交易建议的区别。
2. 用 B0 打通数据更新、固定模型每日推理、账户建议、模拟成交记账与策略看板。
3. 在共同真实数据与任务上，接入 Qlib 配方对照、B1 和已有版本比较能力。
4. 完成冷安装、普通用户试用、资源测量、Linux 与目标服务器验收，再发布。

竞品、文献、已核查的能力缺口和不能宣传的结论见 [方向核验](../research/PRODUCT_DIRECTION_REVIEW_20261023.md)。用户操作见 [使用手册](../使用手册.md)，现有运行与版本比较见 [研究闭环](../RESEARCH_WORKFLOW.md)。
