# STRUCT 接入策略账本 v1

2026-10-23。新策略默认使用 `struct_v1`，高级设置可选原佣金税费口径。默认版本为 `policy_defaults_v2`。既有缺少此字段的冻结政策仍解释为旧口径；执行实现变化仍要求建立新策略版本，不迁移旧成绩。

## 算法与记账

复用 `netcost.struct_half_spread_bp()` 和随仓库的 `ashare-tcost`。单边成本为上月报价价差估计的一半，加佣金（含最低佣金）、按执行日期的卖出印花税及用户自填的额外滑点压力。四项分别记录，不把 STRUCT 当作冲击，也不抵消额外压力。

估计使用上月成交额均值、原始收盘价均值及月末 21 日收益波动代理；月度结果滞后一月映射到执行日。缺少估计时停止，不按零费用继续。系数拟合使用 2021–2023 的 L2 资料：更早历史只可称事后成本估计，不宣称当时已经获得这些系数。

STRUCT 费用参与买入数量的现金可负担性搜索，不能成交完再把现金扣成负数。成交仍按日线开盘价格代理，成本作为单独现金支出。自融资与损益勾稽包含全部四项；每笔记录估计 bp、输入月份和成本分项。

当前政策、立即调整及平均实际仓位匹配组使用相同成本口径。历史检验和该版本的纸面运行也相同。STRUCT 估计不证明真实成交成本准确，不含大额订单价格冲击；价差估计更充分不能当作新策略获得收益增量的证据。

## 执行版本与旧账户

新建 `portfolio/struct_reference.py`，保留旧 `portfolio/reference.py` 原文件。两者的目标、整手、T+1、受阻、自融资和损益检查语义相同，新版支持按股票传入费用。零 STRUCT 的配对测试验证持仓与现金和原执行器一致；单独测试新增费用改变最小整手可负担性、成本分解和缺失时停止。

旧纸面账户使用原执行文件与冻结实现检查。本轮没有将新成本注入旧前向账户，没有改写其记录。对旧工作区策略，如实现身份不匹配，仍明确阻塞并要求新版本，不修改哈希绕过保护。
