# 策略流程与页面链路 SPEC（草案）

版本：0.3，2026-10-24。状态：**四阶段架构实施版；用户试用验收仍待进行**。本文按产品负责人确认的模型、规则、部署、运行四阶段组织页面；模型检验属于模型阶段，账户历史检验属于规则阶段。模型组装的研究能力另见 [模型组装 SPEC](MODEL_BUILDER_SPEC.md)，不将其全部视为本轮已实现。不改变已冻结的协议、账户。界面原则沿用 [简单模式 SPEC](SIMPLE_MODE_SPEC.md)，规则细节见 [治理层 SPEC](GOVERNANCE_SPEC.md)。

## 1. 要解决的问题

以一个从未接触过本项目的用户视角走查当前工作台，发现：

1. **页面按功能并列铺开，不按进度组织。** 训练、模型评价、治理实验、原纸面账户、模拟持仓、我的策略同时出现在导航里，用户不知道先点哪个。
2. **首页干扰多。** 右上角"全部策略"、"继续上次工作"与"开始"抢注意力；最关键的"训练模型 / 用已有模型"不突出。
3. **训练和策略是两条线。** 训练完要跳到另一个页面再找入口建策略，链路断开。
4. **数据导入要用户猜表头。** 只说"上传 CSV"，不说要哪些列、能不能改名、单位是什么。只有代码、日期、成交量的用户不知道自己缺什么。
5. **看不出整体进度。** 无法一眼看到一个策略做到哪一步、哪里断了、从哪里继续。

## 2. 核心原则

- **策略是唯一的主对象。** 用户首页看到的是"我的策略"，所有工作都在某个策略里进行。
- **一个策略分四个阶段，顺序固定：模型 → 规则 → 部署 → 运行。** 模型阶段的信号检验和规则阶段的账户检验分别命名，不能互相代替。
- **模型库、数据是资源库，不是流程。** 用于管理和复用；主流程不要求用户先进资源库。
- **每页只有一个主要动作。** 按钮按当前动作命名，如开始训练、保存并继续、开始检验、开启纸面账户；其他操作为次要或折叠项。
- **断点可见、可续。** 进入策略即可看到四个阶段的状态，点"继续"回到第一个未完成的阶段。

### 5.1 阶段状态

| 状态 | 含义 | 显示 |
| --- | --- | --- |
| 未开始 | 前一阶段未完成，或本阶段尚未操作 | ○ 灰 |
| 进行中 | 已开始但未达到完成标志，或任务正在运行 | ● 蓝，附进度 |
| 已完成 | 达到操作完成标志，不表示收益有效 | 中性完成标记，结论独立显示 |
| 待重新检验 | 前面阶段改变后，本阶段证据已不对应当前版本 | 待处理标记，附原因 |
| 受阻 | 运行失败、缺数据、公司行动等 | ✕ 红，附原因与处理入口 |

### 5.2 前面改了，后面怎么办

- 修改任何阶段都生成新版本；旧版本和旧纸面账户保留，不覆盖。
- 修改模型 → 继承原规则到新草稿并检查兼容性，历史检验和部署待重新确认。修改规则 → 新版历史检验和部署待重新确认。
- 待重新检验的版本不能沿用旧结果进入部署，但可以用新版本重新检验；不让用户重填未改变的规则。
- 运行中的纸面账户继续按旧版本记账，直到用户为新版本开启新账户。

## 6. 阶段 ① 模型

回答："用哪个信号？它有没有用？"

模型阶段内部的组装、参考系、增量对照、诊断与冠军/挑战者，见 [模型组装 SPEC](MODEL_BUILDER_SPEC.md)；本节只规定入口与完成标志。

### 6.1 入口：选一个来源

```
这个策略用哪个模型打分？

 ○ 用入门模型（推荐新手）  公开日线训练的 LightGBM，覆盖 40 只股票，几秒即可用
 ○ 用我已有的模型          从模型库选择
 ○ 训练一个新模型          使用默认配置或加入自己的数据
 ○ 导入外部预测            在 Qlib、聚宽等别处训练的打分表

                                     [ 下一步 → ]
```

### 6.2 训练子流程

```
数据预检 → 训练配置 → 后台训练 → 开发比较与下一步
```

1. **数据**：选已有数据源，或在此处新增（§7）。显示数据预检结果：够不够、缺什么。
2. **训练设置**：默认五日任务，股票池按数据实际覆盖与历史状态定义，40 股样本不标全 A。核心只留行情数据、名称和配置摘要，输入组件、任务与引擎按需展开，详见模型组装 SPEC。
3. **训练中**：真实阶段进度、已有本机记录时的时间估计、取消。可离开页面，回来时状态保留；不伪造精确剩余时间。
4. **模型比较**：训练完成后直接显示基础参考/上一版对照、本次改动与下一步，不跳到其他页面。这里是可反复使用的开发比较，不自动消耗最终留出期。

### 6.3 模型检验

回答"这个信号本身有没有排序能力"，与规则无关：

- 排序能力（RankIC 与区间）及与简单基准对比
- 前视检查、数据缺失等硬伤
- 一句有证据的发现；完成、可运行和改善分开显示，暂不确定使用中性色，不给未来收益总绿灯

主按钮："用这个模型，去设置规则 →"。次要："调整参数重新训练"、"换一个模型"。

### 6.4 导入外部预测

上传打分表，并声明决策时间、预测期限、股票池、版本（见 [信号与政策交换](SIGNAL_AND_POLICY_EXCHANGE.md)）。导入后同样进入模型检验。

### 6.5 完成标志

已选定模型且必要的数据、时点与输出检查完成，排序结果及局限可查看。统计不确定或相对退化不等于不可运行，允许进入规则阶段；实际硬错误主操作为修复问题，不提供绕过。未完成的对照如实标记，不伪造通过。

## 7. 数据：CSV 导入改为"上传后映射"

### 7.1 页面

```
1 选择文件   2 对应列   3 检查   4 保存

第 2 步：告诉我们每一列是什么
预览前 5 行：
 ┌──────────┬────────────┬───────┬───────┬─────────┐
 │ 股票代码  │ 交易日期    │ 开     │ 收     │ 成交额    │
 │ [代码 ▾] │ [日期 ▾]   │[开盘价▾]│[收盘价▾]│[成交额▾]  │
 ├──────────┼────────────┼───────┼───────┼─────────┤
 │ 000001   │ 2024-01-02 │ 9.39  │ 9.21  │ 1158366  │
 └──────────┴────────────┴───────┴───────┴─────────┘
 成交额单位：( ) 元  (●) 千元  ( ) 万元
 ⚠ 还缺：最高价、最低价。   [ 下载模板 ]  [ 改用免费数据 ]
```

### 7.2 字段

| 字段 | 必填 | 自动识别的列名 | 说明 |
| --- | --- | --- | --- |
| 代码 | 是 | code、ts_code、代码、股票代码、证券代码 | 000001 或 000001.SZ 均可 |
| 日期 | 是 | date、trade_date、日期、交易日期 | 一行一只股票一天 |
| 开盘价、最高价、最低价、收盘价 | 是 | open/high/low/close、开盘价… | 不复权价格 |
| 成交额 | 是 | amount、成交额、成交金额 | 页面选择单位后换算为元 |
| 复权因子 | 否，强烈建议 | adj_factor、复权因子 | 没有时收益会被除权日扭曲，检验中提示 |
| 是否 ST | 否 | is_st、st、是否st | 没有时不能按时点剔除 ST |
| 涨停价、跌停价 | 否 | up_limit、down_limit | 没有时按规则包推算 |
| 成交量 | 否 | volume、vol、成交量 | 可存储备用；**不能代替成交额** |

规则：

- 先按列名自动识别；识别不了的列，用户在下拉框中选择或选"忽略"。
- 必填字段缺失时，明确列出缺哪几项，并提供"下载模板"和"改用免费数据"两个出路，不只是报错。
- 只有代码、日期、成交量时：提示"缺少价格，无法计算收益，不能训练；可改用免费数据自动下载"。
- 映射关系随数据源保存；带日历和复权因子的 CSV 建立增量快照。下次追加同一来源时自动套用，列与单位仍需确认；检查不发布快照，保存才追加，不接受历史行情或日历改写。旧静态来源保留原入口，不自动转换。
- 交易日历由数据供应方提供，列为 date、is_open；免费行情自带。CSV 可以先保存并训练，但进入规则前必须补齐日历；导入阶段提前提示，不靠工作日推测交易日。
- 自有特征另声明实际可用时点、来源与修订语义，训练前反馈匹配和缺失，不因低覆盖悄悄删样本。股票代码存在交易所歧义时要求确认，不靠补后缀猜测。

### 7.3 其他来源

数据页同时提供：免费数据（BaoStock，选股票范围后自动下载）、Tushare（填 token）、已有数据文件夹。均进入同一预检。

## 8. 阶段 ② 规则

回答："拿到排名后，怎么买？"

```
模板 → 资金与可选持仓 → 配置摘要 → 保存版本 → 规则检验
```

1. **模板**：紧凑选择（直接调整 / 分步靠近目标 / 波动目标），原理集中帮助，不在每个选项下加段落。
2. **资金与持仓**：资金与初始持仓共同推导默认持仓数等设置；已微调的项保留。预设描述行为，不用风险偏好名称承诺亏损范围。
3. **配置摘要**：一行显示持仓数、单票/总仓位上限、节奏和调整方式，详细说明按需查看。
4. **高级设置**：折叠，收起不丢改动。
5. **保存版本**：绑定模型、账户初值、规则和成本口径，进入本阶段的规则检验；不自动沿用其他版本成绩。

主按钮："保存并继续"。

保存不是本阶段完成标志；还需要完成当前版本的规则检验。

### 8.1 规则检验

回答：过去按当前账户和规则运行会怎样；这次改动与参考版本差在哪里。

先展示净值、收益/回撤、实际仓位、费用、换手和成交受阻，再在详情显示统计口径。当前规则、立即调整和平均实际仓位匹配三组沿用原协议；事后仓位校准明确不可部署，建仓期和后段分开报告。对比模型时固定规则与账户初值，不能拿不同起点曲线直接相减。

### 8.2 自带信号与调仓时机

用户可以带因子排名或外部策略输出，不强制在本平台重新训练。规则阶段分别回答“目标怎么构建”和“什么时候允许调整”。默认守固定周期；允许额外调整是显式授权，普通排名不进入收益/费用门槛。

本轮在规则页折叠区提供“高级：调仓时机试验”，用同一账户独立比较固定周期和周期外调整。细节见 [账户治理 v2](ACCOUNT_GOVERNANCE_V2.md)。历史试验不改变当前运行版本，未完成新调度的纸面部署验收，不从该试验跳转为已部署状态。

未检验时主按钮“开始检验”；完成且无硬错误时为“配置部署”。不确定可继续明确标记的纸面观察，不能仅因净收益不显著认定成本是原因。诊断和下一版草稿沿用模型组装 SPEC §6；最终留出独立揭示，不因用户反复改日期变成新证据。

完成标志：当前冻结版本的历史账户检验已完成，数据/执行检查范围与局限可见；不以证明未来收益为完成条件。

## 9. 阶段 ③ 部署

回答："从哪天开始、怎么跟踪？"

| 项 | 默认 |
| --- | --- |
| 账户起点 | 沿用规则阶段的现金及可选持仓；部署时改变初值须建立新版本并重新检查，旧检验不能冒充新初值结果 |
| 开始日 | 今日启用；最早下一交易日模拟执行，沿用账本现有时点契约，不因页面改版改写启用日 |
| 每日自动运行 | 关闭，用户开启；说明关机或关闭工作台期间不运行 |
| 数据更新方式 | 跟随实际支持的增量适配器；当前 BaoStock 源支持自动刷新，CSV 和外部预测需追加，其他来源未实现前不承诺自动拉取；显示最近日期 |

页面明确说明：纸面账户只模拟，不连接券商，不下单；历史检验成绩不计入前向记录。

主按钮："开启纸面账户"。完成标志：纸面账户已开启。

## 10. 阶段 ④ 运行

沿用 [部署看板](DEPLOYMENT_DASHBOARD.md) 的总览与专业多窗，顶部固定三行：

1. **今天**：已记账 / 等待数据（原因）/ 受阻（原因与处理入口）
2. **账户**：权益、前向天数、累计费用、最大回撤
3. **建议**：今日目标持仓与参考买卖清单（导出 CSV）

其余：净值曲线（按时记录、迟到重建、历史演示分开）、持仓、成交与受阻、版本切换。

## 11. 模型库与数据页

- **模型库**：卡片列出每个模型的来源、训练数据范围、检验结论、被哪些策略使用。操作：查看检验、再训练（生成新模型，不覆盖）、导入外部预测、删除（被策略使用时不可删）。从模型库"用这个模型新建策略"，直接进入策略的阶段 ①，模型已选好。
- **数据**：列出数据源、覆盖日期、股票数、最近更新、预检结论。操作：新增、追加、更新、查看映射。

| `/strategies/{sid}/{vid}/rules` | 阶段 ② 规则检验 | `/edit` 仍为建立新版本的编辑页；POST `/evaluate` 仍提交任务 |
| `/strategies/{sid}/{vid}/deploy` | 阶段 ③ 启用设置 | 未检验时引导回规则，已有账户时进入看板 |
| `/strategies/{sid}/{vid}/dashboard` | 阶段 ④ 运行看板 | 保留 |
| `/models`、`/data` | 资源库 | `/models` 改为模型库；数据页新增 |
| `/governance`、`/paper`、`/holdings`、`/experiments`、`/audit` | 移入"更多" | 原 URL 继续可用 |

已有的策略、模型、纸面账户、数据源不迁移、不改写；按新结构读取并推断阶段状态。

## 13. 文案原则

- 每个阶段只留标题、当前状态和必要输入。含义、原因、参数解释集中到右上角帮助，按当前阶段定位；不默认展开三行教学，不给每个按钮附说明。
- 按钮写当前动作，如“开始训练”“保存并继续”“开始检验”“开启纸面账户”；不要求每个按钮同时解释目的和去向。
- 报错写原因和出路，例如"缺少最高价、最低价"加两个按钮，不只写"格式错误"。
- 术语解释放进帮助或按需详情；未完成、不可运行、暂不能判断与历史改善分别表达，颜色不是唯一信号。

## 14. 里程碑

| 里程碑 | 交付 | 停止条件 |
| --- | --- | --- |
| F1 导航与首页 | §3、§4 | 首页上半部两条开始路线，下半部恢复已有策略 |
| F2 策略总览与阶段状态 | §5 | 现有策略能正确显示四阶段状态与断点；"继续"落到正确阶段 |
| F3 阶段 ① 模型 | §6，训练完直接显示检验并进入规则 | 训练完成后不需离开策略页面 |
| F4 CSV 列映射 | §7 | 只有代码、日期、成交量的文件得到明确的缺失提示与出路 |
| F5 阶段 ②③④ 整合 | §8、§9、§10 | 规则含历史检验，部署单独确认，运行进入大看板 |
| F6 模型库与数据页 | §11 | 从模型库可直接新建策略 |

F1、F2 先做，改动最小、收益最大。

## 15. 验收

- 一位从未用过本项目的人，不看文档，从首页到开启纸面账户，过程中不需要询问"下一步点哪里"。
- 中途关闭浏览器，重新打开后能从首页找到策略并点"继续"回到原处。
- 只有代码、日期、成交量的 CSV，能看懂缺什么、怎么补。
- 修改模型后，能看出规则和部署需要重做，旧账户仍在。

自动化覆盖：`scripts/qa_experience.mjs` 跑真实训练、规则检验、部署和记账；`scripts/qa_csv_mapping.mjs` 覆盖草稿恢复、列映射与单位修改后重检；`scripts/qa_deployment.mjs` 覆盖看板、自动检查、重复记账及移动端。使用隔离合成行情，不模拟服务响应；这些是软件验收，不替代新用户试用或真实市场前向证据。

## 16. 未冻结事项与本版规则
