## 1. 目标与现状

目标是让用户在自有数据/算力上开展两类研究，并用同一套时点、试验记录和独立账户规则评价：

1. 历史行情及可选文本 → 自动学习表示 → 预测。
2. 历史观测 + 实际账户状态 → 受约束目标持仓 → 按风险、成本和收益训练。

因子不是必经模块。专业用户可以继续使用手工因子、树模型、自定义网络与外部训练框架；平台要求的是可验证的契约和证据。

| 项目 | 当前 | 本规范目标 |
| --- | --- | --- |
| 原生训练 | Ridge/LightGBM 年度路径；另有时点 GRU/Ridge 月周预测运行 | 保留兼容并完成可扩展适配器、共同组合层和证据验收 |
| 外部模型 | 标准预测；初步独立目标 JSON 与本地回调 | 保留预测路径，补齐目标账户生命周期 |
| Bench | 分数独立账户；初步目标原始股数回放与重算 | 分数和目标持仓分开验证，完善公司行为与完整执行证据 |
| 目标训练 | 已有原始输入、可微组合层与连续净效用微调的合成运行，代理差异超限 | 完成数值/账户边界与公平研究，按证据声明适用范围 |
| 专业扩展 | 已有接口但能力有限 | 自定义 encoder/loss/allocator/folds，能力声明与版本契约 |
| 经济证据 | 当前真实开发账户仍有 `DIAGNOSTIC_ONLY` 限制 | 分离软件就绪与经济确认，满足数据和账户门槛才提升证据等级 |

## 3. 架构与职责

```text
版本化时点数据 + 可用时间/修订 + 历史资产池
  → ObservationAdapter → Encoder → 预测头 / 组合参数头
  → Allocator(实际状态、已知风险/约束) → 分数或目标持仓产物
  → 独立 Bench → 成交/交收/现金/净权益 → 比较与证据包

训练专用：按时间推进的可微环境 → 净效用损失 → 编码器/参数头
                              ↘ 与独立 Bench 的路径差异审查
```

训练器不得依赖 Bench 的未来标签、未来状态或最终评分来选择模型。Bench 不执行提交模型的任意 Python；本地用户显式安装的适配器在用户环境运行。社区继续只展示元信息与链接，不远程执行仓库代码。

职责分别由 `src/qwb/observations/`、`src/qwb/training/`、`src/qwb/portfolio/` 承担，复用现有 `folds.py`、`experiments.py`、`worker.py`、`src/qwb/bench/`；接口与接入决策由各 ADR 固定。不给网站前端另造训练或账户逻辑。

## 4. 数据和观察接口

### OBS-01：数值窗口

- 逻辑输入 `values[batch, asset, lookback, channel]`；首个配方为 60 个交易日、OHLCV/amount 六通道，通道变换和单位有版本。不是强制所有模型使用该形状。
- 同时传入 `asset_ids`、`decision_time`、`available_time`、缺失掩码、历史资产池掩码与窗口有效长度。模型不能通过填充位置或未来资产顺序隐式获得信息。
- 窗口止于决策时已知数据；归一化仅在当前窗口或历史训练段拟合，不能整段包含验证/测试数据。批标准化等状态同样受约束。
- 原始价格用于可追踪观察，成交使用可交易价格。拆分/分红须用当时已知事件处理；不得用今天的后复权水平重写历史输入而不检查其因果性。
- 缺失、停牌、退市、新股短历史须有显式策略，不能静默删除困难样本。失去预测资格不等于账户已持仓可以消失。
- 指纹覆盖源数据内容、时间范围、修订/可用时间、资产池、观察配方与拟合状态；在现有 manifest 上扩展，不能只有路径或快照名称。

### OBS-02：可选因子、文本和预训练

因子走可选分支，声明是否使用以及来源；数值原始输入分支无需先构造 Alpha158 等因子。文本需 `publish_time/available_time/revision` 与正文身份，先实现可用时间再引入编码器。未知公告历史修订、现代 LLM 的历史知识以及未知预训练覆盖都必须记录为污染风险。

Kronos/Chronos 权重固定哈希、训练截止与已知市场覆盖，未能核实的数据重叠不得标为干净历史样本外。可发布受限诊断；经济确认需要独立未见时段。网络下载、权重授权与数据授权分开记录。

## 5. 模型、折与专业扩展

### MOD-01：适配器

统一能力声明：输入模态、输出类型、训练目标、是否需要跨资产批、动态资产池支持、CPU/GPU、状态恢复粒度、随机性和版本。接口语义为 `fit(train, validation, context)`、`predict(observations, state)`、`save/load`，具体类型在 M0 固定。

外部用户可以提交标准预测而不使用本平台训练器；新增目标持仓接口允许其自有策略受相同账户约束评价。用户自定义代码仅本地受信任安装，公开网站不承接任意训练执行。

保留模型自己的特征、损失与训练循环；不强制所有专业工作通过固定 GUI。声明不支持的做空、衍生品、高频订单簿等任务应明确拒绝，不能转换成日频多头并继续生成看似有效的报告。

### FOLD-01：通用时间折

将当前年度折扩展为显式 train/validation/test 时间区间与再训练/再平衡日历；支持月/周滚动与扩展窗口。旧年度配置通过兼容适配保留结果身份，不自动重解释旧协议。

标签成熟必须按实际结束时刻及可用时刻判断，而非只减固定行数。重叠标签需 purge，必要的 embargo 长度由标签/协议确定并记录。测试窗口不能参与标准化、早停、参数选择或成本拟合；内层选择与外层预测分开归档。

任意长回看与跨资产窗口均须测试边界；合法使用决策日前历史上下文与把测试标签加入训练是两回事。月/周折未通过前不得称专业 E2E 训练链路已完成。

## 6. 账户状态与目标持仓契约

### STATE-01：账户状态

输入必须是决策时可知的实际账户状态：逐资产数量/估值、现金、结算与可售数量、未成交/待执行指令、上一成交与费用、已知公司行为、持仓估值时点。权重基于价格漂移后的真实持仓计算；不能拿昨日目标持仓替代。

候选资产与现有持仓取并集。退出资产池、停牌或已无新信号的持仓继续留在账中，直到合法卖出、公司行为或显式终止估值事件处理。策略状态重建必须可复现，不能每个验证片段凭空从零开始而不声明。

决策约束与未来成交状态分离：收盘决策时只能使用当时已知状态；次日实际停牌、涨跌停、开盘价、成交量等只能在执行阶段揭示。未来状态可以作为历史训练的环境反馈，不得进入该时点的策略观察或提前排除难成交资产。

### OUT-01：输出版本

现有预测 schema 保留。已新增基础 `target_weights_v1`：每次决策带 `decision_id/decision_time/execution_not_before/task/model_version/data_snapshot_id/state_id/universe_id`；逐项带 `asset_id/target_weight`，另带显式 `cash_weight` 与协议身份。数量型策略未来另建契约，不能混用。

首版只做多、无杠杆，目标是成交后的意向比例，不是已成交持仓。所有值必须有限、资产唯一、身份可解析、权重非负；v1 股票与现金权重合计为 1。v2 显式加入决策时已知、不能交易的 `receivable_weight`，股票、现金和应收合计为 1；应收不能当作现金再配置。版本与生命周期见 ADR 004。缺失决策、重复记录、未知资产、过期 state、未达最低现金或上限约束应拒绝。

工程当前容差：输入权重加总误差 ≤ `1e-6`，单项权重严格非负。最初拟议的 `1e-8` 负值容差经 ADR 001 收紧，不用于接受负持仓；原始求解值和误差保留，不能偷偷裁剪、丢弃或重新归一化。需修复的输出由生产方显式生成新版本。容差是工程选择，不是论文给出的金融有效性阈值。

N02 的生产方可预声明 `strict_raw` 或 `highs_l1_projection_v1`：前者保留严格拒绝，后者在相同经济约束内求最近 L1 可行解，最大单项变化不得超过求解容差，且不超过 `1e-6`。两组权重和差异均归档；验证端不修复。HiGHS 投影不参与反向传播，不能将原始求解器梯度称为完整生产路径梯度，见 ADR 005。

### EXEC-01：执行及失败语义

执行器根据次日揭示的价格、资金、可售数量、交易单位、费用、停牌、涨跌停和成交限制生成实际成交，保留未成交原因；目标与实际权重分别存储。现金不能透支，费用与公司行为进入净权益，自融资残差可逐笔核对。

不可行约束和求解失败不得隐式回退等权/零分。默认发出结构化失败并取消新增指令，保留已有真实账户状态和订单生命周期；市场价值与风险敞口仍随行情变化。冻结持仓本身若违反研究风险上限，必须显示违约，不能将“保留持仓”标为约束满足。

协议需提前声明哪些约束允许带罚项松弛、顺序与最大量；法律/资金/可售约束不松弛。出现未预声明松弛或回退的窗口只作诊断，不能作为通过验证的主要比较。求解失败也计入试验台账。

## 7. 组合层与训练目标

### OPT-01：第一版组合层

给定预测收益向量 `mu`、决策时风险平方根 `L`、实际漂移权重 `h`、已知非交易应收比例 `r` 与约束，求多头目标 `w`、现金 `c`。v1 的 `r=0`，v2 的 `r` 固定为决策账户应收比例。目标结构：

```text
maximize mu' w - lambda_risk * ||L w||²
              - estimated_cost(w, h) - lambda_stability * ||w-h||²
subject to sum(w) + c + r = 1,
           w >= 0, c >= configured_cash_reserve,
           position/sector/turnover limits declared by protocol,
           known restrictions derived from actual holdings.
```

`mu` 为下一执行区间收益估计，`L'L` 与其时段和单位一致。风险和成本系数在历史内层选择，不能拿百分数/小数或日/月单位混算。行业分类、风险估计和成本拟合均来自决策前可用数据。

第一版成本近似采用显式买卖方向与预估成交额/流动性下的凸代理，系数有来源与拟合期；精确最低费、整数手数、冲击、交收与未成交由账户回放。上述权重预算只是意向预算，不意味着精确支付费用后的自融资已经解决；账户执行和可微环境须独立扣费并处理可买数量，不能把费用同时从持仓和收益重复扣除。

风险矩阵缺失策略、收缩、特征值下限和条件数记录；不得用全测试段协方差。`L` 在层外因果估计，固定风险惩罚起步；用 DPP 合规参数化与交易辅助变量，检查 `problem.is_dpp()`，不靠手写 KKT 反传绕过测试。具体库/后端版本在安装兼容验证后锁定，不自动追随主分支。

保留分离的 `Allocator` 后端接口；BPQP 只有在相同问题上满足可行性、解/梯度和净效用路径一致性，并且有实测性能收益后才能替换参考实现。

### LOSS-01：训练效用

首版采用连续净权益的平均对数增长减风险惩罚作为稳定起点：`loss = -mean(log(E[t+1]/E[t])) + lambda_var * Var(net_returns)`；净权益必须严格为正，否则结构化失败。主评价另报告净累计收益、波动、回撤、换手与相对基线，而不将训练损失当作投资绩效。

可选 Sharpe/CVaR 等目标后续加入并单独消融；不能一开始搜索多种指标后只报告赢家。所有费用以真实/近似成交与实际漂移持仓计算，不用相邻目标权重之差代替实际换手。账户已有净收益扣费后，不在损失再次扣同一费用。

训练环境须模拟隔夜旧持仓、次日开盘交易、日内估值和费用的先后次序。训练中的连续份额/平滑成本是近似；T+1、停牌、限价和整数手数无法靠“可微”自动精确化，需明确离散状态、梯度停止位置和代理映射。观测只看到当时已知状态，未来价格仅用于状态推进及计算损失。

### SEQ-01：时间连续训练

按时间顺序推进账户 episode，显式初始现金/持仓、burn-in、再平衡频率及截断 BPTT 长度。不同 episode 可以并行；不可随机打乱重叠日期，然后假装获得了一条连续换手路径。

片段首尾的建仓、清仓和费用策略写进协议；不拼接无关区间制造虚假交易，不用测试收益选择状态初值。验证 episode 独立、无梯度；模型权重、优化器/RNG、数据游标与账户状态若不能共同恢复，应声明只支持整折重跑，不能宣称无损恢复。

## 8. 实验设计与模型选择

### EXP-01：拆开改进来源

先做两组对照，固定样本、原始快照、时点、预算、风险模型和执行器：

| 对照 | 输入/编码 | 训练目标 | 组合层 |
| --- | --- | --- | --- |
| B0 | Ridge/LightGBM + 明示因子配方 | 预测 | 同一固定组合层 |
| B1 | 原始数值窗口 + GRU/ALSTM | 预测 | 同一固定组合层 |
| B2 | 与 B1 相同编码器、初始化与可训练容量 | 决策净效用 | 同一组合层，允许梯度回传 |

B0/B1 的差异同时包含输入和模型，不得全部归因于“表示学习”。若要识别输入贡献，增加同模型、同预算的输入消融。B1/B2 才用于隔离决策训练影响。

随后做 `encoder_frozen / encoder_trainable × prediction_loss / utility_loss` 的 2×2 消融；四格使用共同的可训练头、相同组合层与预训练 checkpoint，明确冻结范围。组合层结构与惩罚先固定；学习风险或成本参数另列实验，避免收益来源无法解释。

增加无成本/基准成本/压力成本、无交收限制/真实限制、相同容量与完整历史资产池对照。去除真实约束的实验只用于解释差异，不作主要绩效证据。

### EXP-02：预算、选择与确认

每次研究先冻结试验清单：模型/数据/任务版本、所有随机种子、候选参数、训练次数/时长/显存预算、选择指标与失败处理。所有尝试（含失败与人工放弃）记录到实验账；探索与确认使用不同标识。

开发阶段至少 3 个预声明种子；若资源只允许更少，结果标为初步。置信区间以日期块为主要重采样单位，配对比较相同日期/资产/成本，不把股票或重叠窗口当作独立样本。块长度与敏感性范围在查看结果前确定，报告种子差异与区间。

不能因均值更高就认定经济有效；净效用区间跨零时报告未确认。做过多少选择必须可追踪；未收集完整试验路径时，不声称已完成 PBO/多重比较校正。

已有历史开发数据，包括反复查看过的 2024–2025 年，不重新命名为独立留出。确认需冻结方案之后取得未用于选择的新数据；跨市场迁移也需核实是否参与过模型预训练/开发。

## 9. 验收测试

| 类别 | 必须覆盖的证据 | 失败处理 |
| --- | --- | --- |
| 时点与折 | 修改未来数据不改变此前观察/预测/约束；标签成熟、公告修订、归一化边界、退市/资产池变化 | 阻止可比较结果产生，保存失败样例 |
| 优化数值 | 双精度可行性/原对偶残差；内点有限差分与方向导数；边界与病态条件敏感性；已知小问题的参考解 | 梯度非有限、误差未解释或求解失败不得静默训练 |
| 账户 | 漂移持仓换手、T+1 可售、最低费/手数、涨跌停/停牌、未成交、退市保留、分红拆股、现金与自融资残差 | 精确账本不平则该路径失败 |
| 代理一致性 | 同一动作/价格路径下，训练环境与独立 Bench 的逐日权益、成交、费用、状态对齐；连续松弛逐项加回真实约束 | 输出差异分解；超协议阈值只作诊断 |
| 可复现与环境 | CPU 小型 smoke、Windows/Linux 干净安装、固定种子/版本、相同 checkpoint 重放、GPU 可选 | 不支持的平台明确标记，不能宣传为已支持 |
| 基准公平性 | 同任务/时点/成本/资产池/预算，完整试验账，负结果与失败比例 | 不满足者不能列入主比较 |

数值初始门槛：参考问题原始约束绝对残差 ≤ `1e-6`；光滑内点方向导数相对误差 ≤ `1e-3`，近零导数同时用绝对误差 ≤ `1e-5` 判断。需标准化问题尺度，保存步长扫描和误差定义；边界不可微点单列，不强迫满足内点门槛，也不伪称梯度唯一。这些阈值在 M0 校准后冻结，变更必须留 ADR。

实际账户与连续代理的容差不能混用。M0 用固定小型确定性夹具建立会计精度门槛，再预声明真实约束下可接受的费用/换手/权益差异阈值；不得看见策略收益后再调整门槛。精确语义夹具不接受用“近似误差”解释会计不平。

性能只报实测硬件、资产数/窗口长度、编译/求解/反传耗时、峰值内存与失败率；本 SPEC 不捏造吞吐指标。扩大资产池前先测稠密风险矩阵与重复求解的资源瓶颈。

## 12. 风险与明确边界

- 优化层规模、数值不稳定、Windows 依赖和 GPU/CPU 数据搬移可能成为瓶颈；先有小规模参考，再依据剖析优化。
- 精确交易含离散约束和不完全成交，可微代理可能系统性偏差；不能用高训练效用掩盖独立账户退化。
- 数据时点、退市与价格口径的现有诊断限制优先修复；复杂模型无法补回缺失的证据。
- GPL 项目只列为研究/独立对照候选；正式依赖与分发须另核许可，不能把整个生态的代码许可统称为本项目 MIT。
- 专业扩展不等于支持一切市场：首版仍为 A 股日频多头；做空、衍生品、高频、实盘券商执行不在本阶段。
- 公告多模态、BPQP、基础模型与在线适应需分别立 ADR 和冻结对照；本轮不提前安装或实现。

后续修改记录：每次方向变更附日期、原因、证据、兼容影响和验收变化；文献编号沿用调研文档，不用新论文标题替代实验结论。

## 14. 可直接拆分的开发任务

本节细化 N01–N05 的交付边界，不表示功能已实现。任务按依赖推进，每项提交都需记录配置、实现身份、验证结果及剩余限制；验收失败时保留失败产物。

### N01：账户生命周期与版本升级

依赖：现有目标回放与参考账户。交付：账户/事件/协议升级 ADR、版本化序列化与身份计算、事件账本、回放及重算器、生命周期夹具。升级涉及应收或权益定义时使用新版本，旧状态和旧协议继续按原语义读取；不支持的组合明确拒绝。

必须覆盖以下场景：

- 登记日捕获有权股数；登记后卖出仍保留已确定的分红权利。登记记录与除权后计入权益的应收分开，不提前增加净权益。
- 除权日按协议确认应收并使用对应原始价格；支付日前应收计入权益，但不可用于买入。支付日应收转现金，不能再次形成收益。
- 税费使用明确的事件金额或已声明规则，区分未知、税前和税后口径；不把固定税率当成已实现真实持有期税制。口径不完整时保留诊断资格。
- 拆股同步调整总股数、可售股数、未交收批次及参考估值；原始成交价与调整后股数配对。残股处理需声明现金结算或拒绝，禁止静默取整。
- 退市和长期无法成交的持仓继续留账；终止估值与可收取现金分别声明。减记不等于获得现金，不允许按最后价格自动卖出。
- 事件包含可用时间；未知事件不能进入此前决策上下文。未来事件内容变化不影响此前观察、目标和已发生交易。

验收：逐事件、逐日核对现金、证券市值、应收与净权益，覆盖持有、登记后卖出、除权后买入、支付日、未交收拆股及终止路径。沿用 ADR 001 会计精度并检查手算金额；验证未知事件、重复事件、单位冲突和旧版错误升级均失败。完整 M2 只有在这些生命周期路径和原有目标/分数回归均通过后才可关闭。

### N02：共享组合层与因果风险/成本

依赖：N01。交付：风险/成本配方及单位说明、完整拟合期与指纹、预测到目标的本地适配器、B0/B1 共同账户运行配置。估计未来流动性只能使用历史可用数据，不得将次日实际成交量作为决策输入。

验收：修改未来价格、行业或成交量不改变此前风险矩阵、成本系数和约束；矩阵收缩、特征值与病态诊断可重算。B0/B1 使用同一初始账户、组合参数、费用、资产池和日期；保留全部求解失败、实际成交和实际换手。先冻结代理差异指标及阈值，再运行收益比较。

### N03：时间连续的决策训练

依赖：N01、N02 及现有序列预测。交付：新配置校验与 CLI/worker 接入、按时间推进的账户 episode、可微效用训练、checkpoint 与恢复能力声明、独立 Bench 差异报告。未实现配置不得通过 `--check` 后转入旧训练器。

训练只使用本时点可知观察和本环境已执行后的状态，未来价格用于推进环境与计算损失。验证无梯度；验证选择之后，外层测试不再影响 checkpoint。截断 BPTT、状态 detach、片段边界费用、初始化与随机状态均入配置及台账。

验收分两层：先以固定动作和共同价格路径核对代理与精确账户的会计，再让策略分别读取各自账户状态运行，报告由状态反馈引起的决策差异。按整数手、最低费、交收、未成交、公司行为逐项分解权益/成交/费用差异；超过预声明阈值保留为诊断。只有模型、优化器、随机状态、数据游标与账户可共同重放时，才允许声明片段级恢复；否则只提供整折重跑。

### N04：冻结对照与增益判断

依赖：N03。交付：运行前冻结的实验清单、B0/B1/B2 与 2×2 配置、成本/约束压力配置、全部 trial 账、日期块配对区间、失败与负结果报告。LightGBM 继续采用历史内层验证选轮数；搜索候选数和时间预算与神经路径一起披露。

验收：样本/标签/任务/账户语义不一致的运行不能直接比较；无效日期不能事后只从劣势模型中删除。按预声明规则处理失败，并同时报告覆盖率与失败率。结果可以是“无增益”或“尚未确认”，不以神经模型胜出作为软件验收条件。合成数据只验软件，真实经济结论必须另过数据与未见时段门槛。

### N05：公开复现与部署交接

依赖：N01–N04；环境安装与文档准备可提前。交付：公开合成/授权样本、模型/数据卡、干净克隆命令、依赖与许可清单、失败案例、版本发布包、服务器配置与备份恢复说明。网站分享、训练 worker 和 Bench 分别说明运行方式，避免将本地可信插件入口开放为公共任意代码执行入口。

验收：Windows/Linux 分别实际安装、运行小型训练、目标回放和证据重算；填写平台、版本、耗时与限制。至少一位非实现者按发布版本复现并留下记录，不能以开发者换一个虚拟环境替代外部复现。服务器上线另记录实际域名/配置、健康检查与恢复结果；源码可上传或容器可构建不等于部署成功。

## 15. 选型依据与复用边界

文献 ID 和核验深度沿用 [研究调研](../research/E2E_RESEARCH_REVIEW_20261022.md)；此处只建立任务对应关系，不把论文结论当作本项目结果。

| 工作 | 可吸收的依据 | 工程处理 |
| --- | --- | --- |
| 原始输入与预测 | P02、Qlib 的 GRU/ALSTM 模式 | 保留当前小型 GRU 与因果窗口，先测同预算基线；不预设图像或 Transformer 必然更好 |
| 树模型增强与专业工作流 | 专业审查中的 Gu/Kelly/Xiu、Qlib、VeighNa | 历史验证选轮数、标签/样本权重与特征消融；保留外部训练和标准输出接入 |
| 决策导向训练 | P01、P03、P04、deepdow | 复用可微优化库，独立实现并核对本项目账户语义；论文窗口收益不能替代实际账户路径 |
| 风险/成本及执行对照 | cvxportfolio、现有 Bench | 参考建模方法，按许可决定是否引入代码；实际执行与训练成本代理分别验证 |
| 后续加速与适应 | P05、P12、P13、P14 | 数值一致性和冻结消融通过后另立 ADR，不在本轮默认增加依赖 |
| 预训练与多模态 | P06–P10、Kronos、Chronos、FinWorld、FinTSB | 保留竞争跟踪和适配可能；先核验权重/数据许可、历史污染及文本时点，再开独立实验 |

专业用户的扩展边界由数据/输出/评价契约决定，不能强制其采用平台的 encoder、特征、损失或训练循环。不支持的市场与交易类型需能力声明并明确拒绝；新增支持通过版本升级实现。
