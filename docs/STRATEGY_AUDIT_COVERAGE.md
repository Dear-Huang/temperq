# 构建、实施与治理审计目录

日期：2026-10-27。目录版本：`audit_coverage_v3`。

## 范围与划界

产品接受用户自己的预测、当前账户和交易规则，关注预测交付之后的决策。
本阶段隐藏训练、模型库和重新建模的界面入口，保留历史代码、数据与记录。

这里的“后端治理”是产品上的宽称。严格区分时：

- **构建**决定已批准的信号怎样变成目标组合，例如选多少只、怎样加权、现金比例、行业/风格暴露和单票上限。
- **实施与执行**决定怎样从当前账户到达目标，例如调整速度、免交易带、订单规模、参与率、费用、受阻处理和完成期限。
- **治理**贯穿上述过程，规定目标、硬约束、允许调整的参数带、批准权限、例外处理、复核和版本留痕。
- **结果检验**负责对账、归因和复验，不把实现结果反推成预测能力的证明。

这是一份结合本地研究资产与公开文献的工程分类，不宣称存在唯一学术标准，也不表示 15 项算法已经完成。

## 报告的 15 个环节

| 环节 | 主要决定与审计对象 | 应输出的优化比较 | 当前基础覆盖 |
| --- | --- | --- | --- |
| 01 预测交付与目标契约 | 分数/排名/权重的含义、可用时点、版本、更新节奏 | 固定预测，确认目标转译，不重新训练预测端 | 代码字面量候选；未恢复完整信号流 |
| 02 股票池、准入与规则暴露 | 时点股票池、ST/停牌/涨跌停、上市期限；有因子定义时做制度规则敏感性 | 可交易过滤与原规则、目标排除量与遗留暴露 | 实际出现证券计数；不当作全候选池 |
| 03 目标到组合映射 | 排序到目标、持仓数、权重法、现金留存 | 原构建、等权、不同宽度/权重方案 | 收盘持仓数范围 |
| 04 约束冲突与边际代价 | 仓位、现金、整手、锁仓、禁买、风险预算是否相容 | 可行候选、冲突解释、放松偏好的代价 | 单票收盘核对与期末必要减持市值下界；带已确认上限转入现有整数账户规划 |
| 05 风险与暴露 | 集中度、行业、风格、beta、相关性和尾部风险 | 风险预算/分散化与原目标的权衡 | HHI、股票部分有效持仓数、现金与权益路径回撤；行业/风格待接 |
| 06 调仓节奏与调整速度 | 日历调仓、偏离触发、部分调整、免交易带 | 共同日期/信号下比较成本、偏离、风险、现金与净表现 | 换手、同日双向重叠及FIFO实际持有期分组（右删失/覆盖缺口分列）；尚未运行政策复验 |
| 07 信号年龄与复核 | 同一信号经过时间后如何使用、复核或替换 | 保留、复核、分批更新；测收益和额外交易代价 | 算法待接入；不能用多期限 IC 冒充年龄曲线 |
| 08 费用、价差与订单规模 | 佣金、最低佣金、税、价差、冲击、价位地板 | 同批合单、减少微调；保持交易制度不变 | STRUCT一档地板分量半档情景、低价暴露/盈亏覆盖、可选同日L2日均报价核对；完整流动性分量待接；合单检查默认折叠 |
| 09 容量与流动性预算 | 资金规模、参与率、流动性、现金结转 | 规模/预算到可达金额和连续短缺量 | 算法待接入；已成交金额不等于容量 |
| 10 建仓、退出与完成期限 | 路径、受阻、未完成目标、可达时间 | 可卖部分、受阻部分、情景下最早/最晚完成界 | 算法待接入；不输出确定的未来成交日期 |
| 11 订单与执行偏离 | 计划、下单、撤单、部分成交、成交、人工干预 | 实现短缺、延迟、机会成本与遗留风险 | 成交/错误日志计数；不把日志数当未成交订单数 |
| 12 账户、现金与公司行动 | 持仓、可卖股数、冻结资金、现金、分红送转 | 修复数据缺口后重新对账 | 导出范围内库存、现金、估值及 P&L 桥 |
| 13 结果、成本与归因 | 证券、行业/风格、现金、构建、执行、交互 | 会计归因、因子/Brinson 归因、可行反事实归因 | 全期/回撤逐股贡献、按实际持有期和买入价的批次归因（仅覆盖证券）；因果归因待接 |
| 14 回测可信度与稳健性 | PIT、前视、引擎实现、样本选择、参数搜索、留出和压力情景 | 原方案与少量冻结候选的配对验证 | 源文件摘要与静态解析；未证明无前视或无过拟合 |
| 15 授权、例外与版本留痕 | 谁可改什么、批准范围、例外、升级、回退 | 建议、人工选择、实际执行分别登记和复核 | 输入与结果版本；保存计划不等于激活或成交 |

01 是预测接口，不是模型评比。05 可能使用用户提供的风险预测，但不因此把整个后端称作“没有预测”。
治理给 03–11 规定边界，不能与调整速度或某个优化器混为一件事。

## 每个环节的输出契约

每项都有：本次观测、量值/单位、当前设置、候选动作、代价和约束、深入检验所需输入、依据、实现状态。
有原始证据时还应引用输入行、来源摘要和规则版本。确认后的参数与代码里识别出的候选分开保存。

证据层次分别表达：

1. 导出记录上的描述或账户恒等核对。
2. 声明模型下的可行方案或费用情景。
3. 共同信号、日期和初始账户下的历史政策复验。
4. 冻结后的独立验证或前向记录。

没有第 3、4 层也可以交付前两层；不能把费用情景写成已兑现节省。
目录缺算法时标“待接入”，有数据缺口时列依赖，不把它评为策略失败。
每个环节再分别列方法的算法状态（已接入 / 可转入账户规划 / 已有代码但本报告未接入 / 报告算法待实现）与材料状态
（材料可计算 / 缺少材料 / 需用户确认 / 先核对账目），并列出具体依赖。两项可以同时不满足，不能用缺材料掩盖未实现算法。
收盘合规不能认证盘中合规，成交表不能替代完整订单生命周期。

每个候选都与原方案、显式不操作基线比较；不同候选若互有取舍，保留少量可选方案。
风险下降、成本下降、偏离增加和现金增加分别报告。不汇总成无依据的“总分”。
只在明确目标、硬约束、模型和求解容差内使用“最优”；历史候选较优不等于未来最优。

## 元课题资产的吸收与纠错

- 现行元课题定义和后端构建规划支持“预测估计 / 构建映射 / 治理授权”分别登记。
- 六站时间线支持信号 → 组合 → 调仓 → 容量 → 期限的产品组织；它不是最新专著章数的依据。
  后续七线复核维持四章专著，也撤销了“所有收益测不准、所有成本风险测得准”的全称主张。
- 093453（作者确认已录用）的构建与调整速度方法可供 03、05、06 设计基准。
  不将防御型权益研究里的 25% 速度设成所有用户默认最优值。
- 093455（作者确认已录用）的规则进入信号测量支持 02；规则敏感性不能直接诊断任意黑箱分数“污染”。
- 093459（作者确认已录用）的信号年龄方法支持 07；先固定信号再测年龄，不能只换未来标签期限。
- STRUCT 支持 08 的价位地板成本代理；模型校准、适用域和观测费用分开显示。
- C1 的可实现性资产支持 02–04；研究中的固定损失比例不是用户策略的损失比例。
- C2 和 M4 分别支持 09 与 10。容量、连续短缺和最早/最晚完成区间分开，不将“可达”写成“保证”。
- B6 和四格实验只吸收预算分解、置换、交互和同口径复验方法。后续撤销的部署命题不恢复为推荐规则。
- P06 和 JEV-like 规划支持受阻状态保留、确定性证据与回放；不移植研究费率、复权价格或未经校准的概率。

## 工程落点与优先级

`audit_catalog.py` 持有有序目录、输入要求、候选动作和边界；`strategy_audit.py` 将本次真实量值填入目录。
报告与证据 JSON 都包含目录。旧版报告只读兼容，展示新目录不会回写历史摘要。

本版已接一档报价地板分量和实际持有期分组。它们不等于完整STRUCT模型、093459信号年龄曲线或093453调整速度历史复验。
日均报价核对也不能建立开收盘竞价的有效成交成本下限；保留“半档情景”口径，不宣称实盘必亏。

后续优先补能产出可核算方案的环节：04 约束与账户候选 → 08 完整费用/STRUCT → 06 调整政策复验 →
11 目标与成交偏离 → 13 分层归因。07、09、10 在数据契约完整后接入。
14 和 15 随每项实施一起建设，不在最后补做。预测训练不属于当前界面和开发主线。
