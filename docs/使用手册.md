# TemperQ 本地量化工作台使用手册

这份手册给没有研发背景的使用者。TemperQ 在自己的电脑上完成数据准备、训练和报告生成，本地训练数据不会上传到平台。第一次使用建议先跑试运行，确认安装、浏览器和训练链路都正常，再使用真实 A 股数据。

## 一、Windows 一键使用

1. 从压缩包中解压出整个 `temperq` 文件夹（现有开发目录 `quant-workbench` 也可继续使用）。不要只复制其中一个 bat 文件。
2. 双击 `install.bat`。安装程序会在当前文件夹创建独立的 Python 3.11 环境，并安装固定版本依赖。第一次安装需要联网，通常需要几分钟。
3. 安装窗口最后出现“安装完成”后，双击 `start.bat`。浏览器会打开 `http://127.0.0.1:8765`。
4. 关闭启动窗口即可停止本地工作台。训练过程中不要关闭它；浏览器页面可以关闭，任务仍会在本机继续。

安装默认使用 CPU 训练 LightGBM，因此 NVIDIA、AMD、核显和没有显卡的电脑都能使用。只有以后安装 Kronos 等需要 PyTorch 的底座时，才需要在安装时选择 GPU 选项；GPU 选项只支持 NVIDIA 驱动对应的 CUDA 版本，AMD 不走这条路径。

如果安装失败，保留窗口中的最后一段错误信息。网络不稳定时重新双击安装即可复用已下载的内容。若提示缺少 Visual C++ 运行库，按窗口提示安装后再次运行安装程序。

## 二、Linux 安装和启动

在终端执行：

```bash
cd /path/to/quant-workbench
sh install.sh
sh start.sh --no-browser
```

服务器只监听 `127.0.0.1`。如果 TemperQ 在远程服务器上运行，在自己的电脑上另开终端做端口转发：

```bash
ssh -N -L 8765:127.0.0.1:8765 user@server
```

然后在本地浏览器打开 `http://127.0.0.1:8765`。需要 GPU 时再运行 `sh install.sh --with-gpu`；默认的 LightGBM 训练不依赖 GPU。Debian/Ubuntu 若提示 LightGBM 缺少运行库，执行 `sudo apt install libgomp1` 后重新启动。

## 三、训练页面

主导航按“训练 → 评价 → 纸面交易 → 模拟持仓”排列。下面四小步只负责第一阶段的训练设置。

### 第 1 步 要打造什么模型：用在哪

先说清楚模型要用在哪里，后面的数据要求和参数都由这一步决定：市场（目前 A 股）、持有期（1 天 / 5 天 / 20 天）、股票池（全 A 股、剔除 ST、只要 ST、沪深 300 / 中证 500 / 中证 1000 成分股、自选名单）、资金量（0–30 万、30–100 万、100–600 万、600 万–1000 万、1000 万–1 亿、1 亿–5 亿、5 亿及以上）、交易方式（只做多）和模型（LightGBM 或 Ridge）。灰色选项是规划中，暂时不能选。资金量决定持股只数和最低成交额：每只仓位不超过该股近 20 日日均成交额的 5%，资金越大，能选的股票越少。指数成分股按每个历史时点当时的成分取。

### 第 2 步 准备数据

可以选择试运行数据、本机已有 TemperQ 数据、上传 CSV，或使用 Tushare 兼容接口下载。

试运行数据只用于熟悉流程，几秒钟完成，结果没有投资含义。

CSV 必须至少有以下列，每行代表一只股票的一天：

| 列 | 含义 | 例子 |
|---|---|---|
| `code` | 股票代码 | `000001` 或 `000001.SZ` |
| `date` | 交易日 | `2024-01-02` |
| `open`、`high`、`low`、`close` | 未复权价格 | `9.39` |
| `amount` | 成交额，单位为元 | `1158366000` |

导入允许缺少 `adj_factor`、`is_st`、`up_limit`、`down_limit`，但强烈建议提供同源复权因子和逐日 ST 标记。没有复权因子会把除权误当收益；没有 `is_st` 时不能可靠剔除 ST，也不能选“只要 ST”。没有涨跌停价时按规则包估算，不能覆盖所有特殊状态。指数池还需历史成分，不能只拿今天的名单回填历史。网页中的“下载模板”可直接保存后填写。

**数据量怎么准备：**建议至少约 3 整年、720 个交易日、30 只以上在同一日期有行情的股票；推荐 5–8 年、数百只起步及较完整的历史股票池，包含后来退市的证券。不要只选现在的赢家。最近 1–2 年用于检验，之前用于滚动训练。公告、财务、自建因子不是基础模型必需输入。

CSV 导入硬条件目前只是至少跨 3 个年份，不能把“跨年”当成“历史充足”。选择数据和上传后会显示范围、股票数、自动训练/检验年份；新 CSV 还检查同时有价格的股票数量和各年原始交易日。已知少于 20 只或检验期过短时，在提交训练前提示补数据。上市年龄、流动性、ST 和标签成熟会继续减少可用样本，初检不替代后续时点和完整性检验。

独立基准每个有效日期至少需 20 只合格股票。默认基准包含最长 40 日块的稳健性检查，至少 160 个有效检验日才能计算该区间；这只是计算条件，不保证显著。5 日任务最后 6 个交易日的标签尚未成熟。更多股票行数不能替代更多独立日期；历史更长也不保证模型赚钱。

Tushare 下载需要能够调用 `daily`、`adj_factor`、`stk_limit`、`suspend_d`、`stock_st` 和 `trade_cal` 的 token。token 只在本次下载内存中使用，不写入配置、数据或日志。全 A 股多年日线下载可能需要约一小时，下载中断后再次提交会复用缓存。

#### 多个数据来源

一份数据可以叠加多个来源，本地 CSV 和 API 可以混用：在第 2 步数据后面点“加更多数据来源”，系统会以原数据为基础新建一份组合数据，原数据保持不变。每添加一个来源，先选它是什么（因子/指标、补充行情、ST 标记），再声明数据可用时间：确实在当日 15:30 决策前可得，或在当日决策后发布、下一交易日决策时使用，也可按公告日顺延。晚间发布的指标不能选当日使用。系统只按用户声明对齐，无法识别供应商倒填、修订历史或未来信息。

因子的数值列默认进入特征；CLI 的 `train.features` 可指定子集进行消融。便捷 CSV 导入单次最多 30 个数值列，大规模特征与自定义模型可在外部框架完成后提交标准预测。补充行情重叠时核对收盘价，口径不一致会拒绝导入。也可从 Tushare 拉取 daily_basic 和 moneyflow，仍须核实各字段实际可用时点。

### 第 3 步 参数（由第 1 步推出）

参数由第 1 步推出，页面会列出“因为你选了什么，所以默认怎样训练”。可以改持股只数和佣金；选 LightGBM 时可改树数量、叶子数、学习率、种子数，选 Ridge 时可改正则强度。改动过的值会列在报告首页，便于复核。最终测试年份会根据数据的最后年份自动选择。

专业配置可在 YAML 中启用 `model.selection`，用每折已成熟历史内的验证区间选择 LightGBM 轮数，再重拟合；固定轮数仍为默认。日期、清除样本与所选轮数会记录。完整示例与能力边界见 [专业研究链路审查](PROFESSIONAL_RESEARCH_AUDIT_20261022.md)。

### 第 4 步 开始训练

点击“开始训练”。网页只负责生成 YAML 和提交本地任务，训练逻辑与命令行完全相同。任务页面会显示状态、进度、日志和结果文件夹；失败时先看“出错信息”，再看完整日志。

## 四、如何读结果

训练报告包含扣成本的简化诊断，以任务持有期、前排持仓和费用假设对比模型与简单参考；它不能替代独立现金/实际保留数量账户。请在“实验记录”冻结协议并运行独立 Bench，查看账户、拒单、估值和数据资格。两者均未模拟真实开盘队列、整数手、最低佣金、冲击和容量，不能当作实盘组合承诺。

随后查看：

- IC、Newey–West 区间及配对 IC 差：分别查看历史信号和相对固定参考的增量，区间描述当前假设下的日期不确定性；
- 多种子相关性和前 10% 重叠：说明结果是否只是随机种子差异；
- 前视检查：截断到历史时点重算特征和股票池，检查是否读到了未来数据；
- 基线和截面打乱：判断模型是否真的超过简单方法和噪声；
- 台账提示：同一测试期被重复评估时，报告会标出重复查看或本次为最好结果。

试运行页面会明确提示“结果只说明流程走通，没有投资含义”。历史信号筛查不能自动执行自然语言 acceptance，也不能校正全部搜索偏差；真实数据中的证据不足和不显著结果应当如实保留，不能只挑好看的记录。

## 五、命令行等价操作

网页保存的配置在 `runs/ui_configs/`。可以用同一配置重跑：

```bash
.venv/bin/python -X utf8 -m qwb.cli run runs/ui_configs/my_first_model.yaml
```

Windows PowerShell：

```powershell
.venv\Scripts\python.exe -X utf8 -m qwb.cli run runs\ui_configs\my_first_model.yaml
```

只检查配置、不开始训练：

```bash
.venv/bin/python -X utf8 -m qwb.cli run runs/ui_configs/my_first_model.yaml --check
```

每次训练归档到 `runs/history/<run_id>/`，成功后更新 `runs/<名称>/` 兼容副本。主要文件是 `report.md`、`metrics.json`、`predictions.parquet`、`data_manifest.json` 和模型文件；失败尝试保留状态。Bench 评价历史折预测，`final_model/` 是供未来推理的另一次重拟合，历史折成绩不能直接证明它的未来表现。完整流程见 [研究闭环说明](RESEARCH_WORKFLOW.md)。

## 六、常见问题

**浏览器打不开。** 确认启动窗口仍在运行，并访问 `127.0.0.1` 而不是电脑名；端口被占用时 TemperQ 会自动选择 8765 之后的可用端口，使用窗口打印出的地址。

**显卡不同导致不能运行。** 首版 LightGBM 训练固定走 CPU，不依赖显卡。不要为了 LightGBM 安装大体积 PyTorch；只有明确使用 Kronos 时才安装 GPU 选项。

**CSV 导入提示成交额单位不对。** Tushare 的 `amount` 通常是千元，导入前请先换算成元；`vol` 不是本模板需要的成交额列。

**内存不足。** 先用试运行确认流程，再使用较小 CSV 或较少股票；全市场多年日线需要更多内存。网页首页会显示本机内存并给出提示。

**扣成本检验缺失。** 确认项目内有 `third_party/ashare-tcost/pyproject.toml`，并重新运行安装器。源码开发环境可执行 `uv pip install --python .venv/Scripts/python.exe --no-deps -e third_party/ashare-tcost`（Linux 使用 `.venv/bin/python`）。

**停止任务。** 在任务页面点击“取消”。取消发生在当前训练单元结束后，已经写出的日志和中间文件会保留。

## 七、数据与安全边界

TemperQ 默认只监听本机，不接受外部 Host 的提交请求；网页提交还需要本次进程生成的令牌。token、原始数据和训练结果不上传。不要把含有 Tushare token 的配置文件或本地数据目录上传到公共仓库。

TemperQ 是研究和复现实验工具，不提供荐股、收益承诺或自动实盘交易功能。

## 八、评价、纸面交易与模拟持仓

1. **评价**：训练结束点击“下一步：评价模型”，或在训练页底部、导航“评价”选择模型。“跑基准”使用同一数据和任务的固定协议；没有可匹配协议的真实 LightGBM 模型可建立一个。Ridge 需要同任务的 LightGBM 参考。报告显示“可进入纸面验证”或“证据不足”，两者都不代表允许实盘。
2. **迭代**：在模型页修改参数后点击“继续训练 · 创建新版本”。这是完整重训，不是断点续训或增量微调；旧模型保留。删除只从常用列表移除，可在“查看已删除模型并恢复”找回，不删除历史证据或纸面账户。
3. **纸面交易**：跑完基准后创建账户，只填虚拟资金、账户名和对应的每日行情目录。默认开启每日 17:30 后检查一次；本地工作台必须保持运行。关闭/注销时不会记账；错过的记录不冒充及时前向。已有 API 每日任务的账户会先更新行情；其余账户需要持续导入对应 CSV。可在账户页暂停自动记账、手动更新、查看净值、持仓、费用与成交。数据过期会等待或受阻，不代表模型正在产生收益。证据不足时只能作为观察。
4. **模拟持仓**：在纸面账户页点击“输入真实仓位 · 模拟建议”，或从导航“模拟持仓”选择前向账户。填写真实现金、计划执行日，上传持仓 CSV；空仓可不上传。此步骤使用该纸面账户冻结的模型和行情，不修改账本，不向券商下单。模板如下：

```csv
code,quantity,sellable_quantity
000001.SZ,100,100
688001.SH,201,201
```

`sellable_quantity` 是你确认的本次计划执行时可卖股数，不能大于持仓；不要把预计买入当成已有持仓。输出中的增减数量按参考价估算，不是下单或成交。原模型页仍是参考选股清单；账户建议才读取你的现金和持仓。

支持主板/创业板 100 股买入，科创板 200 股起、之后每股递增，按规则一次卖出剩余零股。最低佣金每笔 5 元，佣金单边 3 bp，印花税按日期收取。首版模拟未计价差、冲击等完整成本，不能把它当成真实净收益。公司行动、北交所和特殊订单不支持；请勿确认不存在这些事项后又提交相关账户。

建议页可下载 CSV 与冻结配置，并返回原纸面账户查看运行。模型复制后固定，不随原模型重训而替换；默认每 5 个交易日再平衡，未成交开盘指令当次到期，不自动持续挂单。真实前向首版仅支持 5 日、次日开盘到第 6 日开盘的任务；合成模型仅作试运行，不能启用真实前向账户。

“更新日线数据”上传日线与交易日历 CSV，保存成一个新的不可变快照；旧快照保留。每日更新需要 `adj_factor`，停牌写 `state=suspended`。日历格式为 `date,is_open`，开市为 1、休市为 0，覆盖已有数据及下个交易日。只允许末尾追加；历史修订、字段或股票集合变化需另建数据源。更新后在模拟账户点击“更新记账”，不需要重训。

后续更新使用训练时的同一数据名称，模型建议和模拟账户会跟随该数据源的新快照。原来绑定独立目录的旧模型仍读取原目录；需接入追加数据源时，在创建新账户时通过 `qwb paper init ... --data-dir data/my_feed` 明确绑定。保持原来的完整股票集合，不要把全市场模型直接接到 40 只示例股票上，横截面特征会因此改变。模型、配置或执行代码升级后，首版会停止已有冻结账户，保留旧记录并要求另建账户。

CLI 使用同一引擎：

```powershell
temperq paper advice runs/my_model --cash 100000 --holdings examples/holdings.csv --execution-day 2026-10-26
temperq paper init my_account runs/my_model --cash 100000
temperq paper tick my_account
temperq paper show my_account
temperq paper update-data data/my_feed daily.csv --calendar calendar.csv
```

Windows 全市场每日任务：`powershell -File scripts/install_paper_task.ps1 -Python .venv/Scripts/python.exe -Account my_account`，默认当前用户登录时每天 17:30 执行下载和记账；账户需按下一节绑定 API 数据源。已有任务需加 `-Replace`，先备份旧任务再更新。Linux 定时示例见 [paper-ledger.cron.example](../deploy/paper-ledger.cron.example)，服务器时区设为 Asia/Shanghai。缺新行情、日历或遇到不支持事件时，页面显示等待/停止，不会生成虚假成交。账户页显示最近任务、已核验行情截止日和漏记日期；历史演示与晚到数据补记独立标识，不算真实按日提前记录。关机或注销期间不会运行；开机补跑也不会把错过的交易日标成真实前向。

## 九、零成本数据路径

不要求 Tushare token 或积分的可选路径是 [BaoStock](http://www.baostock.com/) 日线。先装扩展，再抓取示例自选股票的数据：

```powershell
uv pip install --python .venv/Scripts/python.exe baostock==0.8.9
.venv/Scripts/python.exe scripts/fetch_free_daily.py --feed data/free_daily
```

Linux 将 Python 路径替换为 `.venv/bin/python`。成功后该数据会出现在训练页；选择 LightGBM、5 日和剔除 ST 即可。名单在 [free_daily_codes.csv](../examples/free_daily_codes.csv)，是演示自选名单，不是历史指数成分，也不代表投资推荐。脚本获取未复权日线、后复权因子、ST 状态和交易日历；再次运行只追加新日期，不改旧快照。

免费接口可能超时或限流；2026-10-23 本机直连 BaoStock 超时，完整联网下载尚未验收，不能承诺十分钟完成。失败不会覆盖已有数据；也可从获授权来源取得相同格式的 CSV，用网页导入。AKShare 格式通常仍需核对字段、未复权价格与成交额单位，不能直接把任意导出文件当成已验证数据。

后续用户试用单独记录：是否需要注册/token/积分、能否拿到数据、下载耗时/失败原因、是否需要人工转换、首份报告耗时。“装好程序”与“拿到可用数据”分别验收。

## 十、已有 API 的真实数据测试

已有兼容 Tushare 的 API 可以用于本机测试。`config.local.yaml` 的 `tushare.url`、`tushare.token_file` 指定接口与凭据文件，`data_dir` 指向已有历史快照；凭据不会复制到运行配置或报告。以下路径可自行替换，所有行情仍保存在 E 盘：

```powershell
.venv/Scripts/python.exe -X utf8 scripts/fetch_api_daily.py --feed E:/data/qwb_api_test_40 --end 2026-10-22
.venv/Scripts/python.exe -X utf8 scripts/test_api_daily_workflow.py --source-feed E:/data/qwb_api_test_40 --strategy-feed E:/data/qwb_api_strategy_test_40
```
