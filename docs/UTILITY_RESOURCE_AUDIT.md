# 效用训练资源实测

这是 [接续 SPEC R03](specs/NEXT_ITERATION_SPEC.md) 的资源证据工具，不是模型效果比较或可支持容量认证。脚本 `scripts/run_utility_resource_audit.py` 使用真实预测预训练归档和原生 GRU 净效用训练，逐场景启动新进程，按固定顺序运行，保留失败及未运行场景。

## 运行

在已安装 [锁定 CPU 研究环境](E2E_IMPLEMENTATION.md) 的项目根目录运行；输出目录必须不存在：

```powershell
artifacts/environments/e2e-clean/Scripts/python.exe scripts/run_utility_resource_audit.py --output artifacts/utility-resource-new --assets 24 64 128 --steps 3 12 --detach full 2 --repeats 2 --epochs 1 --max-seconds 120 --wall-seconds 180
artifacts/environments/e2e-clean/Scripts/python.exe scripts/run_utility_resource_audit.py --verify artifacts/utility-resource-new
```

`full` 表示不截断；整数表示 `detach_every`。参数必须无歧义、唯一、正数，墙钟预算须大于 fit 预算。默认矩阵有 24 个真实效用 fit：三个资产数 × 两种训练 episode 长度 × 两种截断 × 两次重复。重复的 seed 固定为 0，目的是观察软件和资源重复性，不把重复当作独立市场样本。

每种资产数先独立生成 CC0 合成数据，并通过共享 pipeline 训练一个一轮、hidden_size=8 的预测 GRU。其 fold 0/seed 0 归档经 `experiments.verify` 和 `DecisionGRU.from_run` 核验后，供该资产数的所有场景共用。观察为 60 日窗口、至少 20 日历史；不得伪造“已训练”checkpoint 或手动设置收益头来制造成交/梯度。

预测选择截止不晚于效用首次训练决策；训练从 calendar[80] 开始，内层验证共三步、起点固定在最长训练 episode 之后。每组声明独立的初始账户并保留已有持仓；不同场景不是可拼接的交易路径。原风险/成本、生产映射、资金/费用/交收与市场限制均由现有实现处理。训练目标、原选模规则和代理资格不因资源诊断改变。

## 冻结与归档

| 产物 | 含义 |
| --- | --- |
| `intent.json` | 在预训练前固定矩阵、核心/脚本身份、环境、线程与预算 |
| `preparation.json`、`sources/` | 每个资产池的预训练状态、真实预测归档、数据身份、日志和子进程测量 |
| `plan.json` | 在效用测量前追加已准备的源归档身份，不事后修改场景 |
| `attempts.json`、`cases/` | 全部声明场景；每个场景的任务、协议、训练输入、历史、checkpoint、子进程报告和日志 |
| `result.json`、`report.md` | 每组全部声明数量、成功/失败/超时/未运行数量，成功条件下的资源范围及重复参数一致性 |
| `checksums.json` | 文件内容库存；普通库存校验不等于重跑训练或硬件计时认证 |

Windows 子进程通过 `taskkill /PID <本工具启动的进程> /T /F` 终止整棵进程树并等待回收，覆盖虚拟环境启动器和下层解释器；POSIX 使用独立进程组。Windows 有真实嵌套解释器的超时回归；这不能代替 Linux 实测。子报告记录实际 PID/父 PID、Torch 线程与环境线程设置。所有子进程顺序运行；工具不提供机器独占、内存配额或 GPU 隔离。

## 时间与内存

- `wall_elapsed_seconds`：父进程从启动到子进程终止的墙钟时间，包含解释器/依赖导入、源加载、fit 和保存等开销。
- `elapsed_inside_child_seconds`：进入子任务到测量完成的时间，不包含此前解释器和模块导入。
- `fit.elapsed_seconds`：既有 fit 定义的训练耗时；不冒充整个场景耗时。
- `baseline_process_memory`：开始 fit 前进程已经达到的 RSS 高水位，包括导入、数据和模型加载。
- `fit.memory`：fit 内记录的进程 RSS 高水位。
- `memory.peak_rss_bytes`：子任务结束时整个进程的 RSS 高水位，包含保存/重载；不是独占增量内存，不对两次高水位相减称“训练内存”。

每组报告成功测量的 min/median/max，并明确这是成功条件下的统计；失败、超时和未运行继续计入所有声明场景分母。没有成功测量时范围为 null。超时/进程异常可能无法获得最终内存，不能填 0，也不能用别的场景替代。重复权重按实际重载 Tensor 精确比较，元信息中的时间/RSS不要求相同。

`detach_every=K` 只截断账户状态的梯度路径，当前每 epoch 仍汇总后一次反传。即使某个 K 的实测峰值较低，也不能推出内存随 K 有界；资产数、episode 长度、求解活跃集和依赖导入均可能影响结果。不同机器、配置、未测规模及并发训练须另测。

## 失败与验证

预训练失败时该资产数所有依赖场景保留为 not_run。fit 时间预算、求解、生产映射或非有限梯度错误保留失败及原生训练上下文；父进程墙钟超时终止子进程树。任何失败都不被替换为全现金成功，不仅汇总成功子集，不自动扩预算重试。中断仅保留进度，不支持中途恢复；重跑使用新目录。

`--verify` 检查冻结矩阵/覆盖率、内容库存、真实预训练数据和源归档、各场景协议/输入、checkpoint/训练记录、线程与时间/内存单位关系，以及汇总算术。删除声明场景、修改汇总并重哈希仍会被拒绝。验证不重新训练，也不保证存储的计时未被全链条伪造；有需要时从冻结配置在独立机器重新运行并比较。

当前测试与正式测量身份、结果及限制见 [验证记录](VALIDATION.md) 和 [N03 阶段矩阵](specs/N03_STAGE_AUDIT_20261023.md)。资源通过不提升市场效用、代理一致性或服务器部署状态。

## R04-D 开发期动作敏感度诊断

`artifacts/r04-d-diagnostic-20261023-001.json` 是在该历史资源矩阵上追加的开发期诊断。脚本 `artifacts/diagnose_r04_d.py` 固定 64/128 资产的源 checkpoint、账户、风险/成本 recipe、优化器和生产映射，重新运行 3 步训练协议，并对预测值加入 `±1e-4`、`±1e-3` 十进制收益偏移，记录第一决策的原始/生产权重变化和完整 episode 的净收益/成本变化。

诊断显示 64 资产首日 61/64、128 资产 125/128 的原始权重贴近下界，预算使用约 28.3%，预算和上界未激活。`±1e-4` 偏移的首日权重 L1 变化约 `1e-10`（128 资产约 `8e-9`），而 `+1e-3` 偏移出现约 `0.34/0.68` 的 L1 跳变。这与资源矩阵观察到的极小梯度相符，说明活跃集和数值尺度需要单独诊断；该结果不是模型效果结论，也不支持把微小梯度称为有效学习。

该脚本使用历史核心身份，不能代表 ADR 011 当前核心的新测量。下一步要在冻结研究设置前增加方向向量、分母接近零、solver tolerance 和边界分支对照；不通过调高成本、放松约束或强制交易来制造梯度。
