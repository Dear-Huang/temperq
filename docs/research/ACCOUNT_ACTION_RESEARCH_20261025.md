# 从选股训练到已有账户的调整训练：窄域研究与原型

日期：2026-10-25。状态：研究假设；离线回放原型已实现，尚无真实市场收益证据。本文不修改产品定位、主导航或既有账户。

## 1. 建议

首个窄域服务：**已经持有股票、有自己的纪律，也愿意参考模型，但不想把账户推倒重来的个人用户。**

要回答的具体问题是：“模型推荐换仓，但对我的账户，这次调整值得做吗？不动、小调、按模型调整，分别付出什么？”

产品仍然是开源可视化量化训练平台。研究增量是改变训练的对象：在现有股票预测模型之上，训练账户条件下的候选调整排序；把“不动”保留为正式候选。股票涨幅排名高，不自动等于现在值得卖掉已有持仓去买它。

这不是已验证的新算法，也不能声称其他平台没有此能力。我们争取把账户状态、真实交易约束、候选调整、净增量标签和前向记录做成普通用户能连续使用的训练流程。首轮只验证其中的标签与回放环节。

## 2. 痛点证据与竞品边界

本轮依据公开问题、官方文档和论文；没有完成用户访谈，也没有证明需求规模。单个旧 issue 不能证明现版本仍有该缺陷。

| 来源 | 可核实内容 | 对本方向的含义与限制 |
| --- | --- | --- |
| [Qlib #1695，2023-11](https://github.com/microsoft/qlib/issues/1695) | 用户希望权重体现自己的偏好，而非仅依照模型得分等权 | 有真实的“我的账户观念”诉求；不等于 Qlib 不支持自定义权重 |
| [Qlib #1741，2024-01](https://github.com/microsoft/qlib/issues/1741) | 分钟回测用户反馈高换手成本，以及总持仓/可卖持仓区别 | 执行规则可能改变模型结果；这是分钟频个案，不能外推到所有 Qlib 回测 |
| [QuantConnect 官方 Reconciliation](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/reconciliation) | 现有持仓会进入实盘曲线而不进入默认回测曲线；文档建议空账户/子账户避免差异 | “从现有账户开始”确实需要专门处理；文档不是说现有持仓无法支持 |
| [cvxportfolio 约束文档](https://www.cvxportfolio.com/en/stable/constraints.html) | 已有持仓上限、交易上限、参与率、换手约束等 | 约束优化不是我们的独创，也不是成熟平台的空白 |

| [cvxportfolio #194，2025-05](https://github.com/cvxgrp/cvxportfolio/issues/194) | 用户自带预测及短历史风险模型遇到优化问题 | 集成门槛确实存在，但不能据此断言优化器普遍不可靠 |

取舍：

| 候选方向 | 判断 |
| --- | --- |
| 增加特征、优化器、模型数量 | 是基础能力建设；单人维护不宜把数量作为差异化 |
| 通用训练失败诊断助手 | 仍有产品价值，但容易回到“加特征、改参数再跑”；不是本轮首个研究问题 |
| 通用回测到实盘对账平台 | 问题真实，但范围大，成熟平台投入很深；当前不连接券商也限制验证 |
| 已有账户的有限调整训练 | 与重治理定位一致，可复用现有账本；能先从很小、可复算的动作集开始。建议先验证 |

| Sharma et al., [Decision-Point Guided Safe Policy Improvement](https://arxiv.org/abs/2410.09361), 2024 预印本 | 只在数据有支持的局部决策点修改，其余沿用既定策略 | 离线 RL 的安全结论不能直接套到金融历史回放；现阶段不采用“安全改善”宣传 |
| Schutte et al., [Robust Losses for Decision-Focused Learning](https://arxiv.org/abs/2310.04328) | 提醒事后最优动作与期望最优不同；需要处理结果噪声 | 本轮仅核对摘要，不作为已复现或已实现方法 |

前两篇与局部策略改进论文已读取全文；作者排序学习仓库 README 已核对。这里采用的是研究思路，不复制其项目代码。不能因某篇论文更新就判断它更适合当前数据。

与本仓库已有 B2 的关系：B2 已研究可微分配置与效用目标。这里先用现有执行器给有限动作计算精确账务标签，再学习动作价值，避免首轮把离散整手和最低佣金近似成可微函数。它仍受行情、冲击和执行模型限制，不天然优于 B2。

## 4. 最小用户体验

已有模型或导入预测 → 导入当前持仓 → 确认现金底线、不可卖股票和调整预算 → 看到少量候选调整 → 开影子跟踪。

默认只呈现“保持原样 / 小幅调整 / 按模型调整”，每项显示预计交易、费用和约束。用户只需比较结果；高级用户可更换信号、动作生成规则、风险目标和模型引擎。

如果没有证据支持改变，输出“继续现有政策”，并记录为什么。用户仍可观察信号是否兑现、费用是否降低、建议是否可执行；无需不停重新训练追逐回测。但这些过程价值也需要真实用户验证，不能假定“不交易”足以留住用户。

本轮不新增主页面，不用收益评分吸引用户，也不降低已有证据标准。历史结果与当时可得建议必须分开显示。

## 5. 可验证的训练问题

一条样本不再只是“日期、股票、未来收益”，而是：

`决策日可见信息 + 真实账户状态 + 冻结候选动作 → 相对既定政策的事后模拟净增量`

账户状态包括现金、每只持仓、可卖数量、结算锁定和估值时间；上下文还应带预测版本、信号时点、约束和成本版本。候选动作在未来行情揭示前产生，不能事后挑当天涨得好的股票加入候选。

首轮标签：`动作执行后净值 − 同一初始账户执行基线后的净值`。同时保留交易额、费用、实际仓位、未成交原因、约束违例及数据缺失。收益以外的用户目标以后通过明确、冻结的目标函数进入；不临时拼成一个漂亮总分。

基线可以是不动，也可以是用户原有政策。若强制风险规则要求调整，不能把违规的不动当作可部署默认。限售等限制导致实际账户越界时，保留回放事实，但不输出合格训练标签。

这些是模型假设下的模拟反事实，不是因果识别；没有实际观察到所有备选交易。单期标签不能证明多期策略价值。当前回放只覆盖下一交易日开盘到收盘；真正训练前要固定匹配信号的评价期限，并加入多日状态演进。

## 6. 本轮已实现的原型

- `src/qwb/account_rehearsal.py`：不可变计划、显式不动候选、可指定基线、同一账户的独立回放、净增量标签与完整执行审计。
- `scripts/rehearse_account_actions.py`：小账户、大账户、T+1 锁定账户的可复算合成案例。
- `tests/test_account_rehearsal.py`：手算费用、账户依赖、时点身份、锁仓、缺行情、约束违例、基线及候选顺序独立性。

复用现有 `AccountState`、`TargetWeights` 和 `execute_session`。没有修改冻结执行器或已有账户，也未训练或部署动作模型。

运行：

```powershell
& artifacts/environments/e2e-clean/Scripts/python.exe scripts/rehearse_account_actions.py --output artifacts/narrow-domain-research-20261025/account_rehearsal.json
& artifacts/environments/e2e-clean/Scripts/python.exe -m pytest tests/test_account_rehearsal.py tests/test_portfolio_reference.py tests/test_portfolio_contracts.py -q
```

合成条件：原有 A 半仓，现金半仓；次日 A 不涨，B 涨 0.2%；替换半仓；佣金 3bp、最低 5 元，卖出印花税依日期计算。

| 账户总资产 | 保持原样净增量 | 全部替换原有半仓净增量 | 替换费用 |
| --- | --- | --- | --- |
| 1 万元 | 0 元 | -2.50 元 | 12.50 元 |
| 100 万元 | 0 元 | +450 元 | 550 元 |

这只说明“同一股票信号在不同账户中的动作价值不同”。它不是抽样市场实验，也不说明我们能事前识别正收益动作。T+1 情形中，卖出受阻但买入仍可能发生，必须检查实际仓位；不能把提高敞口的收益解释为换仓能力。

计划摘要包含账户、候选目标、费用和协议身份，行情单独记录摘要。摘要不是可信时间戳，不能证明计划确实在市场发生前保存；真实流水线还需只读快照和时点来源审计。

原型限制：仅 v1 原始股数账户、单期、开盘价成交代理、没有公司行动和现有挂单、不含 STRUCT 冲击成本、未匹配敞口。不能直接用于实盘，也不能直接把这些标签当作完成品训练集。

## 7. 下一阶段的工程实验与停止条件

1. **先验证需求**：给至少 3 名确有持仓的目标用户看同一账户的候选调整与费用，而非只问“想不想要”。记录他们是否用它做真实取舍、是否愿意继续看一周。若问题并不困扰他们，停止扩建此方向。
2. **生成有来源的训练集**：冻结信号、候选生成器、用户规则、评价期限和成本。用生命周期账本处理复权/公司行动；接入 STRUCT。每个历史账户状态只来自该政策自己的过去；禁止把事后最佳账户状态当作所有策略共同起点。
3. **先跑简单门槛，再训练**：基线是不动、用户既定政策、信号 Top-k，以及固定成本/排名差门槛。先用成熟 Ridge 或 LightGBM 学习相对动作价值，不上 RL、不新增模型平台。若简单门槛已解决问题，先交付它。
4. **真正留出评价**：按时间滚动训练、purge 重叠标签，按日期聚类比较；同日多个模拟账户不是独立证据。留出账户配置/资金档位，记录全部尝试。训练集、验证集和最终检验集不可循环调参。
5. **独立闭环**：每种政策分别演进现金、持仓、T+1；报告多期净增量、换手、费用、风险违例、尾部损失和不动作比例。补实际平均仓位对照和稳态分析，区分收益、少交易和少持仓的来源。
6. **是否进入产品**：先看时间留出下能否超过最简单动作门槛、压力成本下能否保留价值，再看影子账户。若只降低换手而收益不明确，就只报告成本价值；若效果不稳定，则保留诊断器，停止包装为训练优势。

自己的增量应落在可复用的账户动作样本契约、可审计的配对评价、有限修改的用户流程和持续积累的前向动作记录上。是否有学术新颖性、是否有市场需求、是否改善收益，是三个独立问题，都尚未完成验证。
