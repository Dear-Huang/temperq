# 实务证据、来源边界与 TemperQ 动作定价契约

日期：2026-10-27。主结论见 [07_从诊断到改法与经济代价.md](07_从诊断到改法与经济代价.md)。本文件将公开事实与产品建议分开。GitHub issue 是有上下文的使用反馈，不能当作独立实盘绩效验证。

## 1. 文献与实务证据账

### E01：成本缓解确实给出了可执行规则和经济对照

- 来源：Novy-Marx–Velikov，NBER 2014 工作论文，DOI [10.3386/w20721](https://doi.org/10.3386/w20721)，[全文](https://www.nber.org/system/files/working_papers/w20721/w20721.pdf)。后续期刊版 DOI [10.1093/rfs/hhv063](https://doi.org/10.1093/rfs/hhv063)。
- 已读：第 5.3 节、Tables 2/3/5/8；Table 3 与 8 截图分别为 [PDF 21 页](evidence/actionability/taxonomy_page_21.png)、[PDF 34 页](evidence/actionability/taxonomy_page_34.png)，Table 5 为 [PDF 26 页](evidence/actionability/taxonomy_page_26.png)。
- 动作：买入比继续持有要求更严格；保持近似暴露但减少边界来回交易。文献的排名门槛与仓位权重容忍带是相关但不同的机制，应分别实现与标注。
- 经济证据：工作论文历史多空策略的毛 / 成本 / 净结果；不是用户未来获利，也不是本轮独立复现。原表与派生差记录在 [empirical_case_checks.json](evidence/actionability/empirical_case_checks.json)。
- 成本范围：第 2 节的 Hasbrouck 有效买卖价差估计明确未计大额交易价格冲击，定位于小规模流动性需求者；不能据此声称完成大资金容量或全成本验证。
- 后续文献：*Comparing Cost-Mitigation Techniques*，DOI [10.1080/0015198X.2018.1547057](https://doi.org/10.1080/0015198X.2018.1547057)。本轮只用已取得摘要支持方法方向，不移植未核对的表数。

### E02：动态交易有数学处方，处方依赖输入

- 来源：Gârleanu–Pedersen，DOI [10.1111/jofi.12080](https://doi.org/10.1111/jofi.12080)。本轮补充检索元数据见 [actionsearch3.json](evidence/actionability/actionsearch3.json)，与上一轮理论来源合读。
- 能做：把交易速度、信号衰减、风险与成本联系起来；目标包含未来机会，不能只看今天排名。
- 使用限制：不是“对所有策略慢慢调仓一定更好”；没有历史信号、衰减估计、风险和成本参数时，不存在已校准的用户最优调整比例。实际持有期也不等于信号寿命。

### E03：cvxportfolio 给交易向量，示范回测不等于部署增益

- 理论：Boyd 等，DOI [10.1561/2400000023](https://doi.org/10.1561/2400000023)。全文快照在 `evidence/cvx_paper.pdf` 与 `.txt`。
- 第 7.4 节短引："this is clearly not a practical forecast, since it uses the realized return"。这是作者对该节模拟预测的说明，不能扩张为整套方法无效，也不能把该节结果视为真实预测能力。
- [当前 market-neutral 示例](https://www.cvxportfolio.com/en/stable/examples/market_neutral.html) 说明超参数最大化回测 Sharpe "for illustrative purposes only"。快照：[cvx_mkt_neutral.txt](evidence/actionability/cvx_mkt_neutral.txt)。
- [用户预测接口](https://www.cvxportfolio.com/en/stable/examples/user_provided_forecasters.html) 与 [简单政策](https://www.cvxportfolio.com/en/stable/simple_policies.html) 可作为接入参考。预测、风险与成本既进入目标，也需要在独立执行仿真与外样本评估。
- 仓库的日更权重与初始持仓记录提供时间线，但没有自动证明券商成交、真实滑点或实盘利润。

### E04：真实讨论明确区分“能求解”和“有经济收益”

- [cvxportfolio issue #194](https://github.com/cvxgrp/cvxportfolio/issues/194)。两段核心回复已核对，未执行用户附带脚本。
- [2025-06-01 维护者诊断](https://github.com/cvxgrp/cvxportfolio/issues/194#issuecomment-2927246417)：约 300 期历史、约 4,000 个资产，缺失收益填零；建议保留系统可处理的 NaN、补足数据；换 `DiagonalCovariance` 后脚本可运行。
- [2025-06-02 回复](https://github.com/cvxgrp/cvxportfolio/issues/194#issuecomment-2929039967)："Performance in terms of PnL is a whole other issue"；优化形式取决于信号与约束，没有数学上唯一“正确”的配置。
- 能据此建议：先检查数据覆盖、协方差维度与缺失处理，再检查求解状态和风险模型。不能据此声称对角模型经济上优于因子模型。
- 邻近案例：[issue #185](https://github.com/cvxgrp/cvxportfolio/issues/185) 区分数学不可行/无界状态与数值 SolverError；不能把换 solver 当成修复所有不可行问题。[issue #151](https://github.com/cvxgrp/cvxportfolio/issues/151) 的自动放宽约束是功能请求，不是已实现能力。
- 原始评论存于 `evidence/actionability/cvx_194_comments.json` 等；公共邮件脚注的订阅认证链接已脱敏，不作为研究材料传播。

### E05：pysystemtrade 的实际执行与缓冲代码

仓库现址：[pst-group/pysystemtrade](https://github.com/pst-group/pysystemtrade)，默认分支 `develop`，采集时许可证 GPL-3.0。使用机制与复制代码是不同决策；接入前重新审查许可。固定提交为 `164328bd76d2937d3dd61491377704c488283bc2`；各文件 blob 与链接记录在 [carver_code_manifest.json](evidence/actionability/carver_code_manifest.json)。

| 已读文件 | 明确行为 | 对 TemperQ 的意义 |
|---|---|---|
| [执行策略](https://github.com/pst-group/pysystemtrade/blob/164328bd76d2937d3dd61491377704c488283bc2/sysexecution/strategies/classic_buffered_positions.py) | 以实际持仓计算差；带内不动；越界调到最近上下界；有合约数量舍入 | 输出真实可执行数量；将“回中心/回边界”作为两种政策 |
| [动态优化](https://github.com/pst-group/pysystemtrade/blob/164328bd76d2937d3dd61491377704c488283bc2/systems/provided/dynamic_small_system_optimise/optimisation.py) | `tracking_error + trade_costs + constraint_function_value`；成本乘 `trade_shadow_cost` | 目标是有惩罚权重的权衡，下降量不能直接标成人民币收益 |
| [调整缓冲](https://github.com/pst-group/pysystemtrade/blob/164328bd76d2937d3dd61491377704c488283bc2/systems/provided/dynamic_small_system_optimise/buffering.py) | 根据 tracking error 与缓冲缩小交易，再对合约数量取整 | 整数化与交易缩放后仍需核查最终约束 |
| [贪心算法](https://github.com/pst-group/pysystemtrade/blob/164328bd76d2937d3dd61491377704c488283bc2/systems/provided/dynamic_small_system_optimise/greedy_algo.py) | 搜索离散合约步长 | 可生成候选，不应默认全局最优 |

- [issue #1417](https://github.com/pst-group/pysystemtrade/issues/1417) 转引生产实践：使用实际当前仓位，而非回测以为昨日应有的仓位。这适用于今日决策；长期政策比较仍要让每条政策独立演进，不能反复重置到原账户。
- 以上证明存在具体实现与生产适配考虑，没有提供可归因的实盘收益增量数字。

### E06：缓冲与强制约束之间的争议必须保留

- [issue #1656](https://github.com/pst-group/pysystemtrade/issues/1656)，2026-09-11 创建，采集时开放。报告者认为后置缓冲可能不立即满足新仓位上限或平仓覆盖；其中数值是说明性例子，不是已发生订单或损失。
- [同日评论](https://github.com/pst-group/pysystemtrade/issues/1656#issuecomment-5637916377) 认为它也可能是合理的速度限制：理想目标受约束，但不必急于交易。
- [2026-09-29 评论](https://github.com/pst-group/pysystemtrade/issues/1656#issuecomment-5886019020) 指出还有其他立即平仓功能，担心增加动态优化复杂度。
- 产品推论：把 `hard_limit / soft_target / emergency_exit` 写进规则和优先级。不能称该 issue 已证实某机构风控失效，也不能从示例推算罚款或未来事故概率。

### E07：一次性成本和每期收益容易被错误混算

- [skfolio Transaction Costs 官方教程](https://skfolio.org/auto_examples/mean_risk/plot_6_transaction_costs.html)，快照 [skfolio_costs.txt](evidence/actionability/skfolio_costs.txt)。
- 已核对：优化需提供 previous weights；一次性交易成本与每期预期收益的时间口径必须按预期持有期限协调，优化问题本身没有隐含持有期限。
- 教程演示将成本纳入训练与仅在评估扣成本的区别；这说明操作路径，但不足以给 TemperQ 用户估算收益增量。本报告不引用教程图形为通用实证改善。
- 产品推论：收益预测、成本、风险各字段写清单位和期限；不能把排名当收益率，不能把成本罚项当现金利润。会计账本仍在实际收费时扣一次现金，不因优化期限摊销而改账。

### E08：成熟执行框架也先解决可实施性

- [QuantConnect Position Sizing 官方文档](https://www.quantconnect.com/docs/v2/writing-algorithms/trading-and-orders/position-sizing)，快照 [lean_min_orders.txt](evidence/actionability/lean_min_orders.txt)。
- 文档包含费用与 lot size 调整数量、先减仓再增仓、小额订单门槛，以及默认 0.25% 的购买力现金缓冲。该数字是该框架默认规则，不是 A 股最优现金比例。
- 产品推论：整手、最低佣金、现金缓冲和目标偏离一起比较。不能以拒单数下降为唯一优化目标，因为它可能通过降低交易和增加闲置现金实现。

### E09：TCA 可以指出钱花在哪，不能自动指出全额可省

- [cuemacro/tcapy](https://github.com/cuemacro/tcapy)，README 快照 [tcapy_readme.txt](evidence/actionability/tcapy_readme.txt)。
- 实际能力：接入订单、成交与 tick 数据，比较 arrival/mid/TWAP/VWAP，按流动性提供方、方式与异常点分析执行。工具以 FX 数据适配为主，A 股需另做交易制度与数据适配。
- 理论：Perold 的 implementation shortfall，DOI [10.3905/jpm.1988.409150](https://doi.org/10.3905/jpm.1988.409150)；执行成本—风险理论见 DOI [10.21314/jor.2001.041](https://doi.org/10.21314/jor.2001.041)。
- 产品推论：经纪商/时段/算法的历史差可能来自订单大小、流动性、信号强弱和紧急度。先在可比任务中配对或分层，再形成可前瞻验证的路由/参与率动作。未取得可靠识别前，shortfall 只叫基准差额。
- README 的行业花费营销量级未独立验证，本报告未拿来算用户节省额。

## 2. 一条完整动作建议需要哪些字段

以下为拟议契约，**尚未实现**。不以虚构账户数字作示例。

| 字段组 | 最少信息 | 防止的误导 |
|---|---|---|
| 比较身份 | 原政策、候选政策、共同初始账户、规则/信号/数据版本、信息截止点 | 偷换策略、时间或约束 |
| 动作 | 买卖/不动/分批/等待的量与触发条件；有效期限；失效与回退条件 | 只有“应该降低换手”的抽象建议 |
| 可实施性 | 现金、整手、T+1、停牌涨跌停、锁仓、硬风险限制；求解状态和 gap | 理论权重不可成交 |
| 经济拆分 | 毛结果差、各项成本差、净差、终点现金、过渡费用是否已含 | 用省费冒充净收益；双重扣费 |
| 代价 | 暴露/跟踪偏离、风险变化、未完成目标、价格风险期限 | 把保守方案描述为免费改善 |
| 证据类型 | 已发生会计 / 当前计划情景 / 历史回放 / 事前模型 / 前瞻纸面 / 实际成交 | 模拟与真实混为一谈 |
| 不确定性 | 配对区间、覆盖率、预声明成本与预测情景；不确定项来源 | 无区间的精确“损失额” |
| 价值阈值 | 至多能承受多少毛收益牺牲；费用/衰减/规模超过何值结论反转 | 预测不足时强填预期收益 |
| 结论与留档 | 采用 / 维持 / 强制修复 / 待补数据；理由与观察期 | 平台必须挑赢家、必须要求改 |

`unknown` 与数值零必须分别存储。模型情景的最差结果只表示该组假设下的下界，不能叫真实世界保证收益下界。硬性违规修复可以是规则要求，但不应凭此冒充收益优化。

## 3. 优先落地的四类动作卡

| 诊断触发 | 具体候选 | 如何估计“不改代价” | 核心缺失数据 / 验收 |
|---|---|---|---|
| 临界排名频繁替换、费用侵蚀明显 | 买入/持有双门槛；回中心 vs 回带边界 | 原政策与候选的历史净差；同时列成本节省与毛收益牺牲 | 需要时点全候选信号；只凭成交不能重建。两政策独立现金演进 |
| 小额订单最低佣金占比高 | 合并允许合并的交易；容忍带；部分调整 | 当前费用差 + 延迟敞口盈亏平衡；再做政策回放 | 需要目标时间线与执行权限；不能把跨日相反单随意净额化 |
| 当前仓位偏离与费用权衡 | 现有三类治理计划 + 小范围偏离扫描 | 费用—偏离前沿；有收益预测时再算预期净差 | 排名不是 μ；最终股数、现金与硬约束重新验算 |
| 实际成交偏离目标 / 基准 | 改订单尺寸、时段、方式的有限候选 | 实现短缺拆账；可比任务分析与前瞻检验 | 需要批准目标、decision/arrival、订单撤单、成交与终点估值；成交日志不足则不归因 |

风险协方差异常应另列“先修有效性”卡：明确为何输入或估计不可信、允许的替代模型、随后要跑什么比较。没有收益证据时不填收益改善数。

## 4. 验收怎样避免又回到学术报表

1. 每条建议必须有可执行动作，或明确解释为何暂不能给动作；只显示文献结论不算完成。
2. 每个金额标明已实现、模型条件或历史回放；没有合格替代方案时，不标“可避免损失”。
3. 必须能得出“维持原政策”和“改善后仍不可取”；不允许只输出被挑中的成功候选。
4. 历史选择用开发区间，验证使用截止后未参与选参的数据；重复选择复用试验账本，净差使用配对时间依赖统计。区间包含零应如实报告。
5. 原政策通过新接口能重建现有账本；共用账户规则，停止交易与缺失输入状态明确；不得用额外回测器绕过冻结费用或交易限制。
6. 单步规划从实际当前仓位出发；长期回放从共同初始状态独立演进。这两类结果不得共享一个含糊的“不动”基准名称。
7. 信号、成本或市场条件到什么程度会推翻建议，必须写进观察条件；后续数据也可能支持撤销建议。

## 5. 本轮检索与核验边界

本轮按“能否给动作 / 能否给经济差 / 结果能否外推”重新筛查前轮来源，补采官网与 GitHub 公共 API。原始清单见 `evidence/actionability/source_manifest.json`、`practice_followup.json`、`additional_practice.json`；补充学术检索响应保存在 `actionsearch1/2/3.json`。现有 41 条题录核验见 [05](05_文献DOI与来源.md)；新增 NBER 工作论文 DOI 已另外核验元数据，不能与 RFS 版本算成两项独立实证。

AQR 与 qoppac 博客的部分请求因域名解析失败未取得正文；一条猜测的 Vanguard URL 返回 404，未用于论据。旧 Carver 仓库名检索失败后已改用当前仓库；不把失败访问当成反证。本轮没有从论坛收益截图、未核实实盘宣称或教程合成数字推算收益。

公共网页和 stable 文档会变动，以上是采集时状态；源码固定提交与本地快照可供复查。文档提出的 A 股动作仍需使用 TemperQ 账户制度、用户信息与前瞻记录验证。
