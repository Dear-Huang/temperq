# 第二轮研究的首批工程增量

2026-10-27。对应 [09](09_A股工具与可估值改法_第二轮.md) 的A/B/D和 [10](10_A股来源与实现核查.md) §6。采用已有导入、审计、整数规划与留痕接口；没有复制外部交易引擎源码、引入RQAlpha依赖或增加另一套撮合器。

## 1. 按收费对象核验最低佣金

新增 `audit_fee_units.py`，BigQuant及标准CSV可补：

| 标准字段 | BigQuant可用中文列 | 含义 |
| --- | --- | --- |
| order_id | 委托编号 | 同账户、同回测内的实际委托号；母单号不能代替独立计费子单号 |
| fill_id | 成交编号 | 同日唯一的真实成交标识；重复即拒绝 |
| commission_basis | 佣金计费单位 | order / fill / unknown；也识别按委托 / 按成交 / 未知 |
| commission_evidence | 计费依据 | 用户提供的合同或交割单引用，平台不据此声称已独立认证合同 |
| order_complete | 委托成交完整 | true / false；仅该委托最终全部成交均已导出时填true，不要求全部委托数量成交 |

已有文件仍可原样导入。已知委托号按日期归并；缺收费依据或按委托时导出不完整，仅输出情景，不据此判多收费。没有委托号时逐成交作情景，不假定每次成交实际独立收最低佣金。同日同单证券、方向、依据或完整性冲突会拒绝导入，不自动拆成几个看似合理的订单。用户只导入一个账户、一次回测；混合多账户须先区分导出。

按委托汇总后核对费用；逐笔模型佣金按成交额分摊只用于展示，不因分摊不同误报异常。`fee`必须为该笔已扣或分摊费用，不可把整单总费用重复填到每笔。税仍按各笔日期和方向计算，不调整冻结费率。

独立合单候选不包含同单部分成交。代码建议和小单摩擦也使用收费单位，避免把大订单的小额部分成交当成应该过滤的小买单。

**可复算的合成例：** 一笔2万元买单分两次各1万元成交，佣金3bp、最低5元。按成交收最低费情景为10元；按完整委托计为6元。报告把4元标为记账口径差，不称交易优化收益。报告费用分摊为6元和0元时，汇总仍闭合，不因展示分摊为3元和3元误报。

用户入口：导入核对新增“委托归属与最低佣金单位”；补件和字段模板仍在导入页。完整/受限报告均可查看收费单位明细、下载`fee-units.csv`。旧报告只读，不自动重算。

## 2. 受阻目标的可调整方案与解释

复用 `governance_review.py` 的HiGHS整数规划，新增“只做朝向原目标的调整”对照。在原始参考权益下，不越过朝原目标可到达的整手数量；原目标为零时允许清掉可卖零股。该方案不把受阻权重转给别的股票。

与保持持仓、贴近原目标、允许偏离内省费并排。贴近目标方案仍仅在原目标股票内配置，用户股票池、单票上限、持仓数、现金及换手硬限制不改变。两类方案都独立重核最终数量、费用和全部约束；求解失败或重核不通过时保留状态，不删除硬预算重试。

新增“目标受阻后，还能调整多少”：

- 逐证券列出禁买、禁卖、停牌、不可卖数量、必须保留市值与数量范围；不可卖不自动归因于T+1，可能包含冻结。
- 以该方案费用后权益为分母，计算仅由数量上下界确定的**股票偏离下界**。不是全部因果归因，不包含受阻引起的现金偏离，不将下界翻倍。
- 其余偏离包括现金、整手、费用和预算，不保证全部可消除。
- 朝原目标完成额以初始权益固定原目标，截断超额/反向调整；不计成实际成交、收益或机会损失。

**现有合成示例：** 推荐方案总偏离40.77%，其中股票偏离下界28.61%来自不可卖与禁买，其余12.16%。原先单看40.77%难以解释，现在能定位原因。保持、朝原目标、可调配置之间的费用与现金差可复算，未推算未来收益。

## 3. 未纳入本轮的研究任务

母单TWAP/事前量曲线/参与率比较，需要批准母单、截止时间、可卖库存、时点行情和未成交终点估值。现有日频导出不足以还原，不把更换成交价字段伪装成执行优化。

独立演进的调仓政策重放、点时本土风格基准、完整A股限价制度表仍单独推进；本轮不从已成交路径重扣费用推断行为变化后的收益，不套用未经确认的9.5%/10%统一规则，也不接RL。

## 4. 验收入口

- `tests/test_audit_fee_units.py`：同单部分成交、汇总核对、未知/不完整、历史税率、标识冲突、重复成交、CSV与代码候选。
- `tests/test_governance_review.py`：受阻股票偏离下界、现金不重复计数、朝原目标边界、方向限制；保留原整数规划穷举对照。
- `scripts/qa_audit_research_increments.mjs`：隔离合成数据完成导入→核对→收费单位报告/CSV→受阻方案；检查320/390像素与桌面。

没有执行用户策略代码、下单、启用纸面账户、覆盖原始材料或自动采用候选。

验收结果：兼容回归185项通过；最终CSV转义等改动后相关54项复验通过。上述新增浏览器流程及原导入、完整报告、代码候选流程四条均通过。实际BigQuant四件材料只读复算仍有642笔成交、163个快照且账目闭合；缺实际委托归属及收费依据时，全部保留情景，没有生成虚假的已确认节省。
