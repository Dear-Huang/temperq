日期：2026-10-27。检索目标是补足“策略用户怎样识别归因、构建和调优问题”，并找出长期使用但容易误判的做法。检索使用 Crossref、OpenAlex、arXiv、官方监管页面、GitHub 公共 API 和作者项目页；本报告不是穷尽性综述。论文 DOI 与题录核验见 [05_文献DOI与来源.md](05_文献DOI与来源.md)，原始响应和代码快照在 `evidence/`。

**同日追加的优先级修订：** 用户要求进一步回答具体改法、改后经济效益与不改成本。补充证据与结论见 [07_从诊断到改法与经济代价.md](07_从诊断到改法与经济代价.md)；实务原文与拟议契约见 [08](08_实务证据与动作定价契约.md)。实现顺序调整为：可估值动作 → 历史政策净差 → 前瞻验证。试验记录从第一步就保留，复杂统计模块不再先于用户动作；本文下述研究方向的排列不代表新的实现顺序。

## 先说结论

TemperQ 已经有一条有价值的链条：策略材料导入、账户与费用对账、逐股和持有期归因、约束下的整数股数规划、治理计划留档，以及把“预测、构建、实施、结果”分开的 15 个审计环节。新增量不应再做一个泛化的回测报表或第二个撮合器。

首轮筛选的五个研究方向如下（实施优先级以 `07` 和修订后的 `03` 为准）：

1. **贯通已有试验账本 + 搜索调整后的结论**：复用 `ledger.py`、训练候选审查和追加报告，把治理政策候选纳入同一试验族；在族内提供 SPA / Reality Check、Model Confidence Set、PBO/DSR 的适用性分层。DSR 或 p 值不能替代试验记录。
2. **构建政策的成对反事实**：同一信号、同一股票池、同一账户、同一成本和同一日期，只替换持仓宽度、权重、免交易带、调整速度或成本模型，输出风险、费用、暴露、换手和净结果的差异。不要只展示最好的配置。
3. **实现有效前沿**：把“预测分数好”改成“在给定风险下，扣除交易成本后是否仍可实现”。外部文献把交易成本、风险与权重共同放入目标；这与 TemperQ 的治理边界相容，但 A 股整手、T+1、涨跌停和最低佣金仍应由现有账户引擎处理。
4. **决策目标验证**：任何成本模型或筛选器至少同时看全体排名、最贵尾部识别、组合替换清单和真实/情景交易成本。你新增目录中的成本模型已经示范了这条原则，平台可把它抽象成通用审计协议。
5. **持续监测和有效挑战**：将“预期偏离、输入漂移、性能退化、异常结果、复核人、处置和回退”写成结构化事件。美联储 2026 年 SR 26-2 已替代 SR 11-7，明确把概念合理性、结果分析、持续监测、模型清单和有效挑战放在生命周期内。

## 外部研究给出的可落地增量

### A. 回测搜索与多重比较：从“结果显著”升级为“搜索过程可审计”

**问题。** 用户往往只留下胜出的参数、最好的窗口和一张净值曲线。这样无法知道结果是经济规律、构建选择还是搜索运气。单一 Sharpe、普通 bootstrap 或一段 holdout 都不能自动修复反复查看和选择偏差。

**证据。** Bailey、Borwein、López de Prado 与 Zhu 的 PBO/CSCV（R19）专门估计投资回测过拟合概率；White 的 Reality Check（R20）、Hansen 的 SPA（R21）比较一族模型相对于基准的优越性；Hansen、Lunde 与 Nason 的 MCS（R22）输出“数据不足以排除的模型集合”，而不是强行挑一个冠军；DSR（R17）对试验数、非正态和选择偏差作搜索调整，2026 年的新版本（R18）把它明确写成统一的搜索调整推断框架。`arch` 提供 `MCS`、`StepM`、`SPA` 和 `RealityCheck` 的公开实现（代码快照见 `evidence/bashtage_arch_multiple_comparison.py`）。

**已有基础。** `src/qwb/ledger.py` 已记录同一任务/数据快照下重看最终测试的次数、配置和历史；ADR 010 已要求保存逐轮内层验证候选、失败和未运行轮次。它们不应被说成空白。当前增量是把该语义贯通到导入策略、治理方案和政策回放，并接入统计比较，而非再建一个平行日志。

**TemperQ 设计。** 以现有账本扩展出 `trial_ledger_v1` 统一视图，每个候选至少记录：

```json
{
  "trial_id": "uuid",
  "family_id": "signal_X__mapping__monthly",
  "data_snapshot": "hash",
  "policy_version": "hash",
  "parameter_grid": "frozen or exploratory",
  "selection_stage": "development|validation|outer_test",
  "metrics": {"net_return": 0, "risk": 0, "turnover": 0, "cost": 0},
  "status": "selected|rejected|inconclusive",
  "reason": "predeclared rule or analyst note"
}
```

首版不必一次实现所有统计量：先把试验族、共同日期、共同基准、候选差值和预登记阈值保存下来；随后接入 SPA/MCS，再把 PBO/DSR 标成“依赖试验族定义”的诊断。`family_size` 不能由最终胜者手填，否则审计只是在记录一个可操纵的数字。

### B. 构建选择不是噪声：要做“成对反事实”

**问题。** 同一预测可能因为股票池、分组断点、微盘股过滤、行业调整、调仓频率、持仓宽度或权重方案不同而得到不同结论。只报一个配置会把构建边际误归为预测边际。

**证据。** Soebhag、Van Vliet 与 Verwijmeren（R06）发现研究设计选择产生的 non-standard error 平均可超过普通标准误；断点、微盘股、行业调整和再平衡频率都会改变因子结果。Hou、Xue 与 Zhang（R27）对 452 个异常的复验显示，多重检验门槛下失败比例显著上升。Jensen、Kelly 与 Pedersen（R29）给出相反方向的复验证据：许多因子可以在全球数据中复现；这说明“复现危机”本身不能靠单一论文决定。

**TemperQ 设计。** 以一个 `policy_family` 绑定共同的信号、日期、股票池、账户和成本，候选只改变一个治理轴；输出 paired difference、块 bootstrap、共同样本覆盖率和最小可检测差异。对 A 股至少加入：股票池时点、上市/退市、ST、停牌、涨跌停、复权因子版本、整手、T+1 和公司行动。若一个候选依赖更完整的数据，报告为“不具可比性”，而不是自动胜出。

### C. 交易成本和调仓治理：固定频率不是默认正确答案

**问题。** 行业长期使用固定月度/季度调仓、简单低成本筛选和等权，但这些做法可能把信号暴露、交易成本和执行路径混为一谈。

**证据。** Gârleanu 与 Pedersen（R02）推导出预测衰减与交易成本共同决定的动态策略：应部分向当前目标交易，并对衰减慢的信号给更高权重；这不支持普适固定调整比例。Novy-Marx 与 Velikov（R08）比较成本缓解方法，发现 buy/hold band（进入比继续持有更高的门槛）常比单纯降低调仓频率更有效；成本高的高换手策略仍可能无法留下净价差。Detzel、Novy-Marx 与 Velikov（R09）发现忽略交易成本会改变模型比较结论。Jensen 等（R10）把目标放在 net-of-cost return at each risk level，即“implementable efficient frontier”。

**TemperQ 设计。** 在现有账户回放上加入政策候选：固定频率、免交易带、部分调整、信号年龄触发、资金/参与率限制。每个候选都和“不动”及原策略对比，分别报告总成本、风险、净结果、现金、未完成目标和受阻原因。`GOVERNANCE_REVIEW.md` 当前的快照规划只代表声明价格下的可行方案，不能替代这一历史闭环。

### D. 归因要先确定对象：会计贡献、因子归因和因果反事实不能混写

**问题。** 逐股 P&L 桥能回答“哪些持仓贡献了金额”，但不能证明某个信号有 alpha；Brinson 能拆配置/选择，但依赖基准和口径；风险贡献又可能把绝对和相对收益混在一起。

**证据。** Brinson、Hood 与 Beebower（R14）及 Menchero（R15）提供基准相对和多期归因框架；Davis 与 Menchero 的 *Pitfalls in Risk Attribution*（[工作论文 DOI](https://doi.org/10.2139/ssrn.1823628)，摘要级证据）说明绝对收益风险归因与基准相对绩效错配会产生直觉相反的边际风险。TemperQ 当前策略审计文档已经明确：逐股货币贡献是会计敏感性，不是 skill、luck 或预测 alpha 的证明。

**TemperQ 设计。** 输出三层并强制分开：

- `accounting_contribution`：现有账户桥，必须闭合；
- `benchmark_factor_attribution`：需要基准、因子收益和点时暴露；
- `policy_counterfactual`：同一账户、信号和成本下替换构建/执行政策，才可讨论治理边际。

报告标题和图例应显示层级；没有因子或反事实输入时只显示“未接入”，不显示空的 alpha 数字。

### E. 解释模型时不要把 feature attribution 当成交易归因

Aas、Jullum 与 Løland（R31）说明特征相关时，假设特征独立的 Shapley 近似可能给出错误解释。若 TemperQ 将来解释 LightGBM 或外部预测，应保留特征的时点和相关结构，报告 conditional/permutation sensitivity，并与组合层的实际交易贡献分开。SHAP 值解释“模型输出变化”，不解释“净收益由谁贡献”。

### F. 风险与约束的反常识结论：约束可能帮忙，但也可能是错误保护

Jagannathan 与 Ma（R03）提出 no-short-sale 约束即使经济上“错误”也可能降低估计误差导致的风险；R04 是 2019 年对该证明的勘误。这个结论不能简化为“约束越多越好”：应在相同预测、相同交易成本和外层留出上比较约束的边际代价，并记录约束是否真的绑定。DeMiguel、Garlappi 与 Uppal（R05）说明 1/N 可能难以被优化组合击败，核心原因是估计误差；它不证明 1/N 普遍最优。Clarke、de Silva 与 Thorley（R13）则把约束造成的噪声与预测成功分开。

**产品规则。** 每一条硬约束显示 `binding_frequency`、`shadow_price/relaxation_cost`（能算时）和“若放松会发生什么”；没有历史外层验证时不得写“约束降低风险”作为普遍结论。

### G. 成本模型的目标依赖性：你的新增论文应成为平台协议

外部流动性研究提供很多低频 spread proxy，但 TemperQ 不应把 proxy 直接当作成交成本。Corwin 与 Schultz（R34）展示了用日内最高/最低价估计价差的经典方法；Zhao 等（R33）提供中国股票高频流动性测量。你的 `submission_jpm_20261020` 已经把 tick floor、尾部筛选重合、替换清单和实际价差分开，并明确 quoted-spread charge 不是 observed execution shortfall。最值得产品化的不是复制某个 proxy，而是一个**决策目标验证卡**：

| 检查 | 必须回答 |
|---|---|
| 整体排序 | 与点时实测/替代目标的 rank correlation 是多少？ |
| 尾部筛选 | 最贵 decile / top-k 的 overlap、precision、recall 是多少？ |
| 构建后果 | 哪些证券被替换，换手和暴露如何变化？ |
| 交易后果 | 费用、价差、冲击、最低佣金和账户约束各是多少？ |
| 经济后果 | gross、cost、net、风险和现金分别如何变化？ |
| 迁移 | 换市场、价位制度、股票池和频率后结论是否保留？ |

### H. 统计不确定性和监测：普通 Sharpe 与“看起来显著”不够

Lo（R16）指出 Sharpe 统计量受非正态和序列相关影响；TemperQ 现有块 bootstrap 是良好基础，但每次看结果、改规则再看会消耗独立性。Howard 等（R30）的 confidence sequence 提供了适合持续监测和任意停止时点的思路，首版可先记录“观察次数”和时间块，再评估是否需要引入 time-uniform interval。

### I. 2026 年治理标准：生命周期、有效挑战和模型清单

SR 26-2（Federal Reserve/OCC/FDIC，2026-04-17，官方页和 PDF 在 `evidence/sr2602.txt` 与 `sr2602_guidance.txt`）明确要求按用途、方法、重要性和数据限制确定验证强度；概念合理性、结果分析、持续监测、角色责任、模型清单、文档和第三方模型验证应贯穿生命周期。它适用于受监管银行组织的模型风险管理，不是 A 股个人策略的法律认证，但可以转译成 TemperQ 的审计对象：

`model/policy inventory → conceptual soundness → outcome analysis → ongoing monitoring → effective challenge → exception/rollback`。

## 反常识与“行业常用但容易错”的清单

| 常见说法/做法 | 更准确的审计命题 | TemperQ 应怎样提示 |
|---|---|---|
| “Sharpe 高就是策略好” | 需要考虑搜索次数、非正态、序列相关、成本和外层留出 | 显示 gross/net、试验族、DSR/SPA/MCS 状态；缺试验账本则标 `search_unresolved` |
| “相关性更高的成本模型一定更好” | 若决策是排除最贵股票，尾部识别和替换成本更重要 | 同时展示整体 rank、tail overlap、turnover 和 net consequence |
| “少调仓总会省成本” | banding 可能以更少暴露损失达到相同成本节省；固定频率未必最好 | 回放 frequency、band、partial adjustment 三类候选 |
| “约束越多风险越低” | 错误约束可能减少估计误差，也可能造成机会成本和暴露偏离 | 绑定频率、放松代价、外层净结果分开 |
| “1/N 是最稳妥的基线，因此优化一定应胜出” | 参数估计误差可能让优化输给 1/N；不同资产市场结论可反转 | 保留 1/N、原政策和简单风险权重作为显式基线 |
| “逐股贡献就是 alpha 归因” | 会计贡献、因子归因和策略反事实回答不同问题 | 三层归因分栏，缺输入就降级 |
| “模型给出的 SHAP 就是策略原因” | 相关特征下独立性假设可能错；模型解释不等于交易贡献 | 输出 feature sensitivity 与实际交易/账户贡献两套证据 |
| “p<0.05 说明调优成功” | 反复搜索和多模型比较使普通门槛失效 | 试验族、SPA/MCS/PBO/DSR 和独立外测同时显示 |
| “回测引擎是实现细节” | 价格路径、费用、公司行动和成交规则会改变结果 | 保存引擎版本、规则包、输入哈希；做账户恒等式对账 |
| “监管 SR 11-7 还是最新治理依据” | 2026-04-17 已被 SR 26-2 替代 | 记录来源版本和适用范围；旧版本只作历史参考 |

## 推荐实施顺序

### P0：先把已有方案做成可估值动作（同日修订）

- 复用快照治理的保持、贴近目标、容忍偏离省费方案，给具体数量、费用差、偏离代价和盈亏平衡条件；无预期收益时不报净收益最优。
- 缓冲与整手处理后复核硬约束，区分软目标、强制修复与紧急退出。
- 复用已有试验账本记录全部候选及版本，报告证据类型、输入覆盖和未知项；不以复杂统计建设阻塞动作比较。
- 将成本模型成果转成决策目标验证卡，检查单位与期限；不复制第二套撮合器。

### P1：历史政策净差与前瞻记录（同日修订）

- `policy_family_v1` 绑定共同信号、日期、成本和初始账户，让原政策、banding、回边界与部分调整分别演进。
- 输出毛结果变化、成本节省、净差、风险与现金，复用现有 paired block bootstrap；探索与外层验证分开，保留失败候选。
- 冻结事前推荐与反转条件，追加前瞻纸面记录；效果不足时允许维持原政策或否决改法。
- SPA / RealityCheck / MCS、DSR/PBO 的完整接入延后至候选族和输入具备时；未知搜索历史不显示完整搜索认证。

### P2：补数据和实现归因（依赖外部输入）

- 02：点时股票池、上市/退市、ST、停牌、公司行动。
- 05/13：基准、行业/风格因子收益、点时暴露和多期归因。
- 09–11：订单生命周期、盘口/成交、参与率、短缺和机会成本。
- 07：版本化信号历史和可用时点；不以多个预测期限的 IC 替代信号年龄。

### P3：高级方法（有明确需求后再做）

- time-uniform confidence sequences；
- conditional SHAP 或模型特征敏感性；
- multi-period convex/MPC 参考优化；
- account-level learning of economic feature importance。

## 不建议现在做的事

- 不把 DSR 单独做成“策略真伪判定器”；它依赖试验数和候选相关结构。
- 不用 `cvxportfolio` 替换现有账户成交引擎。先把它用作连续优化对照，因为它不能自动覆盖 A 股整手、T+1、涨跌停和最低佣金。其仓库为 GPL-3.0；TemperQ 当前为 AGPL-3.0-or-later，这里没有判定两者不兼容，实际接入需按所采用文件和版本处理许可。
- 不把 Qlib、Lean、Alphalens、Pyfolio、QuantStats 的图表或指标直接等同于审计。它们适合作为对照、输入适配或回归测试。
- 不把本地论文的结果当外部独立复验；应把它们登记为已知假设、冻结参数和需要跨场景检验的承重资产。
- 不把 2026 年预印本和 SSRN 工作论文写成已同行评审的定论；报告按 `A/M` 降级。

## 来源可靠性与边界

- Crossref DOI：用于题名、作者、期刊和出版时间核验；存在 HTTP 429 的记录已通过重试补齐。
- 官方监管 PDF：SR 26-2 由 Federal Reserve 官网取得，页面明确声明其 supersedes SR 11-7 和 SR 21-8；适用对象是银行模型风险管理。
- NBER / 作者项目 / GitHub：用于全文、代码和数据流程；数据许可、WRDS 访问和第三方条款仍由使用者负责。
- SSRN / arXiv：用于新方法线索和预印本证据；不按期刊同行评审证据计权。
- OpenAlex 有时会给出题名相近但 DOI 不正确的结果；本报告的 DOI 以 Crossref 核验表为准。

## 最终判断

同日深化后的增量方向是：从可执行动作开始，把成本节省、收益牺牲、风险变化与不确定性放在一起比较，再用可回放证据与前瞻记录验证。搜索与归因是这条链的支撑。用户应能知道怎么改、什么条件下值得改、目前仍不知道什么，以及为何有时应保持原政策。具体外部案例和动作契约见 `07`、`08`。
