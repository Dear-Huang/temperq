# 专业研究链路审查与本轮增强

日期：2026-10-22。目标是让研究结果更可信、可复核，并保留专业用户自己的研究方法。本文件区分官方代码、已发表文献、预印本主张与本机实测，不把它们合并成收益承诺。

## 结论与本轮取舍

项目适合定位为本地优先的 A 股 ML 研究与证据工作台。要走出个人脚本阶段，首先需要稳定的数据、时间、预测、版本和评价契约，以及可独立复查的测试与案例；模型数量和页面数量不能替代这些条件。

本轮完成的重点：

1. LightGBM 可以在每个外层训练历史内，用清除标签重叠的尾部验证选择轮数，再使用全部已成熟外层训练样本重拟合。外层测试标签不参与该折选择。固定轮数方式仍可用。
2. 训练报告的增量判断改用相同股票/日期样本上的配对 IC 差；对三个固定简单参考的正态近似 Newey-West 区间做 Bonferroni 校正。独立 Bench 仍使用日期块重采样，两种诊断方法分别标明。
3. Newey-West 不再删除缺失日后重新拼接时间轴；无效价格、复权因子与无穷特征不再被当成有效标签或极端排序值。
4. 训练保存实际输入文件清单和内容哈希，并在结束前复核。组合数据的基础行情、来源文件、配方、ST 与指数名单全部纳入清单。新训练的 Bench 证据会核对训练时的数据内容。
5. Bench schema 5 支持组合数据、历史指数成分和自选股票池，使用与训练一致的来源覆盖顺序。覆盖行情时缺失的状态不会继承成“正常”。旧 schema 3/4 保留原解释，不改写历史结果。
6. 支持显式特征子集，便于在同一数据集、同一协议下做特征消融；来源编号改为独立 ID，修复删除来源后再次导入可能覆盖其他来源的问题。
7. 报告不再把写在任务卡中的自然语言条件称为已执行的预注册判断，也不把简化费用诊断等同于独立现金/持仓账户。

## 与成熟平台逐层对标

| 链路 | 已核验的外部实践 | 本项目本轮采用或保留的做法 | 尚未具备的能力 |
| --- | --- | --- | --- |
| 数据与预处理 | Qlib 的 handler 有单独的拟合区间；VeighNa Alpha 分离 dataset、model、strategy、lab | 日度特征不拟合全样本标准化；记录组合数据实际内容；可选择特征子集 | 数据供应商的原始修订历史、财报公告精确时间与完整退市覆盖尚未独立认证 |
| 训练与选择 | Qlib LGBModel 支持 train/valid 和早停，基准 YAML 分开 train/valid/test | 增加按标签成熟时间清除的内层验证，固定设置后逐折选择轮数 | 尚无统一搜索预算、嵌套参数搜索、分布式训练与完整 trial 账本 |
| 时间适应 | QuantConnect 官方 walk-forward 文档讨论尾部历史优化与优化频率的过拟合权衡 | 保留按年滚动；选择仅看该折可用历史 | 月/周重训、漂移告警与自适应算法尚未统一进入原生训练器 |

| 组合与执行 | Qlib 基准有明确的价格、费率、最小费用与策略设置；VeighNa/LEAN 有更广的交易执行体系 | 保留 A 股独立研究账户和规则；对外部默认口径只做敏感性对照 | 不是券商仿真器；未实现整数手、最低佣金、队列、真实冲击、容量与公司行动逐笔账本 |
| 统计评价 | 成熟资产定价研究强调时序划分、强基线和经济结果；过拟合文献强调完整选择过程 | 同样本配对、固定参考、费用压力、数据资格和版本追溯 | 固定比较校正不等于校正全部搜索；没有独立前向业绩或平台认证 |
| 产品与协作 | 成熟平台具备稳定接口、共享结果、运行环境和持续测试 | 单一主仓库、版本归档、后台 worker、可复核报告与白名单分享摘要 | 多用户权限、资源配额、常驻服务器调度与结构化网站评价上传仍未完成 |

## 真实开发数据对照

运行命令：

```powershell
.venv\Scripts\python.exe scripts/compare_training_quality.py --data-dir E:/data/qwb_data --output artifacts/my-quality-audit --codes 240 --end-year 2023
```

目标目录必须不存在。先从历史股票代码并集中按 `sha256(code)` 固定抽样，排除北交所，选择 240 只沪深股票；选股不使用收益或当前上市名单。使用 2018–2023 行情，2021–2023 按年滚动预测，两个种子；本轮不读取 2024–2025 行情文件来选择设置。它仍是已经接触过的历史开发数据，不能称为独立确认。

对照预先固定为：原参数最多 300 轮，另一组只增加 60 个历史验证日、30 轮耐心、至少 120 个训练日。两组使用同一任务、数据、股票池、参考、费用、样本与 20 日块重采样，2,000 次。没有在多个验证窗设置中挑选最好的一个。

| --- | --- | --- |
| 有效 IC 日期 | 721 | 721 |
| 平均 Rank IC | 0.06375 | 0.08370 |
| 2021 IC | 0.04082 | 0.05392 |
| 2022 IC | 0.07742 | 0.10126 |
| 2023 IC | 0.07334 | 0.09634 |

配对 Rank IC 增量为 **+0.01995**，95% 日期块区间 **[+0.01089, +0.02843]**，在这个开发子集上支持信号改善。

基础费用下新减旧年化净收益点估计为 **+847.85 bp**，区间 **[-61.76, +1779.88] bp** 跨零；两组均有未解释估值/数据缺口，账户不授予净改善通过结论。额外滑点情景即使区间为正，也保留 DIAGNOSTIC_ONLY。拒单和陈旧估值并未全面减少，不能把 IC 提升概括为整体投资效果已经改善。

## 专业用户会不会被约束

会。当前原生训练器和标准 Bench 都有明确边界，不能把“任务卡能描述”误当成“系统已实现”。合适的做法是让默认工作流简单，同时让专业用户在自己的环境训练并通过数据/预测契约接入；资格约束放在评价与证据上。

| 需求 | 当前路径 | 本轮后仍需注意 |
| --- | --- | --- |
| 自建数值因子、财务或外部特征 | 组合数据来源；`train.features` 明确选择，原生特征可与 `x_<来源ID>_<列>` 混用 | same-day 规则仅适用于 15:30 前实际可得的数据；晚间发布选 next_day。系统无法识别供应商倒填或用户把未来信息写入因子 |
| 自选池、历史指数池 | 原生训练和 schema 5 Bench 均可接入 | 历史成分名单必须来自用户的数据；名单完整性与公告时点仍由来源负责 |
| 特征消融 | 两个配置使用同一组合数据，仅改变 `train.features`，从而共用协议 | 不要通过删掉行情、改测试期、改变覆盖来制造增量 |
| 自己的模型、损失、GPU 或研究框架 | 在 Notebook/Qlib/自有管线生成标准预测 parquet/CSV，用 `qwb bench model` 提交 | 预测可以获得诊断；来源缺失或不符合现有折证据契约时不会获得同等级的排名结论 |
| 自己决定训练轮数 | 不写 `model.selection`，保持固定轮数及合法 LightGBM 参数 | 开放参数不等于容忍拼写错误；未知参数有警告，选轮数时禁止会覆盖预算/早停的别名 |
| 日频其他持有期 | 原生日频返回标签与工具 API 可研究；标准 Bench 仍为 A 股 5/20 日排序 | 其他市场、盘中任务、分类、直接持仓/RL 不应套用当前标准 Bench 或声称已有对应标签实现 |
| 月/周滚动、任意自定义折 | 在外部管线完成训练并提交预测，可获取诊断 | 当前训练来源检查主要是年滚动声明，尚未统一支持这些折的同等级验证；不能用伪造年折来获得资格 |
| 机构组合约束、风险模型、容量、成交 | 将输出接到自己的组合/执行引擎，固定规则后保留独立报告 | 当前分数复权单位账户不足以承接这些职责，不应包装成实盘仿真 |

组合数据的 CSV 导入界面保留便捷限制，例如单次 30 个数值列；这不是通用特征仓库。大规模特征工程宜在外部数据管线完成，先固定版本和时点，再接入数值来源或标准预测。未来扩展应增加明确的模型/折/组合适配契约，而不是在一个表单中放开任意代码执行。

## 配置与解释

```yaml
model:
  name: lightgbm
  num_boost_round: 300
  selection:
    validation_days: 60
    patience: 30
    min_train_days: 120
  params:
    num_threads: 8
train:
  features: [r1, r5, r20, r60, vol20, amt20, amt_ratio, gap, range, to_limit]
```

将这两段合入完整运行配置。缺少指定特征、历史日期不足或所选模型无法给出有效验证 IC 时明确失败，不自动换成另一种方案。选轮数仅用于 LightGBM 的可早停 boosting；DART 保留固定轮数路径。最终推理模型会截至数据末日另行选择与重拟合，其历史折成绩不能证明该最终模型已经得到独立样本外验证。

指定的最终测试年份必须存在，不能静默丢弃。验证期只汇总早于最早最终测试年份的年份；后来新增数据可以生成滚动预测、参与最终推理模型拟合，但不能回头充当更早测试期的调参验证。

## 下一轮优先级

首先修复和核验造成 DIAGNOSTIC_ONLY 的真实价格、状态、停牌/退市估值与费用缺口，建立前向冻结提交；随后扩大历史抽样、种子与市场状态覆盖，做验证窗敏感性和真实容量研究。只有在数据/选择预算固定、经济用途明确的条件下，再评估 DoubleAdapt、MASTER、基础模型或因子生成方法。新增模型的价值应由相同规则下的增量证据决定。
