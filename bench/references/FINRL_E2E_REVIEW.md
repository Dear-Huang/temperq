## 2. 对上一版设计的修正

### 2.1 一键流程不等于端到端学习

LightGBM 输出分数，再由固定 Top-K 规则转成组合，是完整研究流程，但组合目标没有反向影响模型训练。E3 直接学习组合权重，E4/FinRL 策略可能以账户状态和持仓为输入、输出动作，两类模型都不必输出可计算 IC 的收益预测。

因此：

- **预测赛道**评价预测输出，IC 与固定组合表现分列。
- **决策赛道**评价策略在共同环境中产生的财富路径，IC 不适用时标 N/A。
- **平台赛道**评价固定预算内从数据到合格策略的完整程序。

不能把每个模型都强制转成预测表，或用“IC 50% + 收益 50%”作为跨赛道能力分。上一版权重没有来自文献的依据，也会奖励与直接组合目标无关的中间预测。

### 2.2 锚是固定实验协议，未必是双基准分母

E5 的确讨论随机/人类双锚点归一化，但也展示基于某算法分数归一化后，重尾分布可能使均值由少数任务支配。金融上的随机与官方模型净收益差可能接近零、换符号或高度依赖行情。

不能因为其他领域采用归一化，就把 `(candidate-random)/(LGBM-random)` 当作金融标准。v0.2 撤回此公式。保留固定参考模型和平台 1.0 的原始成绩，用同一风险约束下的净经济结果作为决策主目标，并把单位直接展示给用户。

这个经济目标及风险约束仍是 q-w 的预注册产品选择；文献支持经济目标、风险与执行评价的必要性，不替 q-w 决定唯一效用函数。

## 3. FinRL 值得吸收的经验

### 3.1 共享的是环境语义，不只是行情表

E1 的数据/环境/agent 分层，让不同算法进入同一状态转移系统。E2 固定数据、初始资金、费用及评价环境，部分任务评价阶段禁止再训练；另一类任务明确采用滚动训练/验证/交易。

q-w 应冻结：观测时间、允许特征、可见持仓/现金、动作含义、动作执行时点、成交限制、交易单位、费用、奖励/指标、终止与重置、更新日程。历史数组在评分端可用，不代表候选策略能直接读未来。

“禁止测试期调参”与“允许预注册滚动更新”可以同时成立；不能混用两种模式比较。RL 在同一历史轨迹上训练一百万步，不等于观察到一百万份独立市场样本。

### 3.2 最终数据需要访问控制或真正前向到达

E2 §4.1 描述组织方保留最近约 15% 数据并处理时间戳，或收集模型提交截止后的新数据。论文还强调真实时序 paper trading 不能像历史回测一样反复重跑。

q-w 可以借鉴受控评测与冻结后前向评价，但不能声称“本地隐藏时间戳”足以隐藏市场；原始价格和公开行情仍可能用于反识别。内部固定锚点可反复用于工程比较，反复反馈后就不再是独立的最终确认。

### 3.3 基准需要匹配经济决策

E1 提供 buy-and-hold、均值/最小方差、等权基准；E3 比较固定分配、均值方差、最大分散等策略，并报告不同费用与风险水平。

因此决策赛道至少包括现金、可实现等权、买入持有、简单风险策略、LightGBM 加固定组合、一个直接学习权重的模型。现金和等权不是深度模型的“弱陪跑”，可以揭示学到的是否主要是市场 beta、降低仓位或降低换手。

用于归因的消融要包含：相同输入与骨干下预测损失训练 vs 组合目标训练、相同模型有/无学习型特征、固定组合规则 vs 学习组合。不能把不同股票池或更高风险导致的差异归给端到端学习。

### 3.4 研究、模拟交易、实盘证据分级

E6 区分两个部署差距，并明确其有限期模拟交易不用于确证统计显著 alpha。该论文是作者团队的预印本，不是独立审计；本文吸收其接口与证据边界，不采信为已验证的超额收益。

q-w 首版不需要接券商，但应从开始保留目标权重、实际成交、实际持仓、费用与偏离原因。以后接入模拟交易时，验证相同策略逻辑能否正确执行；不能因为能发订单就升级为模型长期有效。

## 4. FinRL 的具体教训：分清作者披露、代码证据与我们的推论

### 4.1 比赛表格的 Sharpe 曾被作者标为报错

E2 v4 Table 4 的脚注明确写道：`The results of the Sharpe ratio were reported wrongly.` 该表展示 2023 年比赛、两个较短测试期及其 Sharpe。本文没有独立重算参赛队的资产曲线，也不能从脚注推出其他表格或所有 FinRL Sharpe 都错误。

由此形成 q-w 要求：

1. 评价器从净值路径统一重算指标，不接收作者自报的最终 Sharpe 作为权威值。
2. 固定估值频率、年化因子、无风险利率、ddof、首日处理；明确收益是单期、累计还是年化。
3. 零波动、缺失、破产与短样本要有确定处理；不能用巨大或无穷 Sharpe 赢得排名。
4. 提供可手算的指标样例，并由独立实现交叉核对；保存评分器版本及修正历史。

FinRL 固定提交中的 stock environment 使用 `sqrt(252) * mean(daily_return) / std(daily_return)`，见 [源码 L248-L258](https://github.com/AI4Finance-Foundation/FinRL/blob/c0018c25de864157dc8470f0047b0d10ec721715/finrl/meta/env_stock_trading/env_stocktrading.py#L248-L258)。它是相应频率/假设下的实现，不能直接复制到分钟级、24/7 crypto 或不等间隔账户。

### 4.2 已实际复现：默认预处理可能改变历史可见信息

固定源码为 [preprocessors.py](https://github.com/AI4Finance-Foundation/FinRL/blob/c0018c25de864157dc8470f0047b0d10ec721715/finrl/meta/preprocessor/preprocessors.py)。关键位置：

- L127-L141：`keep_incomplete_tickers=False` 默认设置。
- L171-L180：缺失填充；默认路径为整个表 `ffill().bfill()`，另一条路径虽按股票分组，仍使用 bfill。
- L191-L200：pivot 后默认按整个输入区间 `dropna(axis=1)` 确定保留证券。

本次通过 AST 提取上游原始 `FeatureEngineer.__init__ / preprocess_data / clean_data` 三个方法，用 q-w 本地 pandas 3.0.6 执行最小样例；关闭技术指标、VIX、turbulence 和自定义特征，未修改上述方法。没有安装或运行整套 FinRL。

| 样例 | 输入 | 实际结果 | 说明 |
|---|---|---|---|
| 未来缺失改变股票池 | 首日 A/B 均有价格；第二日只有 A | 截断首日保留 A/B；完整输入只保留 A | 股票池依赖后续缺失，违背前缀一致性；不表示每个不完整股票都是退市股票 |
| 向后填充 | A 首日 feature 缺失；次日为 7 | 完整输入首日为 7；首日前缀仍缺失 | 将未来特征值填回过去 |
| 跨股票填充 | 首日 A.feature=1，B.feature 缺失；次日 A=2/B=3 | 默认路径 B 首日被填成 1 | 非分组填充可将 A 的值带到 B |

结果记录：

```json
{
  "revision": "c0018c25de864157dc8470f0047b0d10ec721715",
  "future_missingness_universe": {"full": ["A"], "prefix": ["A", "B"]},
  "future_backfill": {"full_first_feature": 7.0, "prefix_first_feature": null},
  "cross_asset_fill": {"B_first_feature": 1.0},
  "pandas": "3.0.6"
}
```

这证明具体默认方法在这些输入上存在相关行为，不证明所有 FinRL 路径都使用这些方法，也不量化其对任一公开策略收益的影响。固定提交的环境还存在历史成员 mask 等保护机制，不能一概断言 FinRL 完全没有历史股票池支持。

q-w 对应要求：前缀一致性同时覆盖特征和股票池；只能按 code 与实际可用时间进行因果填充；缺失与退市保留为显式状态。接入第三方处理器不能默认继承其正确性。

### 4.3 同 bar 可见与成交需要单独审计

固定 FinRL 环境在状态中提供 close，动作买卖先发生，再推进到下一日，见 [step 与状态代码](https://github.com/AI4Finance-Foundation/FinRL/blob/c0018c25de864157dc8470f0047b0d10ec721715/finrl/meta/env_stock_trading/env_stocktrading.py#L309-L355)。是否存在不可实现时序，取决于外部如何定义观测和成交时刻；仅凭这段代码不能断言所有实验泄漏。

q-w 不沿用含糊的 bar 语义：t 收盘后可见的数据，默认只能影响 t+1 开盘的订单。若使用盘前、收盘竞价或延迟执行，必须另设对应协议与可用时间证据。

### 4.4 竞赛总名次不是纯模型能力

E2 §7 的组织流程把最终排名写为模型表现 60%、报告评审 40%。这是论文中相应竞赛的组织选择，不能外推所有 FinRL 赛事规则相同。

q-w 的平台能力锚不纳入报告写作质量、人工印象、支持的算法数量或代码行数。文档质量和复现材料作为资格/工程评价分列，不用来抬高交易能力主分。

## 5. 学术评价转为 q-w 可验收条款

| 要求 | 依据 | 验收方式 |
|---|---|---|
| 评价完整决策而非强制中间 IC | E1/E3/E4 | 直接持仓模型可完成决策赛道；IC=N/A 不扣交易能力分 |
| 统一环境与有效信息集 | E1/E2 | 同输入/动作的独立回放一致；未来数据扰动不改变历史决策 |
| 训练/验证/选择/最终评价分离 | E1/E2/E3 | manifest 保存每次访问与选择依据；冻结权重和自适应模式分组 |
| 强经济基准与风险匹配 | E1/E3 | 现金、等权、持有、风险策略与监督学习策略同环境运行 |
| 多种随机性分别记录 | E5/E7 | 完整训练/选择程序重复；训练种子、策略推理随机性、市场时间不确定性分别报告 |
| 区间和分布优于最好一次 | E5 | 原始运行矩阵、日期块区间、失败数、performance profile；任务足够时增加 IQM 诊断 |
| 评分代码可重算 | E2 Table 4/E7 | 净值、交易日志和版本齐备；独立手算与指标交叉核对通过 |
| 计算预算完整披露 | E5/E7 | 计入搜索、选择和失败重试；RL 另报环境步数，预算不能只数最后模型 |
| 消融区分收益来源 | E3 及本项目推导 | 同数据/风险/预算下比较学习目标、特征、组合与执行贡献 |
| 限制与证据等级明确 | E4/E6/E7 | 成本/冲击/可成交性假设、模拟与实盘差距列出；短期前向不自动认证 alpha |

E5 的一般 RL 分层 bootstrap 不能直接当作金融日期独立的证明。q-w 还必须保留相邻时间依赖、同市场多任务依赖和完整运行间的差异；没有足够独立任务时，不能套一个 IQM 就声称稳健泛化。

NeurIPS 检查表没有规定“必须五个种子”或“Sharpe 超过某值即通过”。q-w 可以选择自己的预算与验收条件，但必须预先写清并说明样本下的推断边界。

## 6. 给 Spec 的最终建议

1. 保留用户可读的分数与固定基准名次，但按预测与决策赛道分别定义；撤回 IC/收益混合分与脆弱的双基准比例。
2. 平台锚定完整工作流在共同风险约束下的净经济结果，原始单位和版本差值同时展示；风险与执行违规不能被高收益抵消。
3. 为直接权重/动作模型定义时序策略接口和独立评价账户，不能只扩充模型名称列表。
4. 首版既支持现有预测输出，也完成一个直接组合模型的受控回放，才宣称支持端到端决策 Bench。
5. 固定协议与公开开发集承担持续优化；独立确认使用受控保留或冻结后前向数据。承认固定历史 Bench 会被持续优化，分开解释工程进步与未见市场泛化。

这些建议保留用户的两个核心需求：用户得到明确水平信息，平台有稳定可优化的锚；同时避免为了单一分数而测错对象。
