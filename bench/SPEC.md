## 1. 两个核心需求

### 1.1 用户模型：跑完就知道自己的水平

用户完成模型训练后，将模型或预测结果交给 Bench，得到明确的信息：

1. 训练结果是否可用，能否完成所声明的任务。
2. 模型在适用赛道得多少分，相对同赛道固定参考模型处在什么位置。
3. 在同一组固定参考模型中排第几；有哪些可以解释水平的原始指标。
4. 是否学到预测信号，扣成本后表现怎样，结果有多大不确定性。
5. 哪些证据缺失、检查不通过或薄弱区间影响结论。

用户不需要先读懂所有统计指标才能获取结果。首页先给分数、固定基准排名和一句明确结论，再允许查看指标、证据和细节。

“明确”包含明确指出证据不足，不能为了给用户一个成功/失败按钮而伪造确定性。模型分数描述在指定任务上的表现，不证明所有市场、所有时期都有效。

### 1.2 平台：建立长期优化的固定锚

平台需要一个稳定、可重复运行的主分数。开发者通过改进数据处理、特征、训练、模型选择和工程实现，让同预算下的 Bench 分数持续提高，并能说明提升来自哪里。

必须能够回答：“相同 Bench 协议下，q-w 2.0 比 1.0 高多少分，提升是否稳定，付出了多少资源，有没有引入新的错误？”

防错能力是分数成立的前提和独立发布约束。平台主分数衡量完整工作流产出的策略在共同风险约束下的净经济表现，不能仅靠增加检查、警告或支持的模型数量获得更高模型能力分。预测能力另列，不要求端到端策略提供它没有定义的中间预测。

## 2. 首版产品形态

两个入口，共享评分器、任务、基准和数据协议：

| 入口 | 输入 | 输出 | 主要使用者 |
|---|---|---|---|
| Model Bench | 已训练预测模型、直接权重/动作策略，或可核对的输出与训练证据 | 赛道分、固定基准排名、分层验收与诊断报告 | 用户 |
| Platform Bench | 平台版本、冻结任务集、资源预算和训练入口 | 平台主分数、版本差值、错误案例结果、效率与复现报告 | 平台开发者 |

Model Bench 不替用户再次调参挑最好结果。Platform Bench 从训练入口开始运行完整工作流，再将产物交给同一 Model Bench 评分。

首版分阶段支持规范预测表、q-w 自产 LightGBM、一个直接学习权重的端到端模型；策略必须通过受控回放。接收预测表不等于验证了原模型可以加载，也不等于验证了训练过程无泄漏。

“一键数据到报告”描述工程流程；“端到端学习”指组合/决策目标能参与参数学习，或策略直接学习决策。两者不混称，也不要求一定使用 RL。完整端到端决策 Bench 未通过前，只对已实现的预测赛道作能力声明。

## 3. 范围和边界

### 3.1 v1 必须完成

- A 股日频 5 日、20 日收益排序两个任务。
- 预测赛道覆盖 5 日/20 日任务，给 IC 分、固定组合经济表现和相应排名；不强制合成总分。
- 决策赛道接收直接权重/动作，给经济分和风险/执行报告；IC 不适用时为 N/A。
- 平台在冻结的共同任务、环境、风险约束和预算下形成经济主分数，可比较历史版本。
- 结构化的验收状态、逐期指标、配对比较和可读报告。
- 数据快照、协议、平台版本、配置、预算和产物哈希可追溯。
- 24 对干净/错误案例及外部证据不足的弃权案例。
- 固定配方回归、默认工作流比较、至少一个明确环境档位的复现记录，以及一个端到端直接权重模型的完整回放。

### 3.2 后续阶段

- 社区模型排行榜和同条件模型百分位。
- Kronos 等基础模型、更多 RL 算法、文本、多市场、概率/事件任务与在线适应赛道。
- 受控私有评分、独立前向预测记录、真实用户操作成功率研究。
- 冲击成本、容量和更完整的账户/实盘执行模型。

v1 的排名是“本次模型在固定参考集合中的排名”。没有真实同协议用户模型集合时，不显示“超过 90% 用户”等社区百分位。平台分享站现有职责不因本 Spec 自动扩展。

## 4. 用户报告：信息必须明确

### 4.1 首页固定内容

| 内容 | 展示要求 |
|---|---|
| 任务与口径 | 预测/决策赛道、任务名、Bench 版本、数据快照、评价区间、训练/推理模式 |
| 主表现 | 预测赛道显示 IC 分；决策赛道显示年化净超额基点分；同时展示区间及资格状态 |
| 固定基准排名 | `第 k / N`，列清参考集合，不混入其他任务/数据/预算的分数 |
| 相对锚点 | 对固定经济基准和平台 1.0 的分差；预测与经济表现分别展示 |
| 原始指标 | 适用时的 Rank IC、净超额、净 Sharpe、风险/风格暴露、换手、成本、回撤、覆盖率及有效样本数 |
| 验收结论 | 可运行、评估有效性、预测信号、经济目标分别给状态 |
| 证据标记 | 样本外声明、测试访问记录、来源与污染风险、已执行检查覆盖 |
| 问题与定位 | 影响结论的原因、涉及阶段、日期/字段/产物，以及可采取的动作 |

示意文本，以下数字不是实测结果：

> cn_rank_5d，IC 分 5.0（Rank IC=0.050），预测参考排名第 2/5。固定组合净超额 +120 bp/年，经济证据不足。结果来自本地历史评估，训练与检查证据见下方。

分数是注明单位的指标展示，不是成功概率。相对随机策略改善不自动等于净收益为正。直接权重/动作策略不提供 IC 时显示 N/A，不因此扣经济分。

### 4.2 分层验收状态

复用项目现有 `issues.Report` / `Issue` 的问题记录方式；问题级别与验收状态分开。新增验收状态如下：

| 状态 | 含义 |
|---|---|
| `PASS` | 已有证据达到预注册条件 |
| `FAIL` | 已有证据不满足条件或明确违反要求 |
| `INCONCLUSIVE` | 可以评价，但样本/区间不足以支持通过或失败的统计判断 |
| `NOT_EVALUATED` | 未执行该项，或缺依赖/证据/能力而无法执行 |
| `INVALID` | 上游违规使该维度结果不能作为标准结论，例如标签泄漏 |

预测/经济目标为“均值高于阈值 theta”时，默认以预注册置信区间判断：下界大于 theta 为 PASS，上界不大于 theta 为 FAIL，其余为 INCONCLUSIVE。操作性条件如加载成功按确定性规则判断。

必要检查被关闭、成本依赖缺失或外部特征来源未知时，不能标为检查通过。上游无效应沿依赖关系影响下游资格；原始计算值可保留为诊断，必须标记无效，不能进入标准排名。

### 4.3 分数与证据资格

分别记录 `scorable`（能否计算数值）、`comparable`（是否满足该比较组协议）、`sample_status`（样本关系）和验收状态。

`sample_status` 至少区分 `historical_oos_declared`、`forward`、`in_sample`、`unknown`。另记 `evidence_source=local_declared|controlled`，本地自报不冒充外部认证。

模型权重冻结在 2026 年，若训练用过 2024-2025 标签，就不能再把这段历史标作样本外。合法的历史滚动折外预测可以评分；固定模型只能在其训练未见过的区间或冻结之后的数据上形成相应证据。

仅提交预测表且训练证据缺失时，可给“来源未核验的诊断分”和基准对照，不计入样本外标准排名，也不提供模型加载/复现通过。

### 4.4 已实现的 v0.2 证据与短板诊断

评分器 v0.2 支持预注册信号分门槛和最小锚点增量。均以区间下界严格超过门槛为通过；当前区间下界距目标的分差作为证据差距展示，不承诺训练提分后一定达标。固定四参考用 Bonferroni 百分位块 bootstrap 区间作近似族比较校正；不代表已修正全部调参搜索。

新增年、季度、过去成交额三组、过去 20 日市场均值符号的 IC 诊断，以及预设块长敏感性。切片只定位症状，不作因果解释或独立确认性检验。日历已成熟但缺收益的样本和缺预测日期单列，不能隐藏标签可用性选择。

新增前 10% 股票毛标签收益差及 10/30/60 bp 假设额外买卖摩擦情景；输出逐日事件路径，不年化，不当作自融资账户，不进入 DecisionScore。场景帮助定位排序与买入端收益空间的落差，不替代实际费用与成交。

报告当前适用阶段为修复输入、继续研究或已有历史信号可进入组合与成交验证研究。账户、执行/容量、复现、完整选择偏差和冻结后前向证据未完成前，不提供仿真或实盘准入认证。没有通用 IC 分门槛能替代这些条件。

短板对象固定包含 ID、严重性、观测、门槛、证据差距、定位与下一步。`bench verify` 检查本地产物和逐日均值，`--inputs` 复核输入哈希；本地一致性不认证训练或第三方真实性。方法、原文位置和实务痛点映射见 [近期研究核对](references/PRACTICAL_EVIDENCE_REVIEW.md)。

## 5. 固定任务与数据

### 5.1 两个任务

| 字段 | `cn_rank_5d` | `cn_rank_20d` |
|---|---|---|
| 预测对象 | 未来 5 个交易日收益排序 | 未来 20 个交易日收益排序 |
| 信号/决策 | t 日收盘信息，15:30 决策 | 同左 |
| 入场 | t+1 交易日开盘 | 同左 |
| 标签结束 | t+6 交易日开盘 | t+21 交易日开盘 |
| 输出 | 每个 code / decision_time 一个 score | 同左 |
| 主预测指标 | 按日横截面 Spearman Rank IC | 同左 |
| 经济评价 | 固定多头组合、同口径成本与可实现基准 | 同左 |

“多头”是预测转组合的评价层，不作为第三个独立预测任务。两个预测期共享市场，不能把它们当两个独立市场样本扩大统计显著性。

### 5.1a 端到端决策任务

新增 `cn_allocation_daily_v1` 任务契约：在 PIT 股票池内，每日收盘后由历史观测和当前账户状态输出目标权重/订单，默认下一交易日开盘执行；直接学习组合目标的模型和预测+组合流水线都可参加。

该任务不以 5 日/20 日标签定义策略优劣，而以共同环境产生的净账户路径评价。统一股票池/观测权限、初始资金、无杠杆多头、现金、仓位/行业/换手/风险上限和训练预算；具体数值在开发期冻结。保持现金和不交易都是合法动作。

预测赛道的两个持有期不自动成为决策任务的两个独立样本。平台主分只聚合 manifest 明确列出的决策任务单元，避免重复计算同一市场路径。历史窗口/股票池/市场家族及其权重在冻结时列清，不能事后挑行情。

首版沿用项目历史滚动重训模式，训练日程必须冻结。测试期间允许按预注册日程使用已经成熟的历史标签更新模型，禁止根据测试表现修改超参数、选种子或变更特征；固定权重模型另标模式，不混排。

### 5.2 快照与时间协议

必须冻结行情、历史证券名单、ST/停牌/涨跌停状态、交易日历、复权处理、数据修订可用时间、股票池规则、标签和训练切分。目录名不是内容身份：使用完整 SHA-256，并保存每个文件/分区的哈希清单与快照总哈希。

默认时区 `Asia/Shanghai`；日期偏移按交易日。训练样本必须满足 `label_end_time <= fit_cutoff`，学习型预处理仅拟合当前训练折。历史证券名单与时点覆盖存在缺口时，标明受影响区间及比较资格，不能默默丢样本。

现有验证期 2021-2023、报告期 2024-2025 可作为候选历史锚点；最终区间需核实 20 日任务覆盖、数据来源和已有试验使用情况后写入冻结 manifest。已查看区间只支持透明的历史锚定，不能重新宣称未经使用的保留测试集。

### 5.3 预测覆盖

评价样本由任务和数据预先定义，不能按模型输出删样本。每日有效股票数、每日覆盖率、总覆盖率和跳过日期均须输出。

预测期末标签未成熟、预热期和当时不在股票池的样本按协议排除；其他缺失不得计为零收益或只对共同的“容易样本”排名。比较集合不一致时不出标准排名。覆盖阈值及异常处理在协议冻结前确定。

## 6. 固定参考集合与排名

预测赛道使用以下参考：

| 参考 ID | 用途 |
|---|---|
| `random_panel` | 固定种子的随机排序面板，校准噪声与随机表现分布 |
| `reversal_5d` | 5 日反转简单规则 |
| `momentum_20d` | 20 日动量简单规则 |
| `low_vol_20d` | 20 日低波动简单规则 |
| `lgbm_anchor_v1` | 冻结官方 LightGBM，提供预测与固定组合参考 |

排名集合包含候选与四个确定性参考模型，默认 N=5；随机面板作为分布参照，不将每个随机种子计为一个参赛模型。参考模型并不保证按上述顺序越来越强。

预测排名按 Rank IC，固定组合经济排名按相应净经济结果，分别展示分差区间/不确定性。不得将“点估计第 1”写成“显著优于全部基准”。相同分数使用固定精度的并列排名，不以模型 ID 或提交先后打破统计结论。

先冻结官方模型的配置、训练种子、折清单与预测产物。候选来自同配置 LightGBM 时，不要求它显著超过自身锚点才算训练成功。

决策赛道参考集合至少包括：现金、可实现等权、固定初始组合的买入持有、仅用历史信息的简单风险配置、LightGBM 加冻结组合模块，以及一个直接学习权重的模型。定义相同证券/账户/约束/费用，不能让深度模型用杠杆而参考模型受限。

决策参考总数由冻结清单确定，不沿用预测赛道固定 N=5。现金/等权是经济对照；随机动作仅为负对照，不强迫有交易成本的随机策略充当“零能力”归一化分母。

论文的竞赛总排名可能混入报告评审，例如 FinRL Contests v4 §7 描述的 60% 模型表现、40% 报告评审。q-w 能力分不加入写作或人工印象；复现材料和文档质量分列。

## 7. 模型分与平台主分数

### 7.1 设计选择

v0.1 的“IC/收益各半 + 随机 0/LightGBM 100”被撤回。端到端策略不必输出预测；金融上的双基准收益差又可能接近零，不能用比例放大少数任务。学术界没有要求这种混合分。

v0.2 选择清晰的原始单位，保留可直接优化的单一决策主分。它是 q-w 的预注册设计选择，不是金融学界的统一标准：

```text
SignalScore = 100 * mean(daily_rank_ic)
# Rank IC=0.05 对应 5.0 IC 分；只在同预测任务内排名。

d[j,r,t] = net_return(candidate,j,r,t) - net_return(equal_weight,j,t)
DecisionScore[j,r] = 10000 * 252 * mean_t(d[j,r,t])
# A 股日度账户路径，单位为年化净超额基点；100 bp=1 个百分点。
# 算术年化，CAGR、绝对净收益、Sharpe、回撤和风险暴露另报。

PlatformScore = sum_j(weight[j] * mean_r(DecisionScore[j,r]))
# 任务权重之和为 1；所有单元必须满足共同风险/执行资格。

VersionGain = PlatformScore(new) - PlatformScore(frozen_v1)
```

分数可为负，不截断。平台的锚是冻结协议、经济基准与平台 1.0 的实测成绩，不需要人为规定 1.0 恰好为 100。缺经济依赖、样本不合格、任务失败时不重新归一剩余权重，不给部分任务的正式总分。

净超额必须在共同风险授权下比较：冻结杠杆、集中度、行业、换手和风险预算，所有候选使用同一基于过去信息的风控/裁剪规则并计入换手与成本；约束违规不得用收益抵消。实际风险与风格暴露仍需报告；即便采用相同上限，也不能断言所有策略的实现风险相同。

主分不单独证明 alpha，也不替代风险调整后的比较。高收益是否来自更多 beta、较高实际波动或特定窗口，须由风险报告和配对消融解释。若产品最终选择 Sharpe/确定性等价等其他效用，必须在冻结前明确新主目标并重评所有平台；禁止事后选择更有利指标。

金融绩效不依赖候选的训练 reward 标度。改变 reward scaling、币种计价单位或环境内部累计奖励，不得在相同经济路径下改变经济分。所有主指标由评分器从账户路径重新计算。

### 7.2 平台比较的两种运行

| 模式 | 固定什么 | 允许什么变化 | 回答什么 |
|---|---|---|---|
| `recipe_regression` | 模型、特征、超参数、数据、种子、折与评分器 | 实现和依赖的受控变化 | 升级有没有改变本来相同的工作 |
| `default_workflow` | 数据、任务、训练模式、预算上限、评分器与选择规则 | 新版特征、模型、搜索策略 | 同预算下平台能否得到更好的模型 |

平台长期优化主榜使用 `default_workflow`。固定配方结果用于解释回归与效率。评分器或数据修正单独换 Bench 版本并重跑各平台，不能把修正口径产生的分差当成模型进步。

### 7.3 预算、重复运行和失败

LightGBM 可沿用模型种子 `[0,1,2]` 的集成，但它只是一份候选策略，不等于三次独立流程。正式平台比较初拟至少五次完整训练/选择流程，预算不足则发布明确标记的开发小样本结果；“五次”是资源规划下限，不是文献规定或充分性保证。每次的初始化、搜索、训练环境、推理随机性与非确定硬件设置都记录。

固定 CPU/GPU、线程、内存、墙钟上限和可用搜索次数。特征构造、训练、调参、内部验证、失败重试与模型选择都计入工作流预算，评分时间单列；安装、取数和冷缓存单独记录。RL 另报环境步数、并行环境数和重复使用历史轨迹的次数。超时后仅接收预算内按预定规则选出的产物，不能在超时后继续搜索。

崩溃、无合格产物和缺任务计入端到端完成率分母。规定重复中任一缺产物时，正式完整主分标为不完整，展示成功运行的条件分数但不参与完整主分排名，防止删除差运行。完成率必须与主分同屏。

## 8. 经济评价协议

### v0.3 已实现子集

`src/qwb/bench/account.py` 是独立分数复权单位账本；`economics.py` 将已有预测及四个固定信号参考、可实现等权和现金送入同一环境。已实现次日开盘、按任务周期换仓、现金约束、受阻持仓保留原数量、逐笔费用与拒单、每日估值和净收益、费用压力、净指标/区间、分年诊断与两版结果配对比较。账户测试使用手算案例，校验器独立累计成交现金流/数量并核对逐日持仓与净值，不复用回放循环。

schema 3 的默认环境固定初始资金 100 万、前 10% 多头等权、佣金单边 3 bp（含经手等费用假设）、STRUCT 上月输入半价差、日期印花税。额外单边 0/10/25 bp，基础费用评价全部参考，压力情景评价候选及可实现等权。共同股票池还要求三条规则参考在决策日历史输入足够，记录排除数量；不按未来标签是否完整选样。候选/锚点缺预测则账户不评估。

输出 `economics.json`、`account_paths.parquet`、`fills.parquet` 和 `holdings.parquet`。缺持仓估值仅沿用最近过去复权价并标记；候选或等权有任一次陈旧估值或关键价格/费用缺口时，比较标 `DIAGNOSTIC_ONLY`，禁止净账户通过。其余结果仍仅为 `CONDITIONAL_RESEARCH`。净超额区间下界严格大于 0 只代表本环境的研究目标，不是实用统一门槛。

本实现采用调整单位近似总回报再投资，未完成原始股数/现金分红/退市清算账本；日线状态及开盘价无法证明实际成交。缺整数手、最低佣金、冲击/容量、延迟与开盘队列、风险预算、模型推理重算、全搜索和独立前向。期末收盘估值、不强平、不收假想退出费用。这些限制进入报告，正式经济、仿真及实盘准入恒为 false。B2 只完成账户与部分指标金标准，完整平台挑战集和训练预算运行器未完成。下文其余要求仍为目标协议。

预测赛道的固定组合使用 `weight_research_v1`：固定前 10% 多头等权、每 h 个交易日换仓、未成交部分留现金。决策赛道由候选输出目标权重/动作，不能再被 Top-K 转换覆盖。两者都进入独立账户评价；同一排名组必须使用同一经济规则。

首版先实现分数权重研究账户，不声称满足交易整手、最低佣金或容量约束。策略若输出股数订单，需进入显式的整数账户协议，不能用分数权重回放冒充成交；整数账户未实现时标不支持。账户模型属于环境版本的一部分。

必须做到：

- 模型和全部参考使用同一初始资金、成交逻辑、调仓日、费用和估值规则。
- 沿用 STRUCT 价差、佣金、按日期生效的卖出印花税；STRUCT 使用当时已知的历史输入。
- 不能买入的标的不虚构成交；不能卖出的持仓不能通过重新等权而暗中减仓。现金、持仓和费用满足自融资记账。
- 每日估值、记录日度净收益、持仓与现金，统一生成不同持有期的收益比较；不只记录换仓日汇总。
- 缺失价格、停牌估值、退市和测试期末未平仓的处理必须写入协议；没有规则时该经济维度不可正式评分。
- 毛等权参考用于归因；正式经济分相对遵循相同交易和成本规则的可实现等权参考组合计算。
- 输出费用分解、换手、回撤和缺失处理记录。成本压力测试作为诊断，参数在冻结时记录。

价格冲击未建模时在首页列明，经济结果只在该假设下成立。先用独立手算的小账户案例验证记账，再接全市场；不得把当前 `netcost.py` 的结果未经核对直接当金标准。

### 8.1 端到端策略的环境契约

冻结 `observation -> action -> fill -> account -> next_observation` 的逐步语义：

- 观测仅含决策时刻可得行情/特征、时点股票池、当前现金与实际持仓；标准数据赛道禁止外部数据，开放数据另设组。
- `action_type` 明确为 `target_weights` 或 `orders`；现金权重、资产顺序、交易 mask、越界动作和强制风险裁剪均有规范。不得把现金视为预测缺失。
- t 收盘观测默认影响 t+1 开盘订单，不能既看见完整 t 收盘信号又默认按同价无延迟成交。
- 策略 recurrent state 在评价窗口起点按协议初始化，窗口间是否携带状态显式定义；不能在多窗口测试时暗中重新挑 checkpoint。
- `frozen_policy` 禁止参数更新；`scheduled_adaptation` 只按预定日程使用已成熟信息，更新的预算/参数/选择全记录。两种模式分组，不混排。
- 后端拥有完整历史数据不代表候选可见。回放接口不传未来数组、未来奖励/标签或能任意查询未来的对象；仅交离线预测/动作路径时不能认证策略的信息边界。
- 策略只输出目标/动作；环境生成实际成交，独立账户重算价值与费用；候选不能替换评分环境或提交自报净值作为正式成绩。
- 结束/重置、最后一天持仓、破产和动作无效都有测试。禁止自动重置后多算首日收益，或用未来终值帮助当前决策。

### 8.2 指标金标准

吸收 FinRL Contests v4 Table 4 的 Sharpe 报错教训：指标由统一评分器重算，保留足够产物可由独立实现复算。

固定净值频率、收益口径、无风险利率、交易日年化因子、ddof 和首日缺失处理。A 股日频 Sharpe 的展示值采用 `sqrt(252) * mean(r_net-rf_daily) / std(r_net-rf_daily, ddof=1)`；这一定义本身不保证独立同分布，区间须处理时间依赖。

零波动或样本不足的 Sharpe 为 `null + reason`，不能以无穷值获胜；现金策略仍可得到合法经济分。分钟数据先按日账户聚合再使用本协议，crypto 等日历不得机械套 252。CAGR 与算术年化净超额分开，不把累计收益误称年化。

固定手算案例覆盖：净值到日收益、费用前后、零波动、缺失、末日持仓、自融资、初始资金等比例缩放和奖励重标度。两条独立计算路径不一致时，冻结/发布被阻断。

## 9. 统计比较和“版本更好”

分数用于提供稳定优化方向；置信区间用于判断提升证据。描述性高分与统计成立的改进分别报告。

市场时间不确定性采用配对日期块 bootstrap：共享日历的模型、参考和相关任务使用共同日期块，不能独立抽股票行或把重叠窗口当独立任务。策略净收益路径的重采样用于历史绩效的区间估计，不代表重新训练或在合成价格上回放所得表现。

训练程序不确定性另用完整流程重复来估计，并与日期区间分开显示；联合区间需显式说明运行层与日期层的层级抽样。遵循 rliable 对区间、performance profile、IQM 和改进概率的启发，但不机械套用独立 Atari 任务的假设。任务较少时优先逐任务报告；IQM 只能在扩展任务集后作为预先定义的稳健诊断，不把同市场的 5 日/20 日当足够多的独立任务。

首版默认置信水平 95%、重复 10,000 次，最终块长仅在开发区间按标签重叠及更长自相关确定并冻结。只有有限完整工作流重复时，不夸大对训练随机性的推断能力；增加 bootstrap 次数不能弥补原始市场或训练样本不足。

- 对分差下界高于预注册最小改进 `delta_score`，才写“达到约定幅度的提升”。
- 区间跨零写“提升证据不足”；不能写“相同”或“无差异”。
- 其他维度“不退步”使用预先定义的非劣界，不能仅凭 p 值不显著。
- 主比较预先指定；多个正式任务/指标声明按固定检验家族处理多重比较，诊断项不事后升级为验证性结果。
- 固定参考排名按点估计展示，统计比较另列；不假设简单因子构成单调阶梯。

一个可发布的“新版更好”声明至少满足：主分完整且资格有效、达到预定改进条件、严重错误案例无回退、其他发布约束满足。若仅速度改善，应准确声明速度改善。

### 9.1 端到端学习的归因实验

至少保留三类固定消融：相同输入/骨干下预测损失 vs 组合目标训练、相同预测下固定组合 vs 学习组合、相同模型下基础特征 vs 新特征。输入权限、风险授权、预算与执行一致，报告参数量、搜索和失败尝试。

完整平台改进允许同时优化多环节；若宣称提升来自某个端到端算法，则须有对应消融，不能将更高杠杆、更低成本假设或更有利股票池的收益归给算法。

## 11. 数据、接口与产物契约

### 11.1 规范预测表

继承当前预测表字段 `code`、`decision_time`、`task`、`prediction`、`model_version`、`data_snapshot_id`；Bench sidecar 补充 `protocol_id`、`training_mode`、`fold_id`、`fit_cutoff`、模型/配置哈希与预测来源。

键在同任务/同模型的 `code + decision_time` 上唯一。时区明确，预测为有限值，数据与任务 ID 匹配。评分器从快照计算标签，候选提交的自算标签不作为权威标签。

模型包只沿用当前安全加载与自定义代码执行边界；Bench 不新增自动执行未知 pickle 或仓库脚本的通道。

### 11.1a 策略接口与事件表

规划接口 `reset(context) -> state`、`act(observation, portfolio_state, state) -> action, state`；只向策略传入当前允许的信息。`context` 不包含整个测试数组；未受控的外部代码只能得到本地自报级结果，不能因为接口存在就宣称隔离已被证明。

目标权重表至少包含 `decision_time`、`code`、`target_weight`、`cash_weight` 或显式现金资产、策略版本和上下文哈希。订单表至少包含下单时间、预定执行时间、code、方向、数量及订单类型。按协议定义同时间单次现金字段的规范，避免重复求和。

评价器另写实际成交时间/价格/数量、费用、拒单/部分成交原因、实际持仓/现金和估值；目标权重不能代替实际账户。窗口、训练/更新、recurrent state 初始化和终止事件进入日志。候选提交的历史动作表可作诊断；标准策略决策评价要求由冻结策略通过受控回放生成。

```text
  portfolio_path.parquet    # 日收益、现金、持仓、交易、费用或相应分表
  verdicts.json             # 分层验收、问题代码、证据引用
  case_results.json         # 平台案例；用户单模型任务可不适用
  scorecard.json            # 原始指标、分数、固定排名、区间、完成率
  comparison.json           # 对照版本/模型、配对范围、差值与统计结果
  environment.json
  events.jsonl
  report.md
```

JSON 中未知/缺失值用 `null + reason` 表示，不输出非标准 NaN/Infinity；报告与结构化产物使用同一结论对象生成。关键输入变化产生新 run，已有产物不原地覆盖。

## 12. 目录、集成与命令规划

`bench/` 作为独立的需求、协议和案例目录；共享运行实现置于现有 Python 包内，不另建一套训练或市场规则引擎。

```text
bench/
  SPEC.md
  protocols/                # 后续新增冻结协议
  tasks/                    # 标准任务定义
  baselines/                # 官方参考配置/产物索引
  cases/                    # 可分发的小型案例与独立答案
  schemas/                  # Bench manifest / scorecard 的契约
  references/               # 资料索引与口径依据
src/qwb/bench/              # 后续新增评分、运行与比较实现
tests/                      # 依现有约定组织 Bench 契约/回归检查
```

原始授权行情不进入 `bench/` 或随模型分发，使用现有本地数据连接与缓存。优先复用 `taskcard`、`folds`、`asof`、`metrics`、`rules`、`consistency`、`issues`，对 `netcost` 先用独立案例核对，再按需扩展。

完整产品命令规划如下；v0.1 已实现其中预测表/运行目录的 `bench model` 和预测结果的 `bench compare`，实际参数见 [README.md](README.md)，其余仍不可运行：

```text
qwb bench model <model-or-predictions> --track signal --protocol <frozen.yaml>
qwb bench model <policy> --track decision --protocol <frozen.yaml>
qwb bench platform --protocol <frozen.yaml> --mode default_workflow
qwb bench cases --protocol <frozen.yaml>
qwb bench compare <old-run> <new-run>
```

用户界面后续提供“评估模型”入口，调用与 CLI 相同的任务接口与评分器。现有训练结果保留旧版 `go` 以兼容历史读取，但须标明 legacy IC 判定；新 Bench UI 不将它当成综合成功结论。原任务卡中字符串 acceptance 不能经 `eval` 执行，新规则必须使用结构化字段与白名单指标。

## 13. 版本和优化纪律

- 平台版本与 Bench 版本分别编号。开发期 Bench 可改；冻结后不因新版表现不理想而改权重、区间、基准或门槛。
- 分数优化在开发区间进行；最终锚点的每次访问均记录，公开已经反复使用的历史评分口径。
- 固定历史锚点用于长期对照；真正未见过的市场证据来自冻结后的前向区间或受控保留评测。两者分栏，不混成同一种确认性成绩。
- 候选选择和反馈只使用开发区间；内部历史 Bench 被反复用于版本优化后，标为工程/研究锚，不能再称为未见测试。最终确认限制访问，保留访问历史；时间戳混淆不等于市场数据保密。
- 本地评分与台账可被用户修改，只提供自查与可复现材料。没有独立控制的标签与提交记录时不声称反作弊认证。
- Bench 升版保留共同任务的桥接比较，并在新协议下重跑待比较平台；缺共同协议不直接排序。
- AutoGluon/Qlib 等外部参考比较须统一数据、金融切分、预算和评分器。默认易用性风险与正确配置下的建模能力分别报告。

## 14. 实施里程碑与验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| B0 契约与验收语义 | 预测/决策两赛道、结构化状态、环境/指标定义 | 缺依赖/泄漏/证据不足不产生错误通过；字符串门槛不执行；IC 不适用可标 N/A |
| B1 用户预测评分闭环 | 预测表入口、5 日/20 日任务、参考、IC 分与报告 | 已知预测可独立复算；同输入同结果；明确区分诊断分与标准资格 |
| B2 账户金标准与案例 | 独立指标、账户路径、24 对平台案例及额外环境/指标案例 | 逐笔/逐日和指标复算符合答案；三类已复核预处理行为被自有合成案例覆盖 |
| B3 端到端回放与锚点冻结 | 策略接口、一个直接权重模型、经济基准、预算运行器和冻结 manifest | 策略不必输出 IC；受控回放完整；所有风险/预算参数齐备；当前平台 1.0 留下完整真实锚点 |
| B4 版本比较与发布 | 完整流程重复、区间/分布、消融、主分、环境复现 | 新旧同协议可比；失败不被删除；改进是否超出时间/训练不确定性分别说明 |

B1 的经济分在 B2 金标准完成前必须标“开发诊断”，不得提前发布为正式分数。当前未确定的校准参数阻止 B3 冻结，但不妨碍 B0-B2 实现和合成验证。

Spec 完成不代表上述阶段已完成。v0.1 已实现 B0/B1 的预测入口子集：开发协议与内容哈希、固定样本、三条规则参考与冻结 LightGBM、IC 分与固定排名、日期块区间、局部折声明检查、报告及预测结果配对比较；真实 5 日任务已跑通。20 日任务尚无真实锚点；随机面板分布、账户/策略回放、完整挑战集及平台训练运行器未交付。没有重跑文献的交易收益实验。

v0.2 评分器在该子集上增加 §4.4 的证据与短板能力。旧 v0.1 协议和报告保留；对比必须在相同新协议下重评，不把区间校正变化视为平台能力提升。

## 15. 冻结前必须解决的问题

| 问题 | 完成标准 |
|---|---|
| 真实快照与时间区间 | 两个预测期可用，历史证券与状态覆盖已审计，已有测试访问已披露 |
| 决策任务与风险授权 | 固定决策任务单元、经济基准、股票池/窗口家族、任务权重和风险上限；风险裁剪不使用未来信息 |
| 端到端最小参考 | 选择一个直接权重模型和匹配的预测+组合对照；训练目标、输入权限和成本处理可审计 |
| 资源档位与完整重复 | 固定硬件/线程/内存、工作流时限、搜索上限和完整重复次数 |
| 目标与统计参数 | 覆盖阈值、主目标阈值、块长、最小改进和非劣界已预注册 |
| 经济/指标边界 | 明确动作与成交时序、账户模型、退市、现金、首末日和 Sharpe 口径；独立计算路径一致 |
| 报告兼容 | 新旧 `go` 语义可区分，首页与页脚一致，不声称未执行的认证 |

这些值应依据现有数据和开发期检查确定，不能从最终候选表现倒推“好看的”门槛。若净超额主目标不能代表最终产品的风险目标，应在冻结前明确效用函数及理由，修订本 Spec 并重评所有候选；不能为了维持一个总分而隐藏未确定的评价对象。
