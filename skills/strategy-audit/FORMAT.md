# 标准格式（转换目标）

只在原始导出无法直接导入时才转换。一个目录 = 一次回测。文件名随意，引擎按**表头**识别；编码 UTF-8 或 GBK；第一行是表头；日期写 `YYYY-MM-DD`。

不要混用：一个目录里要么全是某个平台的原始导出，要么全是本格式（策略代码、日志可以随意搭配）。

## 必需

### 成交 `trades.csv`

```
date,time,code,side,quantity,price,fee,order_id
2024-01-02,09:31:00,600000.SH,buy,1000,10.00,5.00,A1
2024-01-03,14:50:00,600000.SH,sell,1000,11.00,10.50,A2
```

| 列 | 必需 | 规则 |
| --- | --- | --- |
| `date` | 是 | 成交日期 |
| `code` | 是 | `600000.SH` / `000001.SZ`；`.XSHG`/`.XSHE`、`SH600000` 也可。股票、ETF/基金、可转债可以；**指数、期货不行** |
| `side` | 是 | `buy`/`sell` 或 `买入`/`卖出` |
| `quantity` | 是 | **股数**，正整数。平台给"手"的乘 100 |
| `price` | 是 | 成交价，不复权 |
| `fee` | 是 | 该笔实际扣的佣金＋税费，元。平台没给填 `0`，并告诉用户 |
| `time` | 否 | `HH:MM:SS` |
| `order_id` | 否 | 委托编号 |

### 策略代码

原样保存为 `.py` 或 `.txt`，不要改。平台把代码嵌在别的文件里时，提取出来单独存。

## 强烈推荐（没有就不能对账，归因和回撤会弱很多）

### 每日持仓 `holdings.csv`

```
date,code,quantity,price
2024-01-02,600000.SH,1000,10.20
```

每个交易日收盘后一行一只；`quantity` 是股数，`price` 是当日收盘价（不复权）。空仓的日子不写行。

### 每日账户 `account.csv`

```
date,equity,cash
2024-01-02,100195.00,89995.00
```

`equity` = 现金＋持仓市值（＋应收股息）。每个交易日一行，包括空仓日。

平台单列"应收股息"（已除息、未到账的分红，米筐有）时，加一列 `receivable_dividend` 原样填入，`cash` 只填可用资金，**不要**自己把两者相加。漏了这一列，除息日会对不上账。

```
date,equity,cash,receivable_dividend
2026-01-16,96268.55,303.25,938.90
```

## 选填

### 运行日志

原样保存为 `.txt`。聚宽格式 `YYYY-MM-DD HH:MM:SS - LEVEL - 内容`、米筐格式 `[YYYY-MM-DD HH:MM:SS] LEVEL: 内容` 都能直接认。其他格式转成 CSV：

```
时间,级别,内容
2024-01-02 09:31:00,WARNING,订单被拒：可用资金不足
```

### 每日打分 `scores.csv`（检验策略前提必需）

```
date,code,score,selected
2024-01-02,600000.SH,0.83,true
2024-01-02,000001.SZ,0.41,false
```

**每个调仓日的全部候选**，不只选中的。`selected` 标出当天实际选中的标的。可加 `available_at`（分数实际可用的时间）。

### 候选池收盘价 `prices.csv`（检验策略前提必需）

```
date,code,close
2024-01-02,600000.SH,10.20
```

打分里出现过的每只标的、每个调仓日的收盘价。可用后复权价（只用来算收益率）。

### 成交日分钟价 `minutes.csv`（检验成交时点、成交后最差价必需）

```
date,time,code,close,open,high,low,volume
2024-01-02,09:31,600000.SH,10.02,10.00,10.05,9.98,152300
2024-01-02,10:00,600000.SH,10.08,,10.09,10.06,
```

每个**有成交的交易日**、每只成交标的，至少要有成交所在的那一分钟和其后 10 分钟，再加几个对照时点：09:31、09:35、09:45、10:00、10:30、11:00、13:30、14:00、14:30、14:50。`close` 必需；`high`、`low` 用来算成交后几分钟内的最差价；`open` 只用在 09:31 那一行（接近开盘竞价价，但只有竞价截止前已提交的订单才可能按它成交）；`volume` 用来判断单笔成交是否超过当分钟成交量。不复权。

### 成交日全天区间 `ranges.csv`（检验成交价是否专挑当天低点买、高点卖）

```
date,code,high,low
2024-01-02,600000.SH,10.31,9.95
```

每个有成交的交易日、每只成交标的的全天最高价和最低价，**不复权**，和成交价同一口径。

数据从哪来：平台研究环境的分钟行情接口（聚宽 `get_price(..., frequency='1m')`、米筐 `get_price(..., frequency='1m')`）。只取成交日，数据量很小。没有就不交，报告会写明本项未审。

### 实际公司行动 `actions.csv`（可选，让逐股分红归因准确）

```
date,code,kind,quantity_change,cash
2024-06-20,600000.SH,dividend,0,300.00
2024-06-20,000001.SZ,bonus,300,0
```

除权日、标的、送转增加的股数、到账的现金分红金额（按当日持股算好的总额，不是每股）。有了它，审计不再从账户现金变化推断分红、按市值分摊。没有就不交，报告会写明哪些分红是估计。

### 回测运行配置 `config.json`（可选，RQAlpha 等）

费用、滑点写在运行配置里而不在策略代码里时，原样附上。审计从中读佣金、最低佣金、印花税倍数和滑点模型；没有它时报告只说"没有读到"，不推断默认费率。

### 平台绩效汇总 `summary.xlsx` / `回测收益.csv`（可选）

平台自报的收益、回撤等，原样附上，报告会逐项对照。

## 不得做的事

- 不得根据策略逻辑推算缺失的成交、持仓。
- 不得用收盘价代替成交价。
- 不得为了让 `qwb audit check` 对上账而调整任何数字。对不上说明转换或材料有问题，要找原因。
- 不得删掉对审计不利的行（亏损交易、被拒订单、错误日志）。
